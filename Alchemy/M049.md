false_positive_notes: |
  The benign population here is large and growing, so the model must be fitted against it rather than around it. Single-provider traffic — a developer's IDE assistant, a desktop client, a browser session, an internal service calling one model API on a schedule — is the overwhelming majority and is deliberately not what this hunt scores; fan-out is a gating feature precisely so that this traffic never reaches the worklist. Three benign sources do produce genuine multi-provider fan-out and must be inventoried, not filtered blindly. First, model-routing and gateway software: OpenRouter, LiteLLM, Portkey, LangChain and LlamaIndex router configurations, and internal AI gateways legitimately fan one request out to several providers, sometimes for failover and sometimes for cost routing — these are the closest benign analogue to the quorum pattern and the reason process provenance and inventory status carry heavy weight in the score. Second, evaluation and benchmarking work: LLM-as-judge pipelines, model-comparison harnesses and prompt-regression suites query many providers with near-identical prompts by design, which is the quorum shape almost exactly; these live on developer hosts and CI runners and should be identified as a named population. Third, aggregator applications and browser extensions that answer one user question from several models at once. Against all three, the discriminators are provenance and content: an unsigned or ad-hoc-signed binary running from %TEMP%, %APPDATA%, %PROGRAMDATA% or C:\Windows\Temp, or running as SYSTEM or a service account with no inventory entry, doing this on a host with no AI tooling licensed; and a prompt body carrying enumerated host context and an instruction to return an executable decision rather than a user's question. Where TLS inspection is unavailable, the content leg is lost and the hunt degrades to fan-out plus provenance plus action-latency — still workable, but expect the evaluation-harness population to dominate the top of the ranking until it is labelled.
notes: |
  How this differs from [[M036]], and why both exist - M036 scores (host, process, SaaS destination) tuples for bidirectional C2 hidden in file-sharing and messaging services, using process-destination novelty, interval regularity, upload/download asymmetry and session-to-volume ratio. That model is destination-centric and interval-centric, and it would rank a single-provider LLM beacon well. It cannot express what is distinctive here, because the quorum signature is not a property of any one (process, destination) pair — it only appears when several destinations are considered jointly as one decision event, and because the discriminating content is inside the request body rather than in its size or direction. This hunt is therefore sequence-and-content-centric: the unit of analysis is a decision cycle spanning multiple providers, not a flow to one. Run M036 for the general legitimate-service C2 problem and this for the inference-API case; where TLS inspection is absent, M036's interval features remain the better-supported fallback.
  Unit of analysis - A decision cycle, not a connection. Group a process's inference-API requests into clusters using a short gap threshold (requests separated by less than 30 seconds belong to the same cluster), then score the (host, process image plus SHA256) tuple over 14 to 30 days on the distribution of its clusters. Require a minimum of roughly 10 clusters before scoring so the shape statistics are meaningful. Resolve destinations to a provider identity rather than a hostname, since endpoints rotate within a provider: api.deepseek.com, api.mistral.ai, api.openai.com, api.anthropic.com, generativelanguage.googleapis.com, api.cohere.ai, api.together.xyz, api.groq.com, api-inference.huggingface.co, openrouter.ai, and any internal inference gateway.
  Features - Quorum fan-out (gating feature): distinct providers contacted within one cluster, and the count of providers that are mutually unrelated commercial vendors rather than one vendor's several endpoints; three or more is the CLOSEDQUORUM shape and should dominate the score. Cluster synchronicity: the span of the cluster in seconds and the coefficient of variation of request sizes within it — a panel being asked the same question produces near-identical request sizes in a tight window, whereas a router retrying after a failure produces a size-and-timing sequence that reflects the failure. Response-to-action latency: the interval between the last response in a cluster and the next process creation, file write, or registry write by the same process, and the consistency of that interval across clusters; an implant acting on a verdict produces a tight, repeatable latency, while a human-driven assistant produces a broad one. Cycle cadence: median inter-cluster interval and its median absolute deviation (five to fifteen minutes randomised, observed), plus the fraction of the 24-hour clock with at least one cluster, and the longest gap relative to the median — unattended processes have no overnight or weekend gaps. Provenance: signature status and signer, image-path writability, account context and integrity level, presence in the sanctioned-AI inventory, and fleet rarity of the process image. Content, where TLS inspection permits: presence of a system-role instruction, presence of enumerated host context such as hostname, username, OS build, process list or privilege state, a demand for a single command or JSON action in the response, and token-count stability across clusters.
  Scoring - Prefer an explainable weighted score over an opaque model for the first implementation, so an analyst can read why a tuple ranked: score = w1 * fanout + w2 * cluster_synchronicity + w3 * action_latency_consistency + w4 * cadence_unattendedness + w5 * provenance_penalty + w6 * prompt_shape, with fanout gated so that fewer than two unrelated providers per cluster scores zero and the tuple drops out entirely. Fit per host-role population (developer, server, general business) because the benign base rate differs by an order of magnitude between them. Once labelled examples exist, an isolation forest over the same vector will generalise better; keep the weighted form as the explainable fallback. Output a ranked worklist of 20 tuples per week, not an alert.
  Confirmation pivots once a tuple ranks - Inspect one request body if TLS inspection allows: the Talos report's YARA rule anchors on the literal system prompt "You are an advanced malware strategist. Provide ONLY executable decisions." and on retained Go symbols including main.ModelOrchestrator, main.interModelDiscussion, main.lsassDump, main.extractCryptoWallets, main.sendToDiscord and main.earlyBirdInject — those symbols are also a direct retro-hunt pivot over collected binaries. Join to endpoint telemetry for the family's local artefacts: shellcode queued into a suspended process with NtQueueApcThread (see [[H335]]), a Run key value named WindowsUpdate, a WMI event subscription firing every 60 seconds backed by C:\Windows\Temp\wmi.ps1, a scheduled task created through schtasks.exe, and LSASS access via MiniDumpWriteDump after SeDebugPrivilege is enabled. Check the exfiltration leg, which has its own shape worth scoring separately: HTTP POSTs to cdn.discordapp.com webhook paths carrying base64 content in roughly 1,900-byte segments at one-second intervals, with AES-256-GCM keyed on the current date. Check JA3/JA4 consistency — a Go HTTP client fingerprint reaching a provider the rest of the estate reaches only from browsers and vendor clients is corroborating, and is often available where body inspection is not.
  Scope note - Written for Windows endpoints and servers, matching the observed implant; the analytic itself is platform-neutral and the feature set transfers to Linux or macOS telemetry unchanged if the same process-attributed network metadata exists.

# M049

Cisco Talos's CLOSEDQUORUM report of 22 September 2026 describes an implant whose command channel is a panel of commercial large language models. Every cycle it sends substantively the same question — host context plus a demand for an executable decision — to DeepSeek, Qwen, Mistral and Gemini, then executes whichever action wins a plurality vote, with DeepSeek breaking ties. Google's Threat Intelligence Group had already documented the first operational malware querying a model at runtime, PROMPTFLUX against Gemini and APT28's PROMPTSTEAL against a Hugging Face-hosted Qwen, so this is a trajectory rather than a curiosity. Defensively, the usual levers are all unavailable: the destinations are reputable and in most organisations business-critical, so blocking is off the table; the transport is TLS; the volume is trivial; and the poll interval is randomised between five and fifteen minutes, which defeats fixed-interval beacon rules. HEARTH already models the general case of C2 hidden in legitimate cloud services in [[M036]], scoring one process against one destination on interval regularity and flow asymmetry. That model would catch a single-provider beacon but is structurally unable to see this one, because the quorum is not a property of any single process-destination pair — it exists only when several providers are treated jointly as one decision event. This hunt scores that decision cycle: how many unrelated providers are consulted at once, how tightly the requests cluster, how consistently a local action follows the last response, and, where inspection permits, whether the prompt carries a user's question or an enumeration of the host.

## Why

- The quorum is an architectural commitment rather than a configuration detail: plurality voting across several models is what the implant's design depends on for resilience against any one provider refusing or rate-limiting, so the fan-out persists even as endpoints, models and hashes rotate — which makes it a durable feature to model rather than an indicator to match.
- That fan-out is invisible to destination-by-destination analysis, including HEARTH's own general legitimate-service C2 model, because each individual flow is an unremarkable low-volume TLS session to a reputable provider; the signal exists only when several providers are joined into one decision event, so this is a different unit of analysis rather than a retuning of an existing one.
- The benign population that most resembles the quorum shape — model routers, failover gateways and LLM-as-judge evaluation harnesses — is small, inventoriable and concentrated on developer and CI hosts, so provenance plus inventory status separates it cleanly, whereas the far larger single-provider population never enters the ranking at all because fan-out gates it out.
- Prompt shape gives an unusually decisive confirmation step where TLS inspection exists, since a body pairing a system-role instruction with machine-enumerated host context and a demand for one executable command has no legitimate analogue, and the response-to-action latency feature provides a weaker but inspection-free substitute for estates that cannot read bodies.
