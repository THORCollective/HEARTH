# M057

HOLLOWCLAD has about eighty PE sections. They are named after Themida, VMProtect, Enigma, UPX and Denuvo. The binary is not packed.

Talos's phrasing is the right one to keep: "the armor for this malware is just a costume." Eighty section names asserting five different commercial protectors, and underneath them, ordinary low-entropy code. The purpose is to dissuade a human analyst and to confuse automated packer identification, and it costs the author nothing.

The temptation is to write a rule for it — alert on a section named `.vmp0`, alert on a section count over fifty. Both fail, for the same reason. Commercial protectors are *legitimately used*. Games use Themida. DRM-bearing media software uses VMProtect. Licensing subsystems use WinLicense. A Themida-named section on a signed commercial game is not a costume; it is Themida. And section counts have no portable normal: the 95th percentile on a .NET application estate and on a Go-heavy build fleet are different numbers, so any global threshold either floods the queue or misses the thing it was written for.

What is actually anomalous is not a value. It is a disagreement between two measurements of the same file.

A genuinely packed binary has a small section table, one or two sections with very high entropy, and an import table reduced to little more than `LoadLibrary` and `GetProcAddress`, because the real imports are resolved at runtime after unpacking. A binary whose section names assert packing while its entropy sits at ordinary-code levels and its import table is fully populated is making a claim its own contents refute. That is the feature, and it is a relationship rather than a threshold — which is why this is a model and not a rule.

The two families in the Talos report happen to give you a clean positive control pair for exactly this. HOLLOWCLAD is named-but-unpacked. MANTLEMAZE is genuinely VMProtect-packed. If the scoring cannot separate those two, it is not implementing the hypothesis; it is just ranking section counts.

Score per host-role population, not estate-wide. Pool developer workstations and build agents with a fleet of office laptops and every engineer becomes an outlier, which buries the one binary you are looking for under a hundred legitimate ones. And treat the output as a queue, not a verdict — the read is fast. Dump the section table and see whether eighty names describe eighty bytes.

## Why

- **Appearance diverging from structure is what static analysis is genuinely good at.** The file carries both the claim and the evidence against it, so no telemetry, no execution and no network activity is required to resolve it.
- **A static threshold on section count does not travel.** Installers, Go binaries, .NET assemblies with embedded resources, drivers with discardable sections and LTCG builds all have different normal shapes. The threshold has to be population-relative, which is the definition of this being a modelling problem.
- **Legitimate protector use is common, so names alone cannot be the signal.** Games, DRM and licensing subsystems use these products openly. Requiring entropy to contradict the name is what keeps those out without an allowlist that rots.
- **The malicious feature is a relationship, not a value.** Names asserting packing plus entropy denying it plus a full import table. A rule can express that for one protector; a model expresses it for the family, including protectors not yet abused.
- **The published families are a built-in control pair.** One named-but-unpacked, one genuinely packed. That makes the model testable on day one rather than after the first incident.
- **The import table is the cheapest confirming feature and the most often skipped.** Real packing collapses imports to loader stubs. A fully populated import table behind a protector-named section table is close to conclusive.
- **It generalises past the AI-evasion story that produced it.** Fake-protector dressing is an old trick aimed at human analysts and at packer ID tools, and this model finds it regardless of whether the binary also carries prompt injection.
- **Interpretability is a requirement, not a nicety.** Whoever works the queue has to be able to say why a file ranked where it did. A low-dimensional outlier model over named features survives that conversation; an opaque score does not.
