# H377

AhnLab calls this step a UAC bypass. The part a defender can rely on is narrower and more useful than that: the next PowerShell stage gets launched by Explorer, not by the script that wanted it.

The secondary PowerShell stage in AhnLab's quote-request chain instantiates the ShellWindows COM object, CLSID `{9BA05972-F6A8-11CF-A442-00A0C90A8F39}`, which returns objects belonging to the running `explorer.exe`. A `ShellExecute` call made through one of them is carried out by Explorer. So the new PowerShell process is recorded with `explorer.exe` as its parent, and the script host that asked for it is nowhere in the tree.

That is a lineage break, and it lands in the most crowded parent-child pair on Windows. `explorer.exe` launches `powershell.exe` every time a person opens a shell. The pair alone is useless; two things separate the attack from the person. A human-opened PowerShell window has a bare command line, while a stager carries hidden-window, bypass or encoded arguments. And this launch follows a script host that ran for the same user seconds earlier.

Be careful with the elevation claim. Under default UAC settings Explorer runs at medium integrity, so routing a launch through it does not raise the integrity level by itself. The report does not say how elevation was achieved. The likely readings are a `runas` call, which still raises a consent prompt but one that now appears to come from Explorer rather than from a script, or a host where Explorer was already elevated. Use integrity level to sort the hits rather than to filter them. Medium means the lineage break alone. High with `consent.exe` just before it means an elevation request a user approved. High with no consent event means UAC is not prompting on that host at all.

Where script-block logging is on, the cleaner signal is in the script itself: the ShellWindows CLSID next to a `ShellExecute` call. Very little legitimate automation does that to start an interpreter.

## Why

- **The re-parenting is the durable artefact.** However the elevation question resolves, the payload's recorded parent is `explorer.exe` and the script host drops out of the lineage.
- **The parent-child pair needs two discriminators to be usable.** Stager arguments on the child, and a script host for the same user seconds earlier. Either alone is weak; together they are narrow.
- **Integrity level classifies the result instead of filtering it.** Filtering on high integrity would miss every medium-integrity launch on a default-UAC host, which is the common case.
- **A `consent.exe` creation next to a hit is evidence for the attack, not against it.** A `runas` request sent through Explorer still prompts; the prompt just looks more trustworthy.
- **The script-block leg is the highest-precision query.** ShellWindows plus `ShellExecute` of an interpreter in a 4104 record has a small benign population.
- **It does not overlap the existing UAC-bypass hunts.** [[H243]] and [[H321]] are built on registry and RPC artefacts this mechanism never produces.
