# H286

Threat actors are publishing npm packages containing standalone HTML files with obfuscated JavaScript to public npm registry mirrors (unpkg, npmmirror, yarn, tencent), exploiting automatic mirroring to host fake Cloudflare verification phishing pages on trusted third-party domains, directly redirecting victims to attacker-controlled ClickFix infrastructure.

## Why
- Abusing trusted npm mirror domains (unpkg.com, npmmirror.com, etc.) as free, reputable frontend hosting allows phishing pages to bypass URL-reputation and domain-age-based detections that would flag newly registered attacker-owned domains.
- Because npm packages and their mirrored content can persist indefinitely across mirrors even after removal from the official npm registry, this technique provides durable, hard-to-fully-remediate hosting infrastructure for phishing and ClickFix payload delivery.
- This pattern reflects a broader trend of adversaries weaponizing legitimate package ecosystems and their supporting infrastructure (registries, mirrors, CDNs) purely for payload storage and delivery rather than for traditional supply-chain code execution, representing a detection blind spot for teams focused only on malicious package behavior at install/runtime.
- Successful use of this infrastructure enables staged redirection chains (fake CAPTCHA → remote-hosted decision logic via services like keyval.org → ClickFix or credential-phishing pages), complicating attribution and takedown since the final malicious destination can be dynamically reconfigured without republishing packages.
