false_positive_notes: |
  Hex-encoded command lines are rare but not unknown in legitimate use - some installers, CI pipelines and configuration-management tools pass encoded blobs, and a few vendor agents encode arguments to survive quoting. The encoding is therefore a strong lead rather than a verdict, and the correlating facts are the executing user, the parent process and the destination the payload came from. Encoded commands run by the application service account under a Java parent have no benign reading.

  Cloudflare Tunnel is legitimate infrastructure and many organisations use it deliberately, including for internal services. The anomaly is direction and purpose - a server fetching executable content from a `trycloudflare.com` hostname is different from an organisation publishing a service through a named, managed tunnel. Check whether the estate has sanctioned tunnels and attribute each hostname before treating it as hostile. Pinggy and `webhook.site` have far narrower legitimate use on a production server and are worth treating as findings by default.

  Vulnerability scanners and authenticated compliance scans generate bursts of enumeration commands on servers and can resemble machine-driven activity in both rate and regularity. Reconcile against the scanning schedule and the scanner's service account first; the distinguishing feature is that a scanner's commands come from its own agent or an SSH session, not from the application's JVM.

  Rate and regularity thresholds do not transfer between estates. Hundreds of commands in a session is extreme for an interactive administrator and unremarkable for a configuration-management run, so the threshold has to be set against the host's own history. B075 is the measurement that makes this leg usable.

  The attribution of this tooling to AI assistance is Rapid7's assessment, drawn from the command structure, and it is explicitly hedged in the report as a suggestion rather than a finding. Treat it as useful framing for why the activity looks the way it does, not as a fact about the operator, and do not build a detection that depends on it being true.

  Luhn-validated card-number searching and Office document parsing are also performed by legitimate data-discovery and DLP tooling, which can read the same attachment corpus for the same patterns. Attribute by the process doing the reading and by whether a sanctioned scan was scheduled.
notes: |
  Leg one, the encoding (auditd execve, Sysmon for Linux, or EDR process events) - Core filter: command lines containing long runs of hexadecimal characters, or the decoders that turn them back into shell. Both halves are worth searching, because the attacker needs a decoder and the decoder names are few.

      # Candidate hex-decode patterns in command lines on application servers
      #   xxd -r -p        |  xxd -p -r
      #   echo <hex> | xxd -r -p | bash
      #   printf '\x..'    repeated
      #   python3 -c "...bytes.fromhex(..."
      #   perl -e 'print pack("H*", ...'
      #   sed 's/../\\x&/g'
      egrep -i 'xxd +-r|bytes\.fromhex|pack\("H\*"|unhexlify' /var/log/audit/audit.log

  Then widen to the shape rather than the tool - a command-line argument of 40 or more characters drawn only from `0-9a-f`. On most servers that returns almost nothing, which is what makes it a usable filter. Note that `base64 -d` piped into a shell is the far more common relative and should be searched alongside it; this intrusion chose hex, and a query written only for Base64 would have missed every command.

  Leg two, the destination class (DNS and egress telemetry) - Core filter: resolutions or connections from any server to an ephemeral tunnel or request-capture provider. The specific families observed here are Pinggy, including the `free.pinggy.net` form, Cloudflare's quick-tunnel domain `trycloudflare.com`, and `webhook.site`. Extend the list with the other common providers an operator reaches for - ngrok, localtunnel, serveo, telebit, bore and the request-capture services such as `requestbin` and `pipedream` - and treat the list as a destination class rather than an indicator list. Red flags - the resolving process is the application's JVM or a shell parented by it; the same hostname is fetched repeatedly over hours, which is tasking rather than a one-off download; the hostname embeds an IP address, as `wpefh-192-238-253-176.free.pinggy[.]net` does, because that string also ties the tunnel to the exploitation source and, in this intrusion, to a later Microsoft 365 sign-in.

  Leg three, the throughput signature (process execution telemetry, aggregated) - Core filter: per-host, per-user command counts in short windows, compared against that host's own history. The operational shape to look for is a session of hundreds of commands against a single host, executed by a service account, with regular inter-command intervals and no idle gaps - no human administrator types for an hour without pausing. Useful summary fields are distinct binaries invoked, the ratio of read-only enumeration commands to state-changing ones, and the proportion of commands whose output is piped into an encoder. Delimiter conventions are visible where command content is captured - the observed tooling wrapped each command's output in labelled delimiters and tagged each with a sequential task ID, so a repeated bracketing string and an incrementing integer in command text are both searchable strings on a host already under suspicion.

  Leg four, what the automation went after (auditd file watches, database logs) - The enumeration target list is specific enough to hunt directly. Set or check watches on the Confluence configuration and key material, and on the attachment corpus at `/var/atlassian/application-data/confluence/attachments/v4/`, which is the default location for uploaded page attachments:

      auditctl -w /var/atlassian/application-data/confluence/attachments/v4/ -p r -k conf_attach
      auditctl -w /var/atlassian/application-data/confluence/confluence.cfg.xml -p r -k conf_cfg

  A bulk sequential read of the attachment tree by a shell rather than by the JVM is the collection step. Alongside it, look for a MySQL client authenticating locally with the application's own database credentials - in the observed intrusion that happened just over three minutes after the first command execution, and the queries went after page bodies, application links, and attachments whose names suggested credentials, tokens, VPN configurations and private keys. Office document parsing and Luhn-checked payment-card searching are the stage after that, so the presence of a card-number pattern search on an application server is a late-stage signal and a regulatory one.

  Why the automation framing matters operationally, stated carefully - Rapid7 attributes the structure to AI-assisted tooling as an assessment, not a finding. What is directly observed is the structure itself, and that structure has two consequences a defender can act on. The first is speed - the whole sequence from exploitation to cloud data warehouse access took about four hours, so a daily hunt cadence is too slow for this activity and the detections in leg one and leg two need to run continuously. The second is breadth - automated enumeration does not stop at what is useful, so the compromise scope is likely to be everything the service account could read, not the subset an operator would have bothered with.

  Scope note: H062 is the closest existing hunt and covers adversary use of legitimate tunnelling services generally, which overlaps leg two. The distinctions are that H062 treats the tunnel as the adversary's own ingress or egress channel, whereas here the tunnel hosts the tasking and the scripts that a compromised server pulls down, and that this hunt adds the hex-encoding and throughput legs that H062 does not have. H510 covers the exploitation that precedes this activity on the same host and H512 the identity pivot that follows it. H162 covers payload staging in `/dev/shm` or `/tmp` on a compromised Confluence host, which is a neighbouring step. No existing hunt names Pinggy, `webhook.site`, hex-encoded command lines, or Luhn-checked card searching - a grep for each of those strings across every hunt returns nothing.

# H511

The most unusual thing in Rapid7's Confluence intrusion is not the exploit. It is the texture of what came after it.

The attacker ran hundreds of hex-encoded shell commands and scripts, fetched from temporary Pinggy and Cloudflare Tunnel domains. Each command wrapped its output in labelled delimiters. Each carried a sequential task ID. Rapid7's read of that structure is that it suggests AI-assisted automated tooling — an assessment, carefully hedged, and one that explains the shape of everything else in the report.

Because the shape is the point. The scripts enumerated the host, the network, the Confluence configuration, its encryption keys and its database settings. They went to `/var/atlassian/application-data/confluence/attachments/v4/`, the default home for uploaded page attachments, parsed Office documents, looked for credentials, and searched for payment card numbers — running Luhn checks to drop false positives. That is a thorough, patient data-mining pass of the kind a human operator rarely bothers with, executed in minutes.

For a hunter, the three artefacts that follow from it are more durable than any IP address: command lines encoded in hex, executable content pulled from ephemeral tunnel hostnames, and a command rate no person produces.

## Why

- Hex-encoded command lines are a near-empty result set on a healthy server. Base64 is the common choice and most detection content assumes it, which is exactly why a query written only for Base64 would have missed this intrusion end to end. Searching both costs nothing.
- Ephemeral tunnel hostnames are a destination class, not an indicator list. `trycloudflare.com`, `free.pinggy.net` and `webhook.site` exist to give something short-lived a public name, and a production application server fetching code from one has no legitimate reading. The class outlives any particular campaign's infrastructure.
- Machine-driven enumeration has a throughput signature a human session cannot fake. Hundreds of ordered, labelled, evenly spaced commands in one session is measurable with data most estates already keep, and it does not depend on recognising any tool.
- Automation changes the scope of the incident, not just its speed. An operator takes what looks useful; a script takes everything the account can read. A confirmed hit should be scoped as full exposure of the attachment corpus and the configuration, including the encryption keys and database settings — which is a different conversation with the business than "a server was compromised".
- The card-number search makes this a regulatory event as well as a security one. Luhn-validated pattern searching across parsed Office documents on a wiki is a deliberate hunt for payment data, and finding that step in the timeline determines who else needs to be told.
