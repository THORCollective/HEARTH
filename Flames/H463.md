false_positive_notes: |
  Developers edit these files legitimately and constantly, so the hunt cannot key on modification alone.
  - The agent itself writes its own configuration, and so does the developer, by hand and through the agent's own commands. Allowlist the agent binary and ordinary editors, and treat a write by a script interpreter, an archive utility or an unsigned installer as the candidate population.
  - Team-shared instruction files are a normal engineering practice. Repositories legitimately carry project-level instruction files that the agent reads, and provisioning scripts legitimately deploy standard global instructions. The discriminator is scope and provenance - a write to the global, user-wide configuration by something fetched from an unvetted repository, rather than a project-level file committed to a reviewed branch.
  - Skills and extension directories fill up legitimately. Developers install community Skills on purpose, which is the intended use of the feature; the finding is not that third-party Skills exist but that they arrived inside an encrypted bundle whose contents cannot be reviewed before installation.
  - Decryption and signature verification in an installer are normal engineering, used by plenty of legitimate software to protect assets. On its own it is uninteresting; paired with writes to an agent's trusted instructions it is the thing that prevented review.
  - Later gateway traffic can be legitimate. Plenty of teams deliberately route model traffic through a gateway or proxy for cost control and auditing. Compare the destination against the approved list rather than treating any gateway as hostile.
  - A hit is an engineering-hygiene finding as often as a security one. Check Point found no evidence that the advertised gateway in the reported case was itself malicious, so the response is usually removal and a conversation, not an incident.
notes: |
  Source reporting is Check Point Research's November 3, 2026 analysis of the Haiou jailbreak bundle, found on a misconfigured threat-actor web server alongside an open Cobalt Strike server whose logs showed the actor compromising computers of Chinese-speaking individuals, plus a VulnClaw agent and the Ladon framework. Check Point is careful that this does not imply the package was designed for cybercrime, and the useful observation for a defender is that these dual-use toolkits are actively used by threat actors. The nearest existing hunts are [[H422]] and [[B066]], which cover a sweep of AI coding-agent credential stores - the same file-system neighbourhood and the same tool inventory, but a read for collection rather than a write for persistence - and [[H375]], which covers natural-language text aimed at automated analysis pipelines rather than at the developer's own agent.
  What the category is - Check Point defines prompt adware as a class of AI-agent modification that persistently alters the trusted instructions an agent reads - global prompts, Skills, configuration files - "to influence future outputs for commercial or behavioral objectives", and draws the distinction that matters for detection: "Unlike traditional adware, it operates entirely through natural language in configuration artifacts, rather than executable payloads." That is why the hunt has to key on the write rather than on subsequent behaviour: after installation there is no malicious process running at all.
  Stage one, acquisition - Core filter: a clone or archive download from a code-hosting repository by a developer workstation, followed by execution of a launcher script from the downloaded tree. The reported package is hosted publicly, has received more than 250 stars, and ships launchers for Linux, macOS and Windows. It is also bundled inside a graphical configuration tool for the agent, which means a developer can acquire it without ever seeing the repository. Triage values are the repository URL, the local path of the clone, the launcher path and command line, and the parent process. Strong red flags are a launcher run from a path under the user's downloads or temporary directories, and an installation performed by a configuration utility rather than by the developer directly.
  Stage two, the opaque payload - Core filter: a script that verifies and decrypts a packaged payload and extracts it to a temporary directory. Check Point reports that the launchers verify a payload package using Ed25519 signatures and SHA-256 hashes and decrypt it with an AES-256-GCM key embedded in the script, that the payload decrypts to a ZIP which is extracted to a temporary directory, and that "This design effectively makes the prompt content opaque to anyone simply browsing the GitHub repository". For Windows hosts the launcher logic is visible in PowerShell Script Block Logging Event ID 4104, where `ScriptBlockText` carries the embedded key and the decryption calls. Note that `DeviceEvents` with `ActionType == "PowerShellCommand"` records cmdlet names only and never script text, so it cannot show the decryption logic; aggregating cmdlet names per process with `make_set` is the most it offers, and 4104 is the required source. Triage values are the script text, the package path, the extraction directory, and the hashes of the extracted files. Strong red flags are an embedded symmetric key in a script that also writes to an agent's configuration, and an extraction whose output is markdown rather than code.
  Stage three, the writes that matter - Core filter: creates or modifies of an AI coding agent's global instruction files and Skills directories by a process other than the agent. Sample Defender XDR query, with the path list filled from the agent inventory:
  ```kql
  let lookback = 30d;
  let agentConfigPaths = dynamic([@"\.codex\", @"\.claude\", @"\.gemini\", @"\.cursor\"]);
  let instructionFiles = dynamic(["AGENTS.md", "CLAUDE.md", "GEMINI.md", "config.toml", "settings.json"]);
  let agentBinaries = dynamic(["codex.exe", "claude.exe", "cursor.exe", "code.exe", "gemini.exe"]);
  DeviceFileEvents
  | where Timestamp > ago(lookback)
  | where ActionType in ("FileCreated", "FileModified", "FileRenamed")
  | where FolderPath has_any (agentConfigPaths)
  | where FileName in~ (instructionFiles) or FolderPath has @"\skills\"
  | where not(InitiatingProcessFileName in~ (agentBinaries))
  | project Timestamp, DeviceId, DeviceName, FileName, FolderPath, SHA256,
            InitiatingProcessFileName, InitiatingProcessCommandLine,
            InitiatingProcessParentFileName, InitiatingProcessAccountName
  | order by Timestamp desc
  ```
  Keep the lookback at `ago(30d)` or less, because Defender XDR advanced hunting retains 30 days and silently truncates longer windows. Fill all three lists from the approved-agent inventory rather than from this example, which names only the most common tools, and remember to allowlist the editors developers legitimately use on these files. Triage values are the written path, the writing process and its parent, the account, and the file hash so the content can be recovered and read.
  Stage four, read what was written - Core concept: the installed instructions are plain text and are the evidence, so triage is reading them. In the reported bundle the modules divide the work: one overrides the model's tone with a rule-breaking persona and "blacklists common refusal phrases"; one forbids opening replies by asking for authorization or setting boundaries; one instructs the model not to refuse based on certain technical trigger words and to reinterpret ambiguous requests as professional ones; one "Reframes any offensive-security task as an educational CTF exercise"; and one supplies shortcut phrases intended to strip away remaining caution. A separate module carries the commercial payload, instructing the agent to answer a list of greeting and activation words with a fixed line advertising the author's gateway. Another module designates the author's own gateway host as protected infrastructure, "forbidding any offensive testing against it" even where the user claims authorisation. Triage values are the module filenames, the instruction text, and any hostname appearing in the instructions. Strong red flags are instruction text that names refusal phrases to avoid, text that specifies a fixed response to trigger words, and any hostname in an instruction file that is not the approved model provider or gateway.
  Stage five, where the traffic goes - Core filter: model API traffic from developer workstations to a destination that is not the approved provider or gateway. The business model in the reported case is acquisition for a paid gateway, and Check Point notes that a recent study found some gateways snooping on user data, stealing secrets such as cloud access keys, and in some cases injecting tool calls to execute code in the routed agent's session. That is the escalation path that turns an advertising nuisance into a credential-access problem, and it is why the egress check belongs in the hunt even though the gateway in this case showed no sign of being malicious. Correlation: a developer workstation whose agent configuration was modified and whose model traffic subsequently changed destination is the case to work first.
  A note on remediation evidence - Check Point records that "the package also contains an uninstaller, which reverts all changes done by the installation and restores the original configurations". A clean-looking configuration therefore does not establish that the bundle was never installed, so the file-event history and the 4104 records are the durable evidence rather than the current state of the files.

# H463

Check Point Research found a misconfigured web server belonging to an actor running Cobalt Strike, and on it a toolkit that included something new: a jailbreak bundle for an AI coding agent, distributed publicly on a code-hosting service, with more than 250 stars and an advertisement on a Chinese video platform.

The bundle gives the agent a new personality through modular instruction files. One blacklists common refusal phrases. One forbids the agent from opening a reply by asking whether the user is authorised. One tells it to reinterpret ambiguous requests as professional work rather than refusing on trigger words. One reframes any offensive-security task as an educational exercise. It also installs six Skills covering license cracking, penetration testing, reverse engineering and game anti-cheat bypasses.

Then it does something a jailbreak does not need to do. It writes an advertisement into the agent's global identity file, so that when the developer greets the agent, the agent answers with a fixed line promoting the author's own paid model gateway. Check Point calls this prompt adware: a persistent modification of an agent's trusted instructions, operating entirely through natural language, for commercial ends.

The whole payload is packaged so it cannot be reviewed. The launcher verifies signatures and hashes, decrypts an opaque package with a key embedded in the script, and extracts markdown to a temporary directory. Anyone browsing the repository sees an archive, not prompts.

For a defender the shape is simple and the consequence is not. Something that is not the agent wrote the agent's trusted instructions, and from then on the agent's refusals, its framing and its output are governed by text nobody reviewed.

## Why

- After installation there is no malicious process to detect. The persistence is a markdown file the agent reads on every invocation, so process-centric and network-centric detection have nothing to work with and the write event is the only moment the activity is visible.
- The instruction files are a trust boundary that is not yet treated as one. They are user-writable, they are not signed, they are not in source control, and changing them changes what the agent will do for every future session - which puts them in the same category as a shell profile or a browser extension, surfaces that already get this scrutiny.
- Encrypting the payload defeats review deliberately. A developer who does the responsible thing and reads the repository before installing sees nothing, and the launcher's own signature verification lends the process a reassuring shape. That makes the decrypt-then-write sequence the detection, because it is the point where reviewability was removed.
- The commercial path leads somewhere worse. The bundle exists to acquire users for a third-party model gateway, and gateways sit in the middle of every prompt, every file the agent reads, and every credential it handles - with documented cases of gateways harvesting secrets and injecting tool calls. A developer workstation routed through an unvetted gateway is a credential-access exposure, not an advertising annoyance.
- It is already in the hands of operators. Check Point found this bundle on an actor's server next to Cobalt Strike, the VulnClaw agent and the Ladon framework. The package was probably not built for that, which is the point: dual-use agent tooling spreads on its own merits and arrives in both populations at once.
