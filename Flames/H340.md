  `s5cmd` is a legitimate and well-regarded tool — it exists precisely because it is much faster than the AWS CLI for bulk transfers, so data engineering, media, genomics, backup and ML teams use it deliberately for exactly the pattern this hunt describes. Inventory sanctioned use first: where the binary legitimately lives, which hosts run it, which buckets they target, and under which service accounts. The discriminators that survive are location, identity and target. Legitimate use runs from a managed install path or a CI/CD workspace under a service account, authenticates with an instance profile, an SSO-issued short-lived credential or a secrets-manager-injected value, and targets a bucket in an account you own. The hunt's signal is the conjunction of an unmanaged binary path (`C:\Users\Public`, `%TEMP%`, `C:\PerfLogs`, `C:\ProgramData`, a user profile), a long-lived access key sitting in a plaintext file beside it, execution under an interactive or newly-created administrative account on a file server or backup host rather than a build agent, and a destination bucket outside your organization's AWS account list. On a domain controller, file server or hypervisor host, `s5cmd` execution should be treated as reportable regardless of the other legs, since no legitimate data-engineering workflow runs there. Renaming the binary is trivial, so do not anchor solely on the filename — the argument grammar below is the more durable signal.

  Platform: Windows. Driven by Microsoft Threat Intelligence, "Beyond the ransomware: Tracking Storm-2570's consistent tradecraft across deployments" (September 24, 2026), which records that Storm-2570 "identifies high-value drives and network shares, stages s5cmd.exe and a credentials file" and then runs `cp` operations filtered by extension against documents, spreadsheets, images, databases, mail files and archives, as the exfiltration leg preceding Qilin, DragonForce, Anubis and BERT ransomware deployments. Microsoft published KQL for this actor's PsExec and MeshAgent activity but not for the exfiltration leg; the queries below are derived from the reported tradecraft and s5cmd's documented argument grammar.
  Why the argument grammar is the durable anchor - `s5cmd` has a distinctive CLI that survives renaming: a bare `cp`, `mv` or `sync` verb; an `s3://bucket/prefix` destination URI; wildcard source globs; and the `--include` / `--exclude` flags used for extension selection. It reads credentials from the standard AWS chain, so unlike Rclone there is no `rclone.conf` to find and no obfuscated password to crack — the credential is a plaintext `credentials` file or `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` environment variables. Its `--numworkers` default is high and tunable, so it saturates upstream bandwidth in a way Rclone's defaults do not.
  Sysmon Event ID 1 / Event ID 4688 / DeviceProcessEvents - Core filter: any process whose command line contains `s3://` together with one of `cp`, `mv`, `sync`, `ls` or `du`. This catches the renamed binary. Secondary filter: `FileName` in (`s5cmd.exe`, `s5cmd`) regardless of arguments. Triage fields: `ProcessCommandLine`, `FolderPath`, `AccountName`, `InitiatingProcessFileName`, `InitiatingProcessCommandLine`, `SHA256`. Strong red flags: the `--include` or `--exclude` flag carrying office and archive extensions (`*.pdf`, `*.doc*`, `*.xls*`, `*.ppt*`, `*.csv`, `*.zip`, `*.rar`, `*.7z`, `*.pst`, `*.ost`, `*.bak`, `*.mdb`, `*.sql`, `*.kdbx`); a UNC source path, which means the operator is pulling from a file share rather than the local disk; `--numworkers` set explicitly high; and a parent of `cmd.exe` or `powershell.exe` launched from a PsExec service, RDP session or RMM agent rather than a build agent.
  Sample KQL — s5cmd or renamed equivalent with an S3 destination:
  `DeviceProcessEvents | where Timestamp > ago(30d) | where ProcessCommandLine has "s3://" and ProcessCommandLine has_any ("cp ", "sync ", "mv ") | extend staged = FolderPath has_any (@"\Users\Public", @"\Windows\Temp", @"\PerfLogs", @"\ProgramData", @"\AppData\") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, staged | order by Timestamp desc`
  Sysmon Event ID 11 / DeviceFileEvents — the credential artifact - Core filter: creation of a file named `credentials` or `config` under a path containing `.aws`, or any file named `credentials` created in the same directory as a recently-created unsigned executable. Storm-2570 staged the credentials file *alongside* the binary rather than in `%USERPROFILE%\.aws\`, which is itself anomalous — the AWS SDK only finds it there if `AWS_SHARED_CREDENTIALS_FILE` is set or the tool is passed an explicit profile path, so look for that environment variable being set in the same command line. Strong red flag: a plaintext file containing `aws_access_key_id` created on a file server or backup host. Where you can retrieve the key ID, the `AKIA` prefix indicates a long-lived IAM user key rather than a temporary `ASIA` session credential — long-lived keys on an endpoint are almost never legitimate in a mature AWS estate.
  Sysmon Event ID 3 / DeviceNetworkEvents - Core filter: outbound TLS from the flagged process to `*.s3.*.amazonaws.com`, `s3.amazonaws.com` or `*.s3.dualstack.*.amazonaws.com` on 443. Correlation: join the destination bucket hostname against your organization's known bucket list; a bucket name that is not yours is the decisive finding. Strong red flags: sustained high-volume upload from a file server or backup host to S3 where that host has no prior S3 history at all; upload volume in the hundreds of megabytes to tens of gigabytes within a single process lifetime; and a `RemoteUrl` bucket name that looks like a victim identifier or a random string. Proxy logs are the better source for volume if TLS inspection is unavailable, since Sysmon Event ID 3 does not carry byte counts — pivot on `bytes_out` per destination per host.
  Read-side confirmation - Core filter: Windows Event ID 5145 (detailed file share access) or FSRM telemetry showing the same account enumerating and reading across many shares and directories in the minutes before the uploads. This distinguishes exfiltration from a backup job, which reads from a known source path, and it establishes scope for the incident — which is the question that actually matters once double extortion is confirmed.

# H340

Microsoft's September 24, 2026 report on Storm-2570 tracks a ransomware affiliate whose tooling is remarkably consistent across deployments of Qilin, DragonForce, Anubis and BERT payloads. Among that tooling is `s5cmd`, staged alongside a plaintext credentials file and invoked with `cp` operations filtered by extension to select documents, spreadsheets, images, databases, mail files and archives, uploading them to S3. This is the double-extortion leg: the data leaves before anything is encrypted, which means it is also the last point at which detection changes the outcome rather than merely explaining it.

`s5cmd` deserves its own hunt rather than being folded into existing Rclone coverage, because the two tools leave materially different evidence. Rclone requires a config file, which is a durable forensic artifact and a well-known hunting anchor — `rclone.conf`, with its obfuscated but reversible password. `s5cmd` has no config file at all. It reads the standard AWS credential chain, so the operator either drops a plaintext `credentials` file or sets two environment variables, and the tool itself is a single static Go binary with no installer and no registry footprint. It is also considerably faster by design, with a high default worker count, so it moves the same volume in less time and across a shorter window of network telemetry. A detection engineered around Rclone's config file finds none of this.

What does survive is the argument grammar. `s5cmd`'s S3 URI scheme and verb set are distinctive enough that hunting `s3://` together with a transfer verb catches the tool even after it has been renamed — which matters, since Storm-2570 demonstrably renames its tooling, as the `meshagent64-<organization>.exe` pattern in the same report shows.

## Why

- This is a pre-encryption detection opportunity in an intrusion that ends in ransomware. Storm-2570's exfiltration precedes payload deployment, so a hit here lands while the environment is still recoverable and before the double-extortion leverage exists — the difference between an incident and a negotiation.
- The absence of a config file is the point. Rclone hunts anchored on `rclone.conf` do not transfer to `s5cmd`, and the credential instead appears as a plaintext `aws_access_key_id` in a file beside the binary or in environment variables, which is a different artifact requiring a different query — a gap an organization can easily believe is covered when it is not.
- The command grammar is a durable anchor that survives the actor's own evasion. Renaming the binary defeats a filename rule but not a rule keyed on an `s3://` destination URI paired with a transfer verb and extension filters, and that grammar is forced by the tool's interface rather than chosen by the operator.
- Destination attribution is unusually decisive here. Unlike generic cloud exfiltration, the target is a named S3 bucket resolvable in DNS and TLS SNI, so joining observed bucket names against the organization's own AWS account inventory produces a high-confidence verdict rather than a probabilistic one.
- Context collapses the false positive rate to near zero on the hosts that matter. `s5cmd` is legitimate on build agents and data-engineering workstations and has no legitimate purpose on a domain controller, file server, backup server or hypervisor host — which is exactly where a ransomware affiliate runs it, because that is where the data is.
