hypothesis: >-
  Windows gives users a switch to disable any startup item, and this downloader takes the switch
  away. Kaspersky documents that to establish persistence the CoffeeLoader downloader copies 7z.dll
  to subfolders of %PROGRAMDATA% or %LOCALAPPDATA% and uses the Run registry key for autorun, with
  the subfolder, library and registry value all named with eight hexadecimal digits generated from
  system volume information - so the same infection produces a different name on every host while
  remaining internally consistent. The autorun value invokes rundll32.exe against the dropped
  library and an exported function named SetCodecs. Kaspersky then records a second, less common
  step - to protect itself, the downloader creates a registry key that prevents the user from
  disabling autorun through Task Manager, writing the matching value name under
  Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run with the binary data
  080000000000000000000000. That key is the store behind the Startup tab of Task Manager, so
  stamping it is how the entry is made to resist the one control an ordinary user has. Hunt for
  writes to StartupApproved\Run that are not accompanied by a user toggling anything, and for
  eight-hexadecimal-digit Run values pointing at rundll32.exe.

false_positive_notes: |
  `StartupApproved\Run` is written legitimately every time a user toggles a startup item in Task Manager or Settings, and also by some installers that set their own initial enabled state. The key is a normal part of Windows, so the write event alone is not the finding - the absence of a corresponding user interaction is. In practice that means correlating against whether `Taskmgr.exe` or the Settings app was running, and which process performed the write.

  The enabled-state blob is not a malware signature. A value of `02` or `06` in the first byte generally indicates enabled and `03` indicates disabled in common usage, and Microsoft does not document the format, so interpretations in public research vary and differ across Windows builds. Kaspersky reports `080000000000000000000000` for this sample; do not treat that exact blob as the indicator, because it is one observed value of an undocumented structure and may differ by build. The durable finding is a non-interactive write to the key by the same process that just created the matching `Run` value.

  `rundll32.exe` in a Run key is common and frequently legitimate. Plenty of vendor software, control-panel applets and shell extensions persist this way. The discriminators are the DLL's location - a `%PROGRAMDATA%` or `%LOCALAPPDATA%` subfolder rather than a program directory - and the random-looking folder and value names.

  The eight-hexadecimal-digit naming scheme will produce occasional coincidental matches. Some legitimate software uses GUID fragments, hashes or build identifiers that look similar, and short hex strings are not rare. Require at least two of the three names to match the pattern - folder, DLL and Run value - since Kaspersky states all three are derived from the same system volume information and will therefore agree with each other.

  `7z.dll` is a genuine 7-Zip library and widely present. A copy inside a 7-Zip installation, or bundled by software that legitimately uses the library, is expected. The finding is a copy in a hex-named subfolder of `%PROGRAMDATA%` or `%LOCALAPPDATA%`, which H522 covers from the image-load side.

  Kaspersky does not state how the downloader obtained the privileges to write to `%PROGRAMDATA%`, nor whether the `HKCU` or `HKLM` hive is used for the autorun in each case - the report names the key path without the hive prefix for the Run entry and shows a `Software\...` path for `StartupApproved`. Check both hives rather than assuming one.
notes: |
  Leg one, the autorun-locking write (Sysmon 13 or DeviceRegistryEvents) - Core filter: any value set under `StartupApproved\Run`, with the writing process captured. This is the highest-value query in the hunt because the key is narrow, the legitimate writers are few, and the malicious write has a distinctive context.

      DeviceRegistryEvents
      | where Timestamp > ago(30d)
      | where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
      | where RegistryKey has @"StartupApproved\Run"
      | where InitiatingProcessFileName !in~ ("Taskmgr.exe", "explorer.exe", "SystemSettings.exe", "msiexec.exe")
      | project Timestamp, DeviceName, RegistryKey, RegistryValueName, RegistryValueData,
                InitiatingProcessFileName, InitiatingProcessFolderPath,
                InitiatingProcessCommandLine, InitiatingProcessAccountName
      | order by Timestamp desc

  Thirty days is the whole Defender advanced hunting retention. The exclusion list covers the normal interactive writers and should be tuned against the estate's own installer behaviour. Rank the results on who wrote it: a process running from `%PROGRAMDATA%`, `%LOCALAPPDATA%` or a temporary directory is the finding; `rundll32.exe` writing it is a near-certain finding, since the legitimate path to this key is a human clicking a toggle.

  Leg two, the paired Run value, which is what makes leg one conclusive. The two writes agree by design - Kaspersky states the subfolder, library and registry value are named with eight hexadecimal digits generated from system volume information, so the `Run` value name and the `StartupApproved\Run` value name are the same string. That pairing is the strongest single discriminator available here, because legitimate software that sets both does so as part of an install with a human-readable name, not with a per-host random hex token. The published example shows the shape:

      Software\Microsoft\Windows\CurrentVersion\Run
      'b79faace.dll' = 'rundll32.exe "C:\ProgramData\b79faace\b79faace.dll",SetCodecs'

  Query for `Run` values whose name matches an eight-hex-digit pattern, optionally with a `.dll` suffix, and whose data invokes `rundll32.exe` with an export name. The export Kaspersky names is `SetCodecs`, which is a plausible-sounding media function and not a real 7-Zip export - a useful second check on any candidate, since a genuine library's exports can be enumerated and compared.

  Leg three, the dropped library on disk (Sysmon 11 or DeviceFileEvents). Core filter: a DLL created in a newly-made hex-named subfolder of `%PROGRAMDATA%` or `%LOCALAPPDATA%`. The two published paths are `C:\ProgramData\b79faace\b79faace.dll` and `C:\Users\[username]\AppData\Local\b79faace\b79faace.dll`, where `b79faace` is this host's derived token and will differ everywhere else. `DeviceFileEvents` records creates, modifies, renames and deletes but no reads, which suits this leg - the question is who dropped the file. The directory name matching the file base name is itself anomalous and queryable without knowing the token.

  Leg four, the injection that follows (Sysmon 1, 7 and 10). Kaspersky states that once persistence is established, the malware launches one of several processes - `dllhost.exe`, `WerFault.exe`, `svchost.exe`, `OpenWith.exe` or `AtBroker.exe` - injects itself into it, and downloads the Trojan's main body from a hardcoded C2 server address. `OpenWith.exe` and `AtBroker.exe` are the two worth querying hardest, because neither has much legitimate reason to be spawned by `rundll32.exe` or to hold network connections. A short-lived `AtBroker.exe` with outbound HTTPS on a host with no accessibility tooling in use is close to self-evidently wrong.

  Leg five, the download, for corroboration. The main body is fetched over HTTPS using the `/payload?md5=` path, with the `md5` parameter all zeros on the first request and the previous payload's hash thereafter. The response carries `X-Signature`, verified against a public key embedded in the Trojan, and `X-Content-MD5`, the MD5 of the decrypted payload; Kaspersky notes the payload is encrypted with a simple XOR whose key is the first 16 bytes of the downloaded data. Where proxy logs retain URIs, the `/payload?md5=00000000000000000000000000000000` first request is a distinctive string. The published example host is `api.internet-speed-check.com`.

  Why the autorun lock matters more than it looks. Task Manager's Startup tab is the only self-service removal path most users have, and the Settings app reads the same store. Stamping `StartupApproved\Run` means a user who notices the entry and switches it off either cannot, or finds it re-enabled - so the infection survives exactly the remediation a non-technical victim would attempt, and survives it quietly. For a hunter the useful consequence is that the attacker has written a second registry value they did not strictly need, which doubles the registry footprint and creates a correlation no legitimate installer reproduces.

  Family context for scoping. This is the downloader stage of CoffeeLoader as delivered by the revived Retadup worm; H522 covers the Armoury packer's GPU-based decryption and the patched `7z.dll` that gets this chain started, including the OpenGL compute-shader unpacking and the protocol magic-constant change from `0xC0FFEE42` to `0xD1D57871`. Kaspersky notes the main CoffeeLoader module itself hasn't changed much since previous campaigns and retains the same three commands for running a C2-supplied payload - injecting it into a process, saving it to disk as an executable and running it, or saving it as a DLL and running it via `rundll32.exe`.

  Scope note on existing coverage. A grep of every hunt body for `StartupApproved` returns nothing - no existing HEARTH hunt covers this key, in either its legitimate or its abused form. `T1547.001` Run-key persistence is well represented in the corpus, which is why this hunt is deliberately scoped to the autorun-locking write and the hex-token pairing rather than to Run-key persistence in general; a hunt that simply looked for new Run values would duplicate existing coverage and drown in legitimate installers. H522 is the sibling hunt on the same chain.

# H523

Windows has a switch for this. Open Task Manager, go to the Startup tab, find the entry, click Disable. It is the one piece of malware remediation an ordinary user can perform without help.

The CoffeeLoader downloader writes to the store behind that switch.

Its persistence is otherwise conventional. A copy of a patched `7z.dll` goes into a subfolder of `%PROGRAMDATA%` or `%LOCALAPPDATA%`, and a `Run` value invokes `rundll32.exe` against it with an export named `SetCodecs` — a name that sounds like media plumbing and does not exist in the real 7-Zip library. The folder, the DLL and the registry value are all named with the same eight hexadecimal digits, derived from system volume information, so every host gets a different token and no two infections share a filename.

Then it writes one more value it did not technically need. Under `Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`, against the same hex name, with the blob `080000000000000000000000`. Kaspersky's description of the purpose is plain: it creates a registry key that prevents the user from disabling autorun through Task Manager.

That extra value is a gift. `StartupApproved\Run` is normally written when a human clicks a toggle, so a write performed by `rundll32.exe` from a `ProgramData` subfolder, carrying a random hex name that matches a `Run` value created moments earlier, is a correlation no installer produces by accident.

## Why

- The key has a tiny set of legitimate writers, which makes it a sharp query. `StartupApproved\Run` is normally touched by Task Manager, the Settings app or Explorer in response to a user action. A write from anywhere else is immediately interesting, and a write from `rundll32.exe` has essentially no benign reading.
- The attacker wrote a value they did not need, and paid for it in visibility. Persistence worked without the lock; adding it doubled the registry footprint and created a matched pair of value names that legitimate software does not reproduce.
- The hex-token naming defeats filename rules but creates a better signal. Because the folder, DLL and both registry values derive from the same per-host seed, they agree with each other — so the pattern to hunt is internal consistency plus randomness, not any particular string.
- It is aimed squarely at self-service removal, so it changes who can clean the host. A user who spots the startup entry and disables it will find it unchanged or restored, which means the infection outlasts the only remediation most victims will ever attempt and produces no help-desk ticket.
- The export name is a free second check. `SetCodecs` is not a genuine 7-Zip export, so enumerating the exports of any suspected library and comparing against the real one confirms or clears a candidate cheaply.
- The processes it injects into afterwards are quiet enough to be queryable. `OpenWith.exe` and `AtBroker.exe` are rarely spawned by `rundll32.exe` and rarely hold outbound HTTPS, so the post-persistence stage is as distinctive as the persistence itself.
