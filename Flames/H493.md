false_positive_notes: |
  Legitimate vCenter administration touches TCP 2012 in normal operation, because it is the SSO control-interface RPC port, and vCenter components talk to `vmdird` constantly. The discriminator is never the port on its own - it is the source. Internal traffic to 2012 should originate from vCenter nodes, their replication partners and a short list of management hosts; a Linux appliance, a web server or a user workstation opening an RPC session to 2012 is outside that set. Build the permitted-source register before running the hunt or this leg will drown.

  Legitimate SSO account creation happens during onboarding, service-account provisioning and vendor deployments. Those are ticketed, performed through the vSphere Client or an identity-management integration by a named administrator, and the resulting account normally receives a scoped role rather than Global Administrator on the root folder. Reconcile every new `vsphere.local` principal against change management and against the approved-administrator register.

  Backup and replication software legitimately reads vCenter data at scale. It does not read `/storage/db/vmware-vmdir/data.mdb` byte-for-byte over an RPC bulk-copy interface from an unprivileged internal host; it uses documented APIs and runs from a registered backup server with its own service account.

  Mandiant notes that CVE-2026-123890 overlaps partially with CVE-2026-59309 - both let an attacker obtain the shared session key without knowing the password - but they are different interfaces. CVE-2026-59309 is a `vmdir` daemon flaw reached with crafted LDAP packets on TCP 389 or 636; CVE-2026-123890 is the DCE/RPC interface. An appliance patched against the former is not protected against the latter. Mandiant records BONESAW executing in early September 2026 against a vCenter already patched for CVE-2026-59309, so do not treat patch state for the LDAP issue as scope reduction for this hunt.

  Attribution of a specific intrusion to this CVE from network telemetry alone is not possible - the flows show an RPC session, not the vulnerability. Treat a 2012 session from an unregistered source as a lead requiring appliance-side corroboration, and keep the account-creation leg as the confirming signal.
notes: |
  Network leg - DCE/RPC interface binds (Zeek `dce_rpc.log`, IDS with RPC parsing, NDR) - Core filter: sessions to TCP 2012 on a vCenter appliance whose source address is not in the permitted-administration register. Where the sensor parses RPC, filter on the bound interface UUID. Mandiant's published BONESAW YARA rule names the two interface UUIDs the utility embeds - `c7e94609-6ab0-4767-8e92-b6485bff1649` for the SRP verifier interface and `72c780fe-af6b-42ba-9b02-f61f4ccc98ed` for the vmdir bulk-copy interface - and those two strings, with their little-endian binary encodings, are what the rule keys on alongside the `data.mdb` path. Watching for a bind to the SRP verifier interface followed in the same session or the same minute by a bind to the bulk-copy interface is a far narrower filter than port 2012 alone, and it is not satisfied by routine vCenter component traffic.

      -- Zeek dce_rpc.log, pseudo-query form
      SELECT ts, id.orig_h, id.resp_h, id.resp_p, endpoint, operation, named_pipe
      FROM dce_rpc
      WHERE id.resp_p = 2012
        AND id.orig_h NOT IN (approved_mgmt_sources)
      ORDER BY ts;

  Triage values are `source IP`, `destination IP`, `destination port`, `RPC interface UUID`, `operation`, `bytes sent`, `bytes received`, `session duration` and `first and last seen`. Strong red flags: the response byte count is large enough to be a database rather than a control exchange, which is the exfiltration of `data.mdb` in flight; the same source address also scanned 9080, 5480 and 2012 shortly beforehand, which is the reconnaissance Mandiant recorded as a sequence of `nmap -sS --open` sweeps against VMware-specific ports; the source is a Linux appliance with no EDR coverage.

  Appliance leg - vmdird and SSO logs forwarded off the VCSA - Core filter: `vmdird` activity that reads or copies the directory database outside a backup window, and any SRP authentication sequence that completes without a preceding credential-bearing bind. Also watch for the on-disk residue BONESAW leaves at its output root when run with its account-creation subcommand - a per-host directory whose name begins `extracted_tenant_signer_`, containing a copied `data.mdb` whose filename begins `anon_`, plus the extracted tenant signing credential as paired `.key.pem` and `.key.der` files, a `.leaf.pem` certificate, a `.chain.pem` chain and a `.context.json` metadata file. That file set is the clearest single artefact in the chain, because every element of it is named by Mandiant and none of it is produced by any vCenter process.

  Identity leg - SSO account and permission changes - Core filter: creation of any principal in the `vsphere.local` domain, and any assignment of Global Administrator on the vCenter root folder, cross-referenced against the approved-administrator register and change management. Mandiant observed the actor create a local administrator account on the vCenter appliance whose name carried an `sps-` prefix, and separately records BONESAW creating a backdoor machine account via `vmdir` and forging administrative SAML 2.0 assertion tokens to assign Global Administrator through the vSphere SOAP API. Triage values are `principal name`, `domain`, `creation time`, `creating principal`, `source IP of the creating session`, `role granted`, `object the role was granted on`. Correlation: a new principal whose creation is attributed to the built-in administrator account, in a session originating from an address in the network leg above, with no corresponding interactive login for that administrator beforehand.

  Strong red flags: the creating session's source address is an internal appliance rather than a management host; the account is granted Global Administrator at the root folder rather than a scoped role; SSH is enabled on the appliance within the same window, which is the behaviour H495 covers.

  Hardening that doubles as telemetry - Mandiant's guidance for this campaign is worth reading as a collection plan, because it is explicit that the native VCSA host-based firewall managed through VAMI "does not generate remote logs for denied connection attempts or shell activity", which "blinds the SOC to active lateral movement and port scanning". Their recommended VCSA Hardening and Logging Tool enforces policy with `iptables` at the Photon kernel level and bridges those events to a SIEM, which converts the port-2012 and port-scan legs of this hunt from inference over flow records into first-party appliance events. The same guidance notes that an inbound DROP policy on 2012 for non-allowlisted addresses stops the exploit payload reaching `vmdird` at all.

  Scope note: HEARTH's existing hypervisor hunts approach this plane from other directions - H065 covers VM provisioning through the vSphere API, H074 and H077 cover rogue virtual network interfaces, H458 covers an ESXi root SSH session disabling `execInstalledOnly`, H480 covers Host Profile remediation turning TSM-SSH on across ESXi hosts, and B070 baselines which identities, sources and paths may administer the management plane at all. None of them cover an unauthenticated RPC path into `vmdird` on 2012 or the directory-database theft that follows, and B070 is the baseline this hunt's permitted-source register should be drawn from.

# H493

On November 19, 2026 Mandiant and Google Threat Intelligence Group published the second part of their analysis of ARMORY CASTLE, the suspected PRC-nexus actor formerly tracked as UNC5221, describing how the group reached VMware vCenter after compromising a BeyondTrust Remote Support appliance. The same day, VMware disclosed CVE-2026-123890 — an unauthenticated SRP-6a session key disclosure over DCE/RPC in vCenter Server, which yields a remote authentication bypass and an authenticated session as the built-in administrator principal.

The actor's tool for it, which Mandiant tracks as BONESAW, is a Golang utility that exfiltrates the Lightning Memory-Mapped Database backing vmdir, hijacks the SAML Security Token Service, and creates an SSO administrator account. Mandiant assesses that ARMORY CASTLE's use of BONESAW represents a significant expansion into post-compromise use of zero-days: forensic evidence places execution in early September 2026, against an appliance already patched for the partially overlapping CVE-2026-59309, and the recovered Go binary carries a build timestamp over a month before deployment — though Mandiant notes Go build metadata can be modified prior to compilation.

What makes this huntable without the exploit signature is the shape of the access. vCenter is the control plane for the virtualised estate, and the path the actor took runs from an unmonitored internal appliance, through an RPC port that should only ever be spoken to by vCenter's own components, to an administrator account nobody asked for.

## Why

- The management plane has a small, enumerable set of legitimate clients. TCP 2012 carries the SSO control-interface RPC, so traffic to it from a web server, a Linux appliance or a workstation is outside the design, regardless of what the payload was. That makes the network leg a low-volume filter once the permitted-source register exists.
- Patching alone did not close this path, and Mandiant says so directly. The appliance was current for CVE-2026-59309 and still fell to CVE-2026-123890, because the two flaws sit on different interfaces — LDAP on 389 and 636 versus DCE/RPC. A hunt keyed on behaviour survives that distinction; a scope decision based on patch state does not.
- The actor deliberately operated from appliances that lacked EDR, which is why the hunt is built on network and appliance-side logs rather than endpoint telemetry. Mandiant's hardening guidance for this campaign states plainly that the stock VAMI firewall generates no remote logs for denied connections or shell activity, so the absence of signal from a VCSA is expected rather than reassuring.
- The identity leg is the one that confirms. Directory theft is quiet and an RPC session is ambiguous, but a new `vsphere.local` principal holding Global Administrator on the root folder, created by the built-in administrator with no preceding interactive login, is a finding that stands on its own and is cheap to reconcile against change management.
