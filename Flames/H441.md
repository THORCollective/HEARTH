false_positive_notes: |
  Management-agent password prompts: Jamf Connect, Iru/Kandji, Workspace ONE, NoMAD, and FileVault escrow or password-sync scripts legitimately show osascript or native password dialogs. They run under the management agent or a root launchd daemon, not under a user's Terminal shell. Exclude by the parent's signing ID and team ID, not by dialog text, because the attacker controls that text.
  
  Build and CI keychain use: fastlane, Xcode build scripts, and CI runners such as GitHub Actions, GitLab Runner, and Jenkins call security unlock-keychain routinely. They run under a runner service process, usually target a dedicated keychain (for example build.keychain) rather than login.keychain-db, and are not preceded by an interactive dialog from the same tree. Baseline these per host and per parent.
  
  Legitimate com.apple.* user LaunchAgents: Apple ships almost all of its agents in /System/Library/LaunchAgents. A few legacy user-scope items exist, such as com.apple.CSConfigDotMacCert-*-SharedServices.Agent.plist, but Apple-signed platform binaries write them. Requiring a non-Apple writer, or a ProgramArguments target outside /System, /usr, and /Applications, removes these.
  
  Long-lived connections: chat clients, sync agents, and Electron apps keep WebSocket sessions open, but they are signed, live in /Applications, and are not launched from a com.apple.* plist in user scope. Unsigned Go binaries built locally by developers are common on engineering Macs. They rarely sit behind a KeepAlive LaunchAgent with an Apple label, so that join keeps volume low.
  
  Admin troubleshooting: help-desk staff may paste one-line commands into Terminal, but these should not combine a hidden-answer dialog, a login-keychain check, and a new Apple-named agent. Confirm with the user and the ticket history before closing.

  macOS EDR process telemetry (Endpoint Security exec events) - Core filter: `osascript` whose process command line contains both `display dialog` and `hidden answer`, with `Terminal.app` (or `iTerm2`) in the process ancestry and an interactive `bash`, `zsh`, or `sh` as the parent. Raise priority when the dialog title or text contains `System Preferences` or `System Settings`. Triage values: `process command line`, `parent process command line`, `process ancestry`, `user`, `session ID`, `process start time`. Correlation: within 10 minutes, in the same process tree or login session, look for `/usr/bin/security` with `login.keychain-db` in the command line (verbs such as `unlock-keychain` or `show-keychain-info`). Also look for `dscl` with `-authonly`, which sibling families use for the same password check. Strong red flags: the prompt-and-validate pair repeating (ICMacOS allows up to five tries); `uname -m` followed by `curl` writing a Mach-O to `/tmp` or a hidden folder under the home directory; `chmod +x` on that file; and `osascript` command lines that target `Terminal` to hide or close its window.
  
  macOS EDR file telemetry plus Background Task Management - Core filter: a file create or rename where the file path matches `~/Library/LaunchAgents/com.apple.*.plist`, or `/Library/LaunchDaemons/com.apple.*.plist` when the dropper found root or admin-group rights. The writing process must not be Apple-signed (signing ID not `com.apple.*`, not a platform binary) or must be unsigned or ad-hoc signed. Known example: `com.apple.systemupdater.plist`. Triage values: `file path`, `writing process path`, `writing process signing ID`, `team ID`, `file hash`. Correlation: `launchctl` with `bootstrap gui/<uid>` pointing at the same plist within 2 minutes, plus the Endpoint Security `btm_launch_item_add` event (macOS 13+) or `com.apple.backgroundtaskmanagement` unified-log entries for the same item. Parse the plist and check for `KeepAlive` set to true, `StartInterval` of `3600`, and `ProgramArguments` pointing to an unsigned Mach-O in a user-writable path. Strong red flags: an Apple-labelled plist in user scope whose program sits outside `/System`, `/usr`, and `/Applications`, created within the same hour as a dialog launched from Terminal.
  
  Endpoint network and child-process telemetry (EDR network events, web proxy, NDR) - Core filter: a process started by `launchd` (parent PID `1`) from the LaunchAgent's `ProgramArguments` path that holds one outbound session longer than 30 minutes, or that shows an HTTP `Upgrade: websocket` handshake to a newly seen domain. Triage values: `process path`, `remote domain`, `remote IP address`, `connection duration`, `bytes sent/received`, `child process command line`. Pivot: children of that binary running `/bin/sh -c` or `zsh -c`, and reads by that same binary of `~/Library/Keychains/login.keychain-db`, `~/.ssh/`, `~/.aws/credentials`, `~/.kube/config`, `~/.docker/config.json`, `~/.config/gh/hosts.yml`, `.env` files, and shell history. Strong red flags: a non-Apple binary reading `login.keychain-db` directly (consistent with offline Keychain decryption), followed by creation of an archive and an upload over the same session.
  
  Cloud and code-platform audit logs (AWS CloudTrail, Kubernetes API audit, GitHub/GitLab audit, IdP sign-in logs) - Core filter: first use of credentials stored on the affected Mac from a source IP address or ASN never seen for that user or device, starting after the LaunchAgent write time. Triage values: `access key ID`, `principal`, `source IP address`, `user agent`, `event name`, `token ID`. Correlation: join by `user` and by the access key IDs or token names found in the host's credential files. Prioritize `GetCallerIdentity`, `ListBuckets`, `ListSecrets`, Kubernetes `get secrets`, bulk repository clones, and creation of new personal access tokens within 24 hours. False positive: VPN egress changes and developer travel; check against the host's own egress IP for the same time window.

# H441

ICMacOS, also sold as Icarus macOS, is a macOS stealer sold as a service. SOCRadar identified it in September 2026 and attributes it to GlowComa, a financially motivated Russian-speaking actor active since January 2026. It is advertised on XSS, Exploit.in, and Rehub under the MADHASH crypto-draining affiliate banner, at prices starting at $699 per week, and is bundled with the Icarus ClickFix panel and a crypto clipper.

Delivery starts with a ClickFix page that convinces the user to paste a command into Terminal. A Bash dropper then:
- pulls a second stage
- hides visible Terminal indicators
- shows a fake System Preferences password dialog
- checks the typed password against the local login Keychain, allowing up to five attempts
- checks the CPU architecture with uname -m and downloads a matching Intel or Apple Silicon Go Mach-O.

Version 1 is a stealer. It takes browser credentials, cookies, password-manager data, crypto wallets, Telegram, Discord, WhatsApp, iMessage, and Apple Notes data, plus developer secrets: SSH keys, AWS profiles, Kubernetes configs, Docker auth files, GitHub CLI tokens, .env files, and shell history. It embeds the open-source keychainbreaker library, which decrypts login.keychain-db once the user's password is known. That is why the dropper has to capture and validate the password.

Version 2 keeps the stealer modules and adds a remote shell. It stops older instances and checks for root or sudo-capable group membership, then picks elevated or user-level persistence. The user-level path writes ~/Library/LaunchAgents/com.apple.systemupdater.plist with KeepAlive and a 3,600-second StartInterval and loads it right away with launchctl bootstrap. A Gorilla WebSocket client then connects to the operator, runs incoming commands through /bin/sh, and streams the output back. Persistence lets the operator keep collecting session tokens and cloud credentials from developer laptops.

Other 2026 macOS stealers use the same prompt, validate, then persist pattern: AMOS, MacSync, CrashStealer, and ClickLock (several of them validate with dscl -authonly). So this hunt targets the Apple-binary chokepoints shared across families, not ICMacOS hashes or domains.

## Why

- This is current and high-impact for engineering-heavy organizations: ICMacOS has been sold as a service since September 2026, bundled with a ClickFix panel, and version 2 turns a one-time grab of SSH keys, AWS and Kubernetes configs, and Git tokens into a persistent remote shell. A single compromised developer laptop becomes an ongoing route into source code and cloud control planes.
- The chain forces checkpoints that survive changes to infrastructure and hashes. keychainbreaker needs the user's plaintext password to decrypt login.keychain-db, so the operator has to prompt and validate. Persistence needs a plist written to a launchd path and loaded with launchctl, which macOS 13+ records as a Background Task Management item-add. Domains, payload hashes, and dialog text can change between builds; the osascript, security/dscl, plist write, launchctl sequence cannot without losing the capability.
- Every step uses Apple binaries or file paths that standard macOS EDR already records: Endpoint Security exec events keep the full osascript argument string (dialog text, hidden-answer flag), file events cover ~/Library/LaunchAgents, and btm_launch_item_add ties the plist to its program, so the hunt needs no extra sensors.
- False positives can be filtered on attributes the attacker cannot easily fake: legitimate password prompts come from management agents with known team IDs rather than Terminal shells, CI keychain unlocks run under runner services against dedicated keychains, and Apple's own user-scope agents are written by Apple-signed platform binaries.
