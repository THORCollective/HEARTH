title: "A non-browser process speaking HTTP/3 on UDP 443 to /agent/register and /agent/heartbeat, and dropping to TCP when QUIC is blocked"
hypothesis: >-
  Two custom RATs that Unit 42 attributes to TGR-STA-0049 use HTTP/3 as their primary C2 transport
  specifically because enterprise inspection is built for TCP. Unit 42's reasoning is explicit -
  because HTTP/3 uses UDP, enterprise network defenses cannot perform passive TLS interception
  without breaking the underlying connection, some corporate firewalls and traditional IDS and IPS
  engines are not updated to inspect UDP traffic with the same level of scrutiny as standard TCP
  traffic, and where legacy policy is optimised exclusively for TCP-based web channels, outbound UDP
  port 443 communications frequently bypass deep packet inspection entirely. Hunt the two things
  that survive the lack of inspection. The first is the process-to-protocol pairing. A QUIC session
  on outbound UDP 443 is legitimate when it comes from a browser or a QUIC-aware application talking
  to a major CDN, and anomalous when it comes from a Go or C++ binary in a user-writable directory
  talking to a destination with no CDN footprint. That pairing needs no payload inspection at all -
  only the initiating process, the destination, and the transport. The second is the fallback. Unit
  42 reports that PerfectPioneer RAT relies on HTTP/3 as its primary C2 communication mechanism,
  automatically falling back to HTTP/2 in the event of connection failure, which means that blocking
  UDP 443 egress does not silence the implant - it converts it into an inspectable TCP session to
  the same destination. A host that attempts UDP 443 to an address, is blocked, and immediately
  opens TCP 443 to that same address, from the same non-browser process, is a fallback channel
  resolving itself in telemetry. Where inspection is available on either leg, four URL paths
  identify the family - /agent/register, /agent/heartbeat, /agent/tasks and /agent/result - and
  Unit 42 notes these overlap with the endpoints its modular successor KUKURAT uses, which register
  and heartbeat at /register and /heartbeat nodes.

false_positive_notes: |
  QUIC on UDP 443 is now ordinary traffic. Chrome, Edge, Firefox and many mobile and desktop applications use it by default against Google, Cloudflare, Akamai, Fastly, Microsoft and most large SaaS platforms, so volume on the port says nothing. Every leg of this hunt is therefore conditioned on the initiating process and the destination rather than the port, and the approved-QUIC-application inventory is a prerequisite rather than a refinement.

  Software updaters, telemetry agents and video-conferencing clients also legitimately speak QUIC from non-browser processes. They differ in being signed by a recognisable publisher, installed under Program Files, and pointed at the vendor's own CDN-backed infrastructure. Resolve each flagged process to its signer and install path before treating it as a finding.

  The fallback leg produces false positives wherever UDP 443 is partially blocked for legitimate reasons, because well-behaved applications are designed to fall back to TCP exactly as described. The discriminator is again the process and the destination - a browser falling back to TCP against a CDN is the protocol working as intended; an unsigned binary in `AppData` doing the same against a single unpopular address is not.

  Unit 42 states that compilation timestamps across all analysed PerfectPioneer samples were either systematically modified or completely omitted, so build-time pivots are unavailable for this family and should not be used to age a sample or to order variants.

  The four `/agent/` paths and the `/register` and `/heartbeat` nodes are observed endpoints for the variants Unit 42 analysed, not a protocol requirement. Unit 42 recovered six distinct PerfectPioneer variants from compiled project paths and describes rapid, adaptive development cycles, so treat the paths as this-campaign indicators and the process-and-transport pairing as the durable leg.

  Note that the URI-path legs only exist where traffic is inspectable. On the HTTP/3 leg they generally will not be, which is the entire premise of the actor's protocol choice. Treating absence of a URI-path hit as absence of the implant inverts the finding.
notes: |
  Transport-and-process leg (Sysmon Event ID 3, DeviceNetworkEvents, firewall logs) - Core filter: outbound UDP destination port 443 where the initiating process is not an approved QUIC application and the destination is not in the organisation CDN and SaaS register. Sysmon Event ID 3 records UDP connections as well as TCP, so this is answerable from stock Sysmon with a configuration that does not exclude UDP - check that first, because many deployed configurations drop UDP to control volume, and if yours does, this hunt has no data until that changes.

  KQL - Defender XDR, non-browser QUIC egress. Advanced hunting retains 30 days, so keep the lookback at `ago(30d)` or less.

      DeviceNetworkEvents
      | where Timestamp > ago(30d)
      | where RemotePort == 443
      | where Protocol =~ "Udp"
      | where RemoteIPType == "Public"
      | where InitiatingProcessFileName !in~ ("chrome.exe", "msedge.exe", "msedgewebview2.exe", "firefox.exe", "brave.exe", "opera.exe", "ms-teams.exe", "teams.exe", "onedrive.exe", "outlook.exe", "slack.exe", "zoom.exe")
      | summarize FirstSeen = min(Timestamp), LastSeen = max(Timestamp), Conns = count(), Dests = dcount(RemoteIP), SampleDests = make_set(RemoteIP, 10)
          by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256
      | extend Span = LastSeen - FirstSeen
      | where not (InitiatingProcessFolderPath startswith @"C:\Program Files")
      | where not (InitiatingProcessFolderPath startswith @"C:\Windows\System32")
      | order by Conns desc

  Triage values are `device name`, `initiating process name, folder path and SHA256`, `signer`, `destination IP`, `destination name from DNS`, `connection count`, `distinct destinations`, `session span`, `bytes sent` and `bytes received`. Strong red flags: the process folder path is under `AppData`, `ProgramData`, `Users\Public` or `Windows\Temp`; a single destination rather than the many a CDN-backed client contacts; the destination name is young, has no popularity ranking, or masquerades as an official government website, which is the phishing infrastructure pattern Unit 42 describes; the process is a Go binary, which is what PerfectPioneer is built in, or a C++ binary, which is what KUKURAT is built in.

  Fallback-channel leg (firewall permit and deny records joined to connection telemetry) - Core filter: for each source host, a denied or failed outbound UDP 443 attempt to an address, followed within a short window by a successful TCP 443 connection to that same address from the same process. The window must be bounded or the correlation is meaningless across a long lookback; a two-minute window around the UDP attempt is a reasonable starting point.

      let udp_fail =
          DeviceNetworkEvents
          | where Timestamp > ago(30d)
          | where RemotePort == 443 and Protocol =~ "Udp"
          | where ActionType in ("ConnectionFailed", "ConnectionRequest")
          | project UdpTime = Timestamp, DeviceId, DeviceName, RemoteIP, InitiatingProcessFileName, InitiatingProcessFolderPath;
      let tcp_ok =
          DeviceNetworkEvents
          | where Timestamp > ago(30d)
          | where RemotePort == 443 and Protocol =~ "Tcp"
          | where ActionType == "ConnectionSuccess"
          | project TcpTime = Timestamp, DeviceId, RemoteIP, InitiatingProcessFileName;
      udp_fail
      | join kind=inner tcp_ok on DeviceId, RemoteIP, InitiatingProcessFileName
      | where TcpTime between (UdpTime .. UdpTime + 2m)
      | project DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, RemoteIP, UdpTime, TcpTime
      | order by UdpTime desc

  This is the leg worth building a control around rather than only a hunt. Denying outbound UDP 443 except from the approved QUIC application inventory does not block this implant, but it does force it onto a transport the organisation can inspect, which converts an uninspectable channel into a visible one. Treat that as the recommended configuration change arising from the hunt.

  URI-path leg (proxy or TLS inspection, on whichever leg is inspectable) - Core filter: requests whose URI path is `/agent/register`, `/agent/heartbeat`, `/agent/tasks` or `/agent/result`, or whose path is `/register` or `/heartbeat` on a destination that is not a known API. Unit 42 lists the first four as the endpoints the `newhttp3` variant uses, and notes the overlap with KUKURAT as an artefact connecting the two families to a common development pipeline. Correlation: a registration request followed by repeated heartbeats and task polls to the same host is the implant's whole lifecycle in four path values.

  Host-side corroboration - Unit 42 documents three delivery routes worth pivoting on once a candidate process is identified. A legitimate, structurally modified executable carrying XOR-encrypted shellcode with an accompanying malicious loader DLL, which is sideloaded on execution - so check the signature and section layout of the apparently benign parent, not just the DLL. A decoy software installer that runs a real setup wizard while writing and executing the RAT in the background, including one case where a genuine GlobalProtect installer was used as cover. And executables disguised as PDF files with a PDF icon, which launch a decoy document to maintain the illusion while the malware runs - in one case a decoy impersonating a 2025 official document from the Union Election Commission of the Republic of the Union of Myanmar. Also look for the implant's own quiet habits, which are themselves unusual: PerfectPioneer tracks and deletes all temporary files it creates, and forces Go's garbage collection when its memory footprint exceeds 100 MB to keep resource use unremarkable.

  Scope note: H263 covers QUIC only incidentally, as the default transport of a Cloudflare tunnel connector on UDP 7844, and keys on named tunnel infrastructure rather than on the protocol choice; M069 scores a proxy family's transport mix including QUIC as one feature among many. Neither covers a custom RAT using HTTP/3 as its primary C2 with an automatic HTTP/2 fallback, and neither addresses the inspection gap that motivates it.

# H498

Unit 42 published analysis on November 16, 2026 of a multi-stage cyberespionage campaign against Southeast Asian government entities running since at least July 2025, tracked as TGR-STA-0049 and also tracked elsewhere as REF7707, Earth Alux and Ink Dragon. The group previously deployed Squidoor, also known as FINALDRAFT. This campaign introduced two previously undocumented custom RATs: PerfectPioneer RAT, a Go family seen from July 2025 in six distinct variants, and KUKURAT, a modular C++ successor seen in the wild from March 2026.

Both use HTTP/3 as their primary C2 transport. Unit 42 describes HTTP/3 adoption as rare across the broader malware landscape but reflecting an emerging trend among advanced threat actors, and is specific about why it helps the attacker: QUIC runs over UDP, so passive TLS interception is not possible without breaking the connection, and firewalls and IDS or IPS engines tuned for TCP web traffic frequently let outbound UDP 443 past deep packet inspection entirely.

That is a detection problem, not a detection impossibility. The protocol choice removes payload visibility but leaves the two things this hunt is built on: which process is speaking QUIC and to where, and what the implant does when QUIC does not work — Unit 42 reports PerfectPioneer falls back automatically to HTTP/2.

## Why

- The inspection gap is real and the hunt is designed around it rather than against it. Nothing here requires decrypting QUIC. A Go binary in a user-writable directory holding a UDP 443 session to a single unpopular destination is a finding built entirely from connection metadata.
- The fallback is an exploitable design decision. Restricting outbound UDP 443 to an approved application inventory does not stop the implant; it pushes it onto TCP 443 where the organisation's existing proxy and TLS inspection already work. That makes the hunt actionable as a control change, not only as a query.
- The destination side is unusually weak for this actor. Unit 42 describes phishing infrastructure using lookalike domains masquerading as official government websites, which gives DNS-based enrichment — domain age, popularity, lookalike scoring — real discriminating power against a campaign whose transport is otherwise uninspectable.
- The implant actively works against forensic recovery, which raises the value of network telemetry over host artefacts. PerfectPioneer continuously deletes the temporary files it creates and forces garbage collection above a 100 MB footprint specifically to keep its on-host presence small and its resource use unremarkable.
