# H283

Two hiding tricks in this campaign are worth separating, because they defend against different
observers.

The first is the leading dot. Payloads staged in `/tmp` are named `.something`, which removes them from
`ls` output and from any casual eyeballing of the directory. It does nothing against telemetry — the
kernel does not care about the dot — but it is remarkably effective against the human step of an
investigation, and against scripts that enumerate directories naively.

The second is name impersonation, and it is aimed at the analyst reading a process list. The operators
create a *directory* called `/tmp/python3` and run the ELF from inside it with supervisord-style
arguments. Someone scanning process output sees a path containing `python3` and a command line that
looks like a process supervisor, and moves on. Microsoft records the same instinct elsewhere in the
campaign: the Kestra XMRig payload was "downloaded, unpacked, and renamed to evade name-based
detection," and relaunch paths were made to mimic systemd and daemon conventions.

Then `chattr +i` makes the payload directories immutable, so cleanup scripts and even root-owned
tooling fail to remove them without first clearing the attribute. That is a defense-evasion measure with
an unusually clean detection profile — it is rare for running processes to set the immutable bit, and
the execve of `chattr` with a `+i` argument is a well-covered Elastic and Splunk analytic.

Worth noting for scoping: this is deliberately the Linux-and-containers counterpart to the Windows
hidden-attribute tradecraft. The mechanism (dot prefix, world-writable staging, ELF impersonating an
interpreter) and the telemetry (execve, `DeviceProcessEvents` FolderPath) are entirely different from
`attrib +h +s` on a `C:\ProgramData` directory, which is why it is a separate hunt rather than a
platform note on one.

## Why

- **The dot prefix costs the attacker nothing and defeats the manual step of triage.** An analyst who
  SSHes to a suspect host and lists `/tmp` sees nothing unusual. The technique survives not because it
  beats EDR but because it beats the human, and the human is frequently the last line when automated
  detection has already been evaded. Querying for it in telemetry — where the dot is plainly visible —
  inverts that advantage at essentially zero cost.
- **Name impersonation targets the analyst too, and `/tmp/python3` is a directory, which is the tell.**
  A real Python interpreter lives in `/usr/bin` or a virtualenv, not in a world-writable directory. The
  conjunction the source query uses — `FolderPath == "/tmp/python3"` together with `supervisord` in the
  command line — is specific enough to be nearly self-validating, and generalizes to any binary running
  from a path that impersonates a system component.
- **Execution from world-writable directories is a chokepoint the whole campaign passes through.** The
  RAGFlow chain base64-decoded Python payloads, wrote them to `/tmp`, and executed them sequentially
  with no interactive shell. The LiteLLM ELF was `/tmp/d`. Kestra's miner was unpacked and renamed. The
  operators vary the delivery, the encoding and the payload, but they all have to execute something out
  of a writable path — which makes an auditd execve watch on /tmp, /var/tmp and /dev/shm one of the
  highest-leverage Linux rules available.
- **The immutable bit is rare enough to be a standalone signal, where the filesystem allows it.** It is
  unusual for a running process to set `+i`, and both Elastic and Splunk publish analytics on `chattr`
  execution with an immutable argument. When it does appear outside of configuration management, it is
  a strong indicator that someone expects their files to be deleted.
- **Absent VirusTotal reputation is a signal, not a gap, in this context.** The LiteLLM ELF was not
  present on VirusTotal at publication. For a binary executing out of `/tmp` under a hidden name on an
  internet-facing gateway, "we have never seen this file before" argues for investigation rather than
  against it.
- **Containers make the baseline unusually tight.** A given image's entrypoint has a near-fixed process
  tree, so execution of an unexpected binary from `/tmp` inside a running container is anomalous almost
  by default — far more so than on a general-purpose host. If you are scoping this hunt and want the
  cleanest starting population, start with containerized gateways.
