# H333

Checkmarx Zero reported an ongoing npm campaign centered on indexed-btree, a counterfeit of the legitimate sorted-btree library that accumulated roughly two million weekly downloads, with about ten related packages removed from npm. The campaign is notable because it was built to defeat the install-time defenses GitHub shipped with npm v12 in June 2026: instead of preinstall/install/postinstall lifecycle scripts, the loader hides inside the package's own BTree.prototype.set() method and only fires when the consuming application calls it with a specific key, so installation looks clean, no approval prompt triggers, and taint-analysis or static scanning of install scripts finds nothing. Once triggered, the malware collects architecture, hostname, CPU, memory, and uptime and exfiltrates the profile through hardcoded Slack and Telegram channels; it then polls a smart contract on the Ethereum Sepolia testnet as a dead-drop resolver, using an X25519 key exchange to derive an AES key and decrypt a second-stage payload stored in the contract - a C2 channel with no domain to sinkhole or server to seize. When operators end an intrusion, the malware deletes its files and removes the malicious trigger from the installed package code to erase evidence. The actors also fabricated a convincing GitHub repository and commit history for legitimacy. Because every install-time control misses this class, the durable defensive chokepoint is the runtime conjunction: one application node process doing chat-API host profiling, blockchain RPC dead-drop polling, and self-editing of its own installed dependency files.

## Why

- npm v12's June 2026 defenses gate preinstall/install/postinstall lifecycle scripts, and this campaign was engineered specifically to render that control irrelevant by moving the trigger into a core library method that fires at application runtime - so every team relying on install-script blocking or install-time scanning has zero coverage against a package that reached ~2M weekly downloads.
- The hunt logic keys on an invariant conjunction rather than rotating indicators: package names, Slack/Telegram channels, and RPC providers all rotate cheaply, but the campaign's architecture requires one application node process to profile the host to a chat API, poll a blockchain read endpoint for dead-drop tasking, and edit its own installed package files for cleanup - abandoning any leg forces the actor to re-architect their unsinkholeable C2 design.
- Every leg lands in commodity telemetry with no payload decryption required: process ancestry distinguishes application-runtime node from package-manager children, chat-API and Sepolia RPC hostnames are visible in DNS/TLS/proxy logs, and node_modules writes/deletes are standard EDR file events - the hunt is a join, not a reverse-engineering exercise.
- False positives are structurally controllable because the benign populations do not overlap: web3 tooling polls RPC but never profiles hosts to Telegram, CI notifiers hit Slack but never poll testnets, and package managers write node_modules only with install-time ancestry - requiring two of three legs on one process collapses the noise floor, and the self-editing leg alone has effectively no legitimate equivalent.
