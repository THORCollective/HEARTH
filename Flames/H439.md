false_positive_notes: |
  A three-character string is a weak matcher and `art` collides with ordinary English and with real software. `artx` and `artex` will match product names, artefact directories, art asset pipelines, user names and build identifiers. Require the match to sit in a plausible position - a parameter value, a directory component, a role-name prefix - rather than anywhere in a long command line, and expect to allowlist a handful of legitimate products per environment on first run.
  `C:\ProgramData` is heavily used by legitimate software and a new subdirectory there is routine. The directory name is the specific part; the location is not. Do not generalise this check to "new directories under ProgramData" or it will return the entire software estate.
  Cloud administration-command comments are free text and some teams genuinely use structured prefixes in them for change tracking. Confirm the local convention before treating a prefix as hostile, and check whether the issuing principal is one your change process recognises.
  Role-name prefixes collide with naming standards. An organisation that prefixes roles by team or application may already have something that matches. Compare against the role inventory and creation timestamps rather than the name alone.
  These are default strings in an open framework, so they are the first thing an operator changes once they are published. Absence of a match means the framework was not used with its defaults; it does not mean the framework was not used. Record that limitation explicitly with any clean result, and treat the behavioural hunts paired below as the durable half of this work.

  What the report states - CrowdStrike OverWatch observed a single ARTEX controller directing exploitation against entities in at least 14 countries over an 11-day window beginning October 17, 2026, and states the controller "intermittently exposed adversary tooling, target files, and ARTEX agent transcripts". The framework is described as follows: "ARTEX coordinates a main agent with subordinate planner and worker agents over a shared graph of facts, findings, and goals, advancing each engagement from initial access through host reconnaissance and lateral movement." CrowdStrike confirmed post-exploitation at nine organisations, where the adversary "gained access, deployed BLOODALCHEMY, and conducted follow-on credential spraying, network scanning, and reconnaissance".
  The hunting guidance is the vendor's own, quoted in full in the hypothesis above - command-line strings, cloud role prefixes, administration-command comment prefixes, and a named directory. This hunt is a structured way of running those four checks and keeping the result honest about how long they will work.
  Why the cloud comment field is the best of the four - an administration-command comment is operator-supplied free text attached to a command sent to instances through a cloud systems-manager service. It is recorded in the control-plane audit log, it is almost never inspected, it is not load-bearing for anything, and a consistent prefix in it is a single string match across an entire account's command history. It is also the artifact least likely to be noticed and changed by the operator, because nothing breaks if it stays.
  Why this is worth doing even though it is fragile - these are framework defaults rather than tradecraft. The report makes clear the operator was not being careful about infrastructure hygiene: the controller exposed its own tooling, target files and transcripts in open directories. An operator who leaves transcripts readable is unlikely to have renamed a working directory. That will change now the strings are public, which is why the pairing section below matters more than the string matches.
  Check 1 - the host strings, over the retained window:
  ```kusto
  let marker = dynamic(["artx", "artex"]);
  DeviceProcessEvents
  | where Timestamp > ago(30d)
  | where ProcessCommandLine has_any (marker)
  | project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine,
            InitiatingProcessFileName, InitiatingProcessCommandLine
  | order by Timestamp desc
  ```
  `has_any` is term-based rather than substring-based, which cuts the collision rate substantially compared with a `contains`. Review every hit by hand on first run and build the allowlist from what comes back; this is a string hunt and it cannot be trusted unsupervised.
  Check 2 - the named directory. This is a location-and-name match, not a pattern:
  ```kusto
  DeviceFileEvents
  | where Timestamp > ago(30d)
  | where FolderPath has @"\ProgramData\artx5v"
  | project Timestamp, DeviceName, ActionType, FileName, FolderPath,
            InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256
  | order by Timestamp asc
  ```
  `DeviceFileEvents` records creates, modifies, renames and deletes but no reads, so this finds the directory being populated and not the framework reading from it. The earliest record is the one worth having, which is why this is ordered ascending.
  Check 3 - the cloud control plane, which is where the most specific artifact lives. In the account's audit records, filter administration-command invocations to those whose operator-supplied comment begins with the published prefix, and separately list identity roles whose names carry the published prefix. Then pivot on the issuing principal rather than on the string: enumerate every command that principal has sent, the instances it targeted, and when it was granted the permission to do so. CrowdStrike describes the scale this reaches - at one organisation an agent chained an unsigned SAML assertion and an XML external entity flaw to query the instance metadata service, "obtaining a role capable of issuing administration commands to thousands of instances before escalating to recover an enterprise administrator account". The blast radius of one such role is the finding, not the prefix.
  Check 4 - the web shells, in both languages. CrowdStrike records that the agents "Deployed JSP and PHP web shells", so a content and file-creation sweep of web-accessible directories has to cover both rather than whichever one the local stack uses; an agent working through a mixed estate writes what fits each host. Pair this with the credential-access activity the report observed next: LAPS password reads, resource-based constrained delegation abuse, and password spraying.
  The operator was in the loop, and it shows in the timestamps - CrowdStrike recovered transcripts showing "an operator issuing instructions in Chinese" and notes they were "timestamped in China Standard Time". That is an analytic aid rather than a detection: activity clustered into one foreign working day, across multiple unrelated victims, is a corroborating pattern once a candidate is in hand.
  Inference, not stated by CrowdStrike - the three queries, the `has_any` term-matching argument, the ascending ordering, the pivot-on-principal approach and the collision warnings are mine. CrowdStrike published the markers and the campaign narrative, not detection logic. CrowdStrike also states the second commercial model the operator used "could not confirm", so nothing here assumes a particular provider, and the hashes and C2 domains in the report are deliberately not reproduced as hunting inputs because they belong to the implant rather than to the framework.
  Pairing, and the durable half of this work - [[M067]] covers the sensor-coverage sweep the same operator directed, which is behavioural and survives a rename. Run it alongside this hunt, and prefer it once these strings go stale. [[H408]] and [[H410]] are existing hunts derived from other operators' exposed ARTEX environments: H408 covers credentials read out of a Java heap dump recovered from such a host, and H410 covers a PHP bot joining an IRC channel on a commerce server run by a rebranded ARTEX build. Both hunt follow-on artefacts of an ARTEX-driven intrusion; this hunt is the only one that targets the framework's own footprint, which is the distinction between them.
  Corroborating reporting - Microsoft states that since late October 2026 it "identified Onyx Sleet and Pearl Sleet leveraging open-source agentic AI penetration testing ARTEX in operations", and AhnLab reports that Korean researchers "first discovered ARTEX-related strings on the web server used in the attack" against financial-sector targets, and that redistributed builds under different names persist after the original repository was removed. Three vendors independently placing the same framework in unrelated intrusions is the reason this is worth a standing check rather than a one-off sweep - and the redistribution under new names is the reason the string matches will decay.

# H439

An intrusion driven by an AI agent framework is still an intrusion: something has to run commands, write files and call APIs. And a framework that was never built to be covert leaves its own name in the things it makes.

CrowdStrike recovered that residue directly. A single ARTEX controller, linked to VAPOR PANDA infrastructure, drove exploitation against organisations in at least 14 countries over an 11-day window, and it "intermittently exposed adversary tooling, target files, and ARTEX agent transcripts." From that, CrowdStrike published four things to look for: "command-line parameters containing artx or artex strings, artx-prefixed cloud roles, art18- administration-command comments, and the C:\ProgramData\artx5v\ directory."

What is notable about that list is that none of it is tradecraft. These are defaults — a working directory, a role naming convention, a comment prefix — that nobody changed. The same report describes an operator who left transcripts, tooling and target files readable in open directories. Someone that careless about infrastructure is unlikely to have renamed a scratch folder.

The cloud half of the list is the most useful, and it is the part most hunters will not have checked. An administration-command comment is operator-supplied free text attached to commands sent to instances through a cloud systems-manager service. It is recorded in the control-plane audit log, nothing depends on it, and almost nobody reads it — which makes a consistent prefix in it both a clean string match across an entire account's command history and the artifact least likely to get cleaned up, because leaving it costs the operator nothing.

Two honest caveats. First, `artx` is a three-character string and it collides with real software, user names and asset pipelines; this is a supervised hunt with an allowlist, not an unattended rule. Second, and more importantly: these strings are public now, so they will decay. An absence of matches means the framework was not used with its defaults, not that it was not used. AhnLab already reports redistributed builds circulating under changed names after the original repository was removed. That is why the behavioral hunt paired with this one is the half worth keeping, and why a clean result here should be recorded with its limitation attached rather than as a clean bill of health.

## Why

- Framework defaults are the cheapest possible detection while they last, and this operator demonstrably did not harden them — the same controller exposed its own transcripts and tooling.
- The cloud administration-command comment field is operator free text in the control-plane audit log that is almost never inspected, which makes it both highly specific and unlikely to be sanitised.
- Three vendors independently place this framework in unrelated intrusions — a China-nexus espionage campaign, North Korean operations, and financial-sector attacks in Korea — so it is a standing check rather than one campaign's indicator list.
- The agents wrote web shells in two languages across a mixed estate, so a single-stack content sweep will miss half of what an agent-driven intrusion leaves behind.
- One compromised cloud role in this campaign could issue administration commands to thousands of instances, so the pivot that matters is the issuing principal's blast radius rather than the string that found it.
- The approach is inherently perishable, and saying so is part of the finding: the durable version of this hunt is the behavioral one it is paired with.
