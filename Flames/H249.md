# H249

The service is called `svchost32`. Its display name is "Cloud Sync Service" and its description says it "Synchronizes files with the cloud storage provider." Both are lies, and both are well-chosen — a SOC analyst scrolling a service inventory reads that line and moves on, because every environment has a cloud-sync agent. The one field that does not cooperate is the ImagePath: `%APPDATA%\svchost32\svchost32.exe`.

That is the whole hunt. No genuine Windows service runs its binary out of a user's roaming profile, and the naming is a deliberate near-miss of `svchost.exe` designed to survive a quick eyeball.

## Why

- **Service persistence buys SYSTEM and survives reboot, which is why it is worth the adversary's noise.** CornFlake accepts the relatively loud 7045 event because an auto-start LocalSystem service is durable and looks legitimate in inventory. That trade is what makes the event a reliable hunting anchor — the adversary cannot avoid generating it and still get the property they want.
- **ImagePath location is a near-binary discriminator.** Service name and description are attacker-controlled free text and will always be plausible. The path is constrained by where the implant was able to write, and unprivileged malware writes to `%APPDATA%`. Hunting the path rather than the name is what keeps this from being a stale IOC.
- **The watchdog means remediation feedback is misleading.** Microsoft notes CornFlake continuously restores removed persistence. Delete the service, confirm it is gone, and it comes back — so the hunt output needs to drive full-host response, not a targeted deletion. Check the Run key and scheduled task siblings before declaring the host clean.
- **A hit here dates the intrusion backwards.** This is stage two. Finding it means the captive-portal delivery in [[H248]] already succeeded, ChocoShell almost certainly ran, and the user's Entra tokens and browser credentials left with it. The service is the artifact you find; the identity compromise is the actual incident.
