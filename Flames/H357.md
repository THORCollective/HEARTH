# H357

The Blinder Tunnel implant that Unit 42 documented in October 2026 treats GitHub as its entire control plane, and it plans for losing it.

Routine tasking is plain repository traffic. ShelbyLoader V2 carries a hardcoded Personal Access Token, derives a 16-hex-character `machineId` from a SHA-256 over the string `Peaky Blinders 2.1` plus a host fingerprint, uploads the Base64 machine fingerprint to `/{machineId}/Lic.txt` through the Contents API, and polls `/{machineId}/Inf.txt` every 63 seconds for commands. If GitHub rate-limits it with a 403, it sleeps for an hour and carries on.

The interesting half is what happens when that token is revoked. On a 401, the loader does not die — it searches GitHub Issues for content matching the current date as `yyyymmdd`, pulls an AES-256-CBC blob out of an HTML comment in the issue body, and decrypts it with a key of MD5(today + machineId), the IV being MD5 iterated five times over that key. The plaintext carries a new repository owner, repository name and token, and the implant rebuilds its channel. Revoking the token and taking down the repo, the two obvious responses, are exactly the trigger for re-resolution.

For a hunter this produces an unusually specific artefact: a non-browser, non-Git process calling the GitHub Issues *search* API. Nothing in a normal software estate does that, and when it happens it marks the moment an implant is recovering from your own containment action.

## Why

- **Takedown-resistant by design.** Blocking the repository or burning the token is the event that activates the backup path. A defender who revokes the PAT and declares the channel dead has, in this design, triggered re-resolution instead of stopping it.
- **The destination cannot be blocked.** `api.github.com` is load-bearing for nearly every software organisation, so domain blocking is not available as a control. That forces detection onto process identity, request shape and population — all of which are observable.
- **Non-developer hosts give the hunt a clean population.** The signal-to-noise problem with GitHub C2 is entirely about developer workstations. Finance, HR, clinical and OT endpoints reaching the GitHub API at a fixed interval are anomalous almost by definition, and that is where this campaign's victims sat.
- **The identifier shape is derivable, not just an IOC.** A Contents API path whose directory component is exactly sixteen lowercase hex characters is a structural pattern that survives the operator rotating repositories, tokens and account names.
- **Jitterless timing is a protocol-independent tell.** A 63-second interval with near-zero variance distinguishes the implant from both human browsing and package-manager traffic without needing to see the URI, which matters wherever TLS is not inspected.
- **A resolver hit is a containment-quality finding.** It says the host is compromised *and* that the primary channel has already been disrupted, which tells the responder exactly where in the incident they are standing.
