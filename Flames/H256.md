# H256

XCSSET does not need a privilege escalation, a user prompt, or a persistence mechanism the OS would recognise. It writes a run-script build phase into the developer's Xcode project and appends a payload to `.git/hooks/pre-commit`, and then it waits. The next time the developer builds or commits — something they do dozens of times a day — the code runs under their account, with their Keychain, their SSH keys, their AWS tokens and their Git credentials.

Then it spreads. `replicator_finder` walks the host injecting every `.xcodeproj` it finds, `git_finder` does the same to every repository, and anyone who clones and builds an infected project becomes the next host without doing anything wrong.

## Why

- **The trigger is an action the developer performs voluntarily, constantly, and without suspicion.** There is no lure to spot and no prompt to decline. Build and commit are the two things a developer does most, which makes execution frequency effectively guaranteed and makes user-awareness controls irrelevant here.
- **Developer workstations are the worst possible host to lose.** The credential set on a build machine — Keychain, SSH keys, Git tokens, AWS tokens, signing identities — is the set that reaches production. This is why a macOS developer fleet deserves its own hunt rather than being folded into general endpoint coverage.
- **One of the two injection points is already under version control, and that is a gift.** `project.pbxproj` is a tracked file, so an injected build phase shows up in `git status` and in pull-request diffs. Git hooks are not tracked and are invisible to code review. That asymmetry should shape the response: hunt hooks on the endpoint, and catch pbxproj injection in review.
- **Mass injection is the discriminator that makes this tractable.** Run-script phases and pre-commit hooks are both legitimate and widespread — Husky, SwiftLint and Crashlytics all live in exactly these places. What no legitimate tool does is rewrite the build phase and hook of every unrelated project on the machine in one pass. Hunting the breadth rather than the individual file is what keeps the false-positive rate survivable.
