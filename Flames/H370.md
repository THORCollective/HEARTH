false_positive_notes: |
  Extension-versus-content mismatch is less noisy than it sounds, but it is not free. Legitimate sources - minified and bundled JavaScript with embedded base64 or source maps can score high on naive entropy tests, as can already-compressed or encrypted assets served deliberately, web fonts, WebAssembly, sprite sheets and some SVG; CMS and framework caches write opaque serialized blobs under arbitrary names; `.js` files that are actually JSON, and `.png` files that are genuinely optimised PNGs with high-entropy IDAT streams, will both appear in a poorly-tuned entropy sweep. The fix is to test the bytes against the claimed type rather than entropy alone - a real PNG starts `89 50 4E 47`, a real GIF starts `GIF87a` or `GIF89a`, a real JPEG starts `FF D8 FF`, a real gzip starts `1F 8B`, and a `.js` or `.css` file that `file` classifies as binary is not text regardless of its entropy. Classify the whole file rather than the first line, because legitimate JavaScript can start with a UTF-8 byte-order mark or a copyright symbol. Use entropy only as a secondary ranking feature on files that already failed the type test. The second benign class is real `.gz` archives in application paths - backup and log-rotation output legitimately lands in writeable directories, so `All_scanner_vXX.pl.gz` style names need the directory and the writing process to carry the signal rather than the extension; a real gzip passes the header test, so a `.gz` that fails it is worth reading. Third, developer and deployment churn writes a lot of files into web roots; scope by writing process. For the Curlc4 leg, `clientid`, `cp` and `.run` are generic file names on their own - only the combination in one directory, or the hardcoded key strings, carries signal.

# H370

`001.gif` is a multi-megabyte file that does not start with `GIF89a`. That is the whole finding.

CISA's October 2026 advisory on Integrity Technology Group-enabled activity says the actors staged a MySQL email dump "with discreet file names to minimize detection" - `001.gif`, `Include.png`, `Css.js`, `M2k.js`, `M2k_list.js`, `M2k_ui_adm.js`, `All_scanner_vXX.pl.gz`. Every one of those reads as web furniture. Look at a directory listing and you see an image, a stylesheet, some JavaScript with a vaguely administrative name. Nothing in the listing says "mailbox dump."

So the artefact is the file, and the signal is disagreement between the name and the bytes. A real GIF begins `GIF89a`. A real PNG begins with eight bytes everyone can recite. A real gzip begins `1F 8B`. A real JavaScript file is text from start to finish. A database export or a compressed mail archive is none of those things.

Reading the first eight bytes of every large static asset is a cheap sweep, and a size floor does most of the tuning for free - the floor is a tuning choice, not something CISA reports, but a mail dump is likely to be large and a sprite is not.

The same advisory describes a second, separate piece of tooling: a PHP bot, `Curlc4.txt`, that pulls mail through the Microsoft EWS API, compresses it, and in some instances encrypts it with RC4 or AES-128-CBC. CISA does not say the disguised names were that bot's output, so this hunt keeps the two apart. The bot is worth its own sweep because CISA published the strings hardcoded in it - the password `jh4jnryw76ikmh`, the key `rhnr5m54pk65wertc`, an output path of `/var/tmp/.sess.zip` - and the marker files it leaves in its working directory: `.run`, `storage/fm`, `clientid`, `cp`. It also renames its child process to `crypto`.

One caution on where to look. CISA assesses the bot as stand-alone rather than installed on a compromised device, which most likely means it ran from actor infrastructure against EWS. The host sweep is still cheap, but the EWS request telemetry and the `natcloudservice[.]com` infrastructure are the more likely places to find it.

## Why

- **Magic-byte mismatch is a structural test, not a signature.** It survives the operator changing every filename, because the disagreement is between the extension and the bytes rather than between the name and a list.
- **Entropy alone is a trap; entropy as a tiebreaker is useful.** Minified JavaScript, web fonts, WebAssembly and optimised PNGs all score high. Testing the type first and ranking the failures by entropy keeps the false-positive rate manageable.
- **Classify the whole file, not the first line.** Legitimate JavaScript can begin with a byte-order mark or a copyright symbol, so a first-line printable check misfires; a whole-file text-versus-binary classification does not.
- **The size floor is free tuning.** Filtering above a hundred kilobytes removes most benign web-root churn before any other test runs.
- **Custom compression and encryption remove the archive-utility process event.** Where the Curlc4 bot compressed and encrypted in its own code, there is no `zip`, `rar` or `7z` execution for a process-centric detection to see; the hardcoded strings and marker files are what is left.
- **The retrieval is a second, independent chance.** A staged file has to be fetched. A single client pulling one enormous `.gif` shows up by ranking access-log rows on bytes-sent — the same reasoning [[M054]] applies to webshell responses.
- **The Microsoft side may be the only durable record.** CISA assesses the bot as stand-alone rather than installed, so a victim host may retain nothing. EWS request telemetry, the `/ews` paths and the `natcloudservice[.]com` infrastructure persist independently.
