false_positive_notes: |
  `rundll32.exe /sta` is legitimate but genuinely rare. It exists to host a COM object in a single-threaded apartment, and a handful of real components use it — some Control Panel and shell extension paths, certain printer and scanner drivers, a few Office and Windows Search helpers, and installer logic that needs an STA host. Expect a small, stable set of GUIDs to appear in any environment; enumerate them over 30 days and resolve each against `HKLM\SOFTWARE\Classes\CLSID\{GUID}` and `HKCR` to name the component, then allowlist by GUID rather than by process. The discriminators that matter are the hive and the target path. A legitimate STA-hosted component is registered machine-wide under `HKLM` by an installer running as SYSTEM, and its `InprocServer32` points into `%SystemRoot%\System32`, `%ProgramFiles%` or a signed vendor directory. The malicious pattern registers under `HKCU\Software\Classes` — which requires no elevation and silently takes precedence over `HKLM` for that user — and points at a DLL in `%AppData%`, `%LOCALAPPDATA%` or `%TEMP%`. A GUID resolving to a per-user registration backed by an unsigned DLL in a user-writable path is reportable on its own; a GUID that resolves to nothing at all, because the registration was deleted after execution, is stronger still. Note that the absence of a comma in the command line is the cheap filter but not sufficient alone: `rundll32` has other argument forms, so keep the `/sta` plus brace-delimited-GUID shape as the anchor.
notes: |
  Platform: Windows. Driven by Huntress, "DarkMe RAT: A VB6 APT Trojan Turned Conventional Infostealer" (September 2026), in which a three-stage VB6 loader chain registers a COM object and executes it as `rundll32.exe /sta {CFDC57BA-1705-45AF-BA10-EFC3D592982B}`, with `HKCU\Software\Classes\CLSID\{CFDC57BA-1705-45AF-BA10-EFC3D592982B}\InprocServer32` pointing at `%AppData%\ComponentsFolder\Coconout.dll` and a ProgID of `Coconout.Primary`. The report calls this invocation "central to DarkMe delivery; rare in legitimate software."
  Why the usual rundll32 rules miss this - Nearly every `rundll32` detection assumes the canonical form `rundll32.exe <path\to.dll>,<ExportName>` and keys on the DLL path, the export name, the comma, or a suspicious directory in the argument. The `/sta {CLSID}` form supplies none of those: there is no path, no export, no comma, and no file extension anywhere on the command line. The DLL is resolved indirectly through the registry at load time, so the only place the malicious path ever appears is a registry value written earlier and often deleted afterwards. This means a rule that looks for `rundll32` with a suspicious DLL argument is structurally incapable of seeing it, while a rule that looks for `rundll32` with *no* DLL argument catches it trivially — an inversion worth making explicit because it costs nothing to add.
  Sigma rule published with the source report - `title: DarkMe Rundll32 COM Invocation via STA` / `logsource: {product: windows, service: sysmon}` / `detection: selection: {EventID: 1, Image|endswith: 'rundll32.exe', CommandLine|contains: '/sta', CommandLine|regex: '/sta\s+\{[A-F0-9\-]{36}\}'}` / `filter_dll_path: {CommandLine|contains: ['.dll', ',']}` / `condition: selection and not filter_dll_path`. The negative filter is the load-bearing half — it is what converts a noisy `rundll32` rule into a precise one.
  Sysmon Event ID 1 / 4688 / DeviceProcessEvents - Core filter: `rundll32.exe` where the command line contains `/sta` (also check `-sta`) followed by a brace-delimited GUID, and does not contain `.dll` or a comma. Triage fields: `ProcessCommandLine`, `AccountName`, `InitiatingProcessFileName`, `InitiatingProcessCommandLine`, `ProcessIntegrityLevel`. Strong red flags: the parent is `explorer.exe` with a custom URL-protocol argument (DarkMe chains through a `Locked://` handler — see [[H345]]), or `wscript.exe`/`cscript.exe`, or a Run-key launch; the GUID does not resolve to any `HKLM` registration; the same GUID appears on multiple hosts, which turns a single-host oddity into a campaign; and `rundll32` subsequently making outbound network connections, which a genuine STA-hosted shell extension essentially never does.
  Sample KQL — rundll32 STA COM invocation without a DLL argument:
  `DeviceProcessEvents | where Timestamp > ago(30d) | where FileName =~ "rundll32.exe" | where ProcessCommandLine matches regex @"(?i)[-/]sta\s+\{[0-9A-Fa-f\-]{36}\}" | where not(ProcessCommandLine has ".dll") and not(ProcessCommandLine has ",") | extend clsid = extract(@"\{([0-9A-Fa-f\-]{36})\}", 1, ProcessCommandLine) | project Timestamp, DeviceName, AccountName, clsid, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId | order by Timestamp desc`
  Sysmon Event ID 13 / DeviceRegistryEvents — the registration, which is the real finding - Core filter: `Set` on a `TargetObject` matching `HKU\*\Software\Classes\CLSID\{*}\InprocServer32\(Default)` or `...\LocalServer32\(Default)`, and on `...\CLSID\{*}\ProgID`. Strong red flags: the written value is a path under `\AppData\`, `\Local\Temp\`, `\ProgramData\` or a user profile; the writing process is `reg.exe` invoked with `import` from `%AppData%` (DarkMe imported a dropped `.reg` template), or `wscript.exe`/`cscript.exe` running a `.wsf`; a `ThreadingModel` value of `Apartment` written alongside, which is what makes the `/sta` host necessary and therefore ties the registration to the execution; and the registration being *deleted* shortly after `rundll32` exits, which is anti-forensic cleanup and makes the registry event the only surviving evidence of the DLL path.
  Sample KQL — per-user COM registration pointing into a user-writable path:
  `DeviceRegistryEvents | where Timestamp > ago(30d) | where ActionType == "RegistryValueSet" | where RegistryKey has @"\Software\Classes\CLSID\" and RegistryKey has_any ("InprocServer32", "LocalServer32") | where RegistryValueData has_any (@"\AppData\", @"\Temp\", @"\ProgramData\", @"\Users\Public") | project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine | order by Timestamp desc`
  Sysmon Event ID 7 (ImageLoad) — closing the gap the command line leaves - Because the DLL path is absent from the command line, ImageLoad is the only process-time telemetry that names the file. Core filter: `rundll32.exe` loading an image from `\AppData\`, `\Temp\` or `\ProgramData\`, with `Signed` false or the signature untrusted. This is also how you recover the DLL for analysis when the registration has already been deleted, and it is worth confirming ImageLoad logging is enabled for `rundll32.exe` specifically, since many Sysmon configurations exclude it by volume.
  Triage pivot — resolve the GUID - For each GUID observed, query both hives on the affected host: `reg query "HKCU\Software\Classes\CLSID\{GUID}" /s` and the `HKLM` equivalent. A per-user-only registration is the finding. DarkMe's ProgID was `Coconout.Primary` and its stage-1 DLL exported `FillText`, so a matching YARA rule on the CLSID string, the ProgID and that export name is published with the source report for retro-hunting recovered DLLs.
  Cross-technique: [[H345]] covers the custom URL-protocol handler that invokes this `rundll32` command line in DarkMe's persistence chain, and [[H346]] the `.pif` delivery that starts it. Compare [[H235]] and [[H319]] for other `rundll32` abuse forms in HEARTH.

# H344

Huntress's September 2026 analysis of DarkMe — a VB6 trojan that began life in APT hands targeting traders and has since been repurposed as a conventional infostealer — documents a loader chain whose execution step is `rundll32.exe /sta {CFDC57BA-1705-45AF-BA10-EFC3D592982B}`. That is the whole command line. No DLL path, no export name, no comma, no file extension.

The `/sta` switch tells `rundll32` to host a COM object in a single-threaded apartment, taking a class identifier and resolving the implementing DLL through the registry rather than from the command line. DarkMe's second-stage loader writes `HKCU\Software\Classes\CLSID\{CFDC57BA-...}\InprocServer32` pointing at `%AppData%\ComponentsFolder\Coconout.dll`, registers the ProgID `Coconout.Primary`, and then invokes the CLSID. The per-user hive matters: `HKCU\Software\Classes` requires no elevation and takes precedence over the machine-wide registration for that user, so an unprivileged process can define a COM class and have the system load its DLL on demand.

The consequence for detection is a clean structural blind spot. Detections for `rundll32` abuse are almost universally built around the canonical `dllname,ExportName` form — they look for suspicious paths in the argument, odd export names, ordinal invocations, or the comma itself. None of those tokens exist here. The fix is almost free, and it is an inversion rather than an addition: alert on `rundll32` invoked with a GUID and *no* DLL argument. The Sigma rule Huntress published makes exactly that negative condition its filter, which is what turns an otherwise impossibly noisy process into a high-precision signal.

## Why

- This is a structural gap rather than an evasion of a specific rule, so it is likely unaddressed rather than merely under-tuned. A detection library built around `rundll32 <dll>,<export>` cannot match a command line containing neither, and the gap persists no matter how well that library is tuned.
- The inverted detection is cheap and precise. `rundll32 /sta {GUID}` with no DLL and no comma is rare enough in real environments that enumerating every occurrence over 30 days is tractable, and the resulting GUID allowlist is small and stable — which is what makes this a hunt with a genuinely low false positive rate rather than another noisy LOLBin query.
- The registry write is a higher-value finding than the process creation, and it is the only place the malicious path appears. Since the DLL is resolved indirectly, `HKCU\Software\Classes\CLSID\...\InprocServer32` pointing into `%AppData%` is both the clearest evidence and the artifact most likely to survive — or, if the loader deletes it, the Sysmon Event ID 13 record becomes the sole remaining proof of what was loaded.
- Per-user COM registration is an unprivileged capability with privileged-looking effects, which makes it broadly reusable beyond this family. Any unelevated process can define a class that the shell and other applications will load, so the same pattern serves both execution and hijacking of legitimate CLSIDs — and hunting the registration shape catches the whole class, not just DarkMe.
- The GUID is a free campaign pivot. A class identifier is chosen by the developer and reused across builds, so a single observed GUID can be swept across the fleet and back through historical telemetry to scope an intrusion without any file or network indicator.
