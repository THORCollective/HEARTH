# H255

Disabling macOS security software is hard and loud. XCSSET v4.0 does something quieter: it leaves XProtect running and simply stops it from ever learning anything new. A Perl process takes an exclusive file lock on the XProtect signature database and holds it, so updates cannot be written. The SoftwareUpdate configuration channel is set to false so the fetch path goes quiet. `CloudTelemetryService` is killed so the telemetry that would show any of this never leaves the host.

Nothing is deleted. Every security control still reports as enabled. It is defence impairment by freezing rather than by removal, and it is the kind of thing that does not appear on a posture dashboard.

## Why

- **Frozen looks identical to healthy on every dashboard you own.** MDM and compliance tooling check whether XProtect is *enabled*, not whether its signatures are *current*. A locked database passes that check indefinitely. The only way to see it is to compare signature versions across the fleet — which is why the staleness sweep is the highest-value query in this hunt and needs no EDR at all.
- **A file lock is a genuinely novel evasion primitive.** Killing a security process is well covered by existing detections; holding a lock on its database is not. There is no process termination, no unload, no SIP bypass, no file modification — just a handle that never closes. Most impair-defenses detections will not fire on any part of it.
- **Interpreters do not hold long-lived locks on security databases.** That is the discriminator. Legitimate readers of XPdb open, read and close, and they are Apple platform binaries. A `perl` process with a persistent open handle on the XProtect database has no benign explanation, and `lsof` answers the question in one command.
- **The three actions together tell you the intent.** Any one of them has a plausible admin story — MDM defers updates, admins kill hung daemons, scanners open files. Update-disable *and* signature-database lock *and* telemetry termination inside one session is a deliberate sequence to blind the host before the payload stages, and treating the conjunction as the alerting condition keeps the false-positive load survivable on a managed fleet.
