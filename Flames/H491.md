false_positive_notes: |
  Genuine image uploads and genuine software update checks both exist in volume. They separate cleanly on three tests. First, a real picture upload normally arrives as `multipart/form-data` with a form boundary, not as a raw image body; a raw PNG body under an `image/jpeg` declaration is already internally inconsistent. Second, a real update check is short-lived and periodic, whereas Rapid7's samples maintain a VPN session, so look for request pairs sustained against one destination over hours. Third, the initiating process for a legitimate upload is a browser or a known application; here it is an unsigned executable that is not in the authorised software inventory, which is the pivot into H490.

  Stock SoftEther VPN deployments are a different kind of false positive and a useful control: they will show POSTs to `/vpnsvc/connect.cgi` and `/vpnsvc/vpn.cgi` with the upstream GIF watermark. Finding those confirms the detection works and tells you which hosts legitimately run SoftEther.

  Organisations without TLS inspection cannot run the body-bytes leg at all. Rapid7 is explicit that this detection is available "If you have the ability to inspect TLS traffic in your organization". Where that is not available, run the URI-path and duration legs against proxy metadata and lean on the host artefacts in H490, which need no network visibility.

  Rapid7 cautions that the HTTP endpoints and the watermark "can be swapped out trivially" and that the NtMonitor branding is the easiest change for the actor to make next. Treat the literal paths and byte pattern as this-sample indicators with a short shelf life. The durable leg is the behavioural one - a long-lived HTTP session from an unsigned non-browser process to a single destination, followed by that host proxying internally.

  The claim that a successful handshake is followed by internal proxying is grounded in Rapid7's finding that the VPN is configured to cascade a remote network into the local one and that the infected host serves as an internal proxy mediating C2 access to other hosts on the network. Rapid7 does not publish a timeline for how soon the internal connections start, so treat the sequencing as expected rather than observed.
notes: |
  Network - decrypted HTTP request inspection (TLS-inspecting proxy, SSL-decrypting IDS, network sensor) - Core filter: HTTP `POST` where the URI path is `/update/picture.cgi` or `/update/alive.cgi`, or more generally any `POST` to a path beginning `/update/` and ending `.cgi`. Rapid7's detection guidance names the first of these as one of the most reliable detections available for this variant - a POST to `/update/picture.cgi` declaring `Content-Type` of `image/jpeg` with a request body whose leading bytes are `89 50 4e 47 0d 0a 1a 0a 00 00 00 0d 49 48 44 52`. Those sixteen bytes are the eight-byte PNG file signature followed by the four-byte length `00 00 00 0d` and the chunk type `IHDR`, so the body is a real PNG header under a JPEG declaration. Triage values are `destination IP`, `destination host header`, `URI path`, `method`, `request Content-Type`, `first 16 bytes of body`, `bytes sent`, `bytes received`, `session duration`, `client IP` and `JA3` or `JA4` fingerprint where available. Strong red flags: the `Content-Type` and the body magic disagree; the same client and destination pair repeats both `/update/alive.cgi` and `/update/picture.cgi`; the destination resolves into bulk-hosting space, with AS 20473 (The Constant Company, LLC) and its subsidiary Vultr the specific ranges Rapid7 associates with Webworm.

  A Suricata-style rule for the body leg, written against the decrypted stream, keyed on the URI and the first bytes of the body rather than on any hash. Example destination values below are illustrative and are not indicators.

      alert http any any -> any any (msg:"NtMonitor SoftEther handshake - PNG watermark POST to /update/picture.cgi"; flow:established,to_server; http.method; content:"POST"; http.uri; content:"/update/picture.cgi"; http.request_body; content:"|89 50 4e 47 0d 0a 1a 0a 00 00 00 0d 49 48 44 52|"; startswith; classtype:trojan-activity; sid:1000001; rev:1;)

  Run the same logic once without the `http.uri` constraint to catch the next endpoint rename, and once without the body constraint to catch the next watermark change. Either alone is noisier; together they bracket the change the actor is most likely to make.

  KQL - Defender XDR, long-lived outbound HTTP sessions from non-browser processes. Advanced hunting retains 30 days, so keep the lookback at `ago(30d)` or less. `DeviceNetworkEvents` carries no URI path, so this leg finds the session and the process, and the URI test comes from the proxy or sensor.

      DeviceNetworkEvents
      | where Timestamp > ago(30d)
      | where ActionType == "ConnectionSuccess"
      | where RemotePort in (80, 443, 8080, 8443, 5555)
      | where InitiatingProcessFileName !in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "iexplore.exe", "outlook.exe", "teams.exe", "ms-teams.exe", "onedrive.exe", "svchost.exe", "backgroundtaskhost.exe")
      | summarize FirstSeen = min(Timestamp), LastSeen = max(Timestamp), Conns = count(), Ports = make_set(RemotePort, 8)
          by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, RemoteIP
      | extend SessionSpan = LastSeen - FirstSeen
      | where SessionSpan > 2h and Conns >= 10
      | where not (InitiatingProcessFolderPath startswith @"C:\Program Files")
      | order by SessionSpan desc

  Pivot each surviving process path straight into H490's PE-metadata and `setting.conf` tests on the same device.

  Internal proxying leg (east-west flow records, internal firewall logs, `DeviceNetworkEvents` for internal destinations) - Core filter: for each device flagged above, the set of internal peers it connected to on `445`, `3389`, `5985`, `5986`, `389` and `636` in the 7 days after `FirstSeen`, minus the set it connected to in the 30 days before. A host that gains new internal peers it never previously contacted, in the window that opens with its first external handshake, matches the cascade behaviour Rapid7 describes. A time-bounded join is required here - correlating on `DeviceId` alone across a long lookback will pair unrelated days.

      let flagged = datatable(DeviceId: string, FirstSeen: datetime) [ "REPLACE-WITH-DEVICEID", datetime(2026-11-01 00:00:00) ];
      let before =
          DeviceNetworkEvents
          | where Timestamp between (ago(37d) .. ago(7d))
          | where RemotePort in (445, 3389, 5985, 5986, 389, 636)
          | summarize OldPeers = make_set(RemoteIP, 1000) by DeviceId;
      let after =
          DeviceNetworkEvents
          | where Timestamp > ago(7d)
          | where RemotePort in (445, 3389, 5985, 5986, 389, 636)
          | summarize NewPeers = make_set(RemoteIP, 1000), Attempts = count() by DeviceId, RemoteIP, RemotePort;
      flagged
      | join kind=inner after on DeviceId
      | join kind=leftouter before on DeviceId
      | where isempty(OldPeers) or RemoteIP !in (OldPeers)
      | project DeviceId, RemoteIP, RemotePort, Attempts
      | order by Attempts desc

  Replace the `flagged` datatable with the device IDs and first-seen times produced by the session query above rather than running it unconstrained.

  Scope note: this is the network half of the NtMonitor problem; H490 covers the on-host PE, service, configuration and firewall-rule artefacts, and the two legs corroborate each other. H168 covers Webworm's ChainWorm and WormSocket multi-hop proxy implants, which chain `ws` to `wss` to `http` to `https` upstream hops and are identified by connection duration to cloud VPS ASNs rather than by a watermarked HTTP handshake to a renamed endpoint. H360 and H397 cover tunnels carried inside a compromised web application's own request stream, which is a different position in the network - the appliance itself rather than a Windows endpoint running a bridge.

# H491

Rapid7's November 19, 2026 analysis of a custom SoftEther VPN Bridge build attributed to the China-aligned APT Webworm documents two protocol-level changes that together make the tool's traffic unrecognisable to anything keyed on stock SoftEther. The HTTP endpoints defined in SoftEther's Mayaqua `Network.h` — `/vpnsvc/vpn.cgi` and `/vpnsvc/connect.cgi` — are replaced with `/update/alive.cgi` and `/update/picture.cgi`. The handshake watermark, which a client sends to `HTTP_VPN_TARGET2` to prove it speaks the VPN protocol and without which the server returns a decoy HTTP response, is replaced with a custom byte pattern. Rapid7 describes that pattern as a truncated PNG file showing the Windows logo.

Both changes are deliberate and symmetrical: stock SoftEther clients and servers cannot handshake with this build, and this build's peers cannot be fingerprinted with the well-known stock GIF watermark. The side effect the actor accepted is a visible inconsistency on the wire — a request that declares one image type and carries another, to a path that looks like a software update check, sustained for the life of a VPN session rather than the few seconds an update check takes.

This hunt pairs that wire signature with what the session is actually for. In every case Rapid7 examined, the VPN was configured to cascade a remote network into the local one, making the infected host an internal proxy that mediates the actor's access to its neighbours.

## Why

- Rapid7 names this the most reliable detection currently deployable against the variant, for defenders who can inspect TLS. It does not depend on a hash, a domain or a file path, all of which the actor controls cheaply.
- The declared content type and the actual body bytes disagree, and that disagreement is structural rather than cosmetic. The protocol requires the watermark in the handshake body; the decoy behaviour requires the request to look like ordinary web traffic. Satisfying both is what produces a PNG header inside an `image/jpeg` POST.
- Webworm's target set makes the second leg worth running on its own. The group's activity focuses on government organisations, especially in Europe, and a bridged network is a persistent lateral-movement channel, not just a C2 path. A host that suddenly acquires internal peers it has never contacted is detectable without any TLS inspection at all.
- Rapid7 expects the endpoints and watermark to change next, and recommends defenders familiarise themselves with intrinsic SoftEther VPN behaviour to stay ahead of the next revision. That is why the queries here are written to be run with each constraint relaxed in turn, and why B073 baselines normal tunnelling behaviour in the estate alongside them.
