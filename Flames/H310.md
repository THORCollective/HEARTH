# H310

The second Toy Ghouls implant documented by Securelist, `matrix-bird-agent`, replaces the public MQTT broker of its sibling with something subtler: a Matrix homeserver. Matrix is a federated, open chat protocol, and the implant participates in it as a client would — it connects to `meet.element[.]tw`, takes commands from an operator account called `panel-bot`, and reports back using custom room event types (`m.bird.status`, `m.bird.metrics`, `m.bird.cmd_response`). The transport is HTTPS to a hostname whose label borrows a mainstream collaboration brand, which means this variant surrenders none of the legitimacy of the MQTT version while giving up its one weakness — an unusual destination port. There is nothing anomalous left at the network layer except the fact that a Windows *service* is holding a chat session. That is the hunt. Host-side, the two variants are near-identical twins: a service binary under `%PROGRAMDATA%`, a `config.toml` on first run, and a ChaCha20-Poly1305 configuration sealed into the registry under a key bound to the machine's own `MachineGuid`.

## Why

- **Bidirectional legitimate-service C2 removes the beacon.** Classic C2 detection leans on a client repeatedly calling a destination that exists only to receive it. Here the destination is a real chat server serving real protocol traffic, and the implant's polling is indistinguishable in shape from a chat client keeping a room in sync — because that is precisely what it is doing. Volumetric beacon-interval analysis is the wrong instrument; process identity is the right one.
- **The brand-lookalike homeserver defeats allowlist-by-substring.** `meet.element[.]tw` reads as Element infrastructure and is not. Any control that permits collaboration tooling by matching vendor names in hostnames will pass this traffic, which makes the specific-homeserver allowlist — rather than the brand allowlist — the only defensible configuration, and this hunt is what surfaces the gap.
- **A Windows service has no reason to hold a chat session.** The implant's one irreducible contradiction is that `services.exe` started a process that behaves like an interactive collaboration client. No legitimate deployment of Element or any other Matrix client runs as a non-interactive system service, so the join between service parentage and client-server API traffic is close to a zero-false-positive condition.
- **Custom event types are a content-level fingerprint that survives infrastructure rotation.** The `m.bird.*` namespace is invented and sits outside the documented Matrix event vocabulary. Where an organisation runs its own homeserver — or can decrypt proxy traffic — enumerating distinct event types is cheap, the legitimate vocabulary is small, and an unknown custom namespace is a direct hit regardless of which homeserver or operator account the campaign moves to next.
