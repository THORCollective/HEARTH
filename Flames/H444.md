false_positive_notes: |
  Endpoint: most legitimate software reads only one credential family.
  - Expected multi-family readers: whole-home backup agents (Time Machine `backupd`, Backblaze, Arq), EDR/AV and DLP scanners, Spotlight indexing (`mds`, `mdworker_shared`), and MDM agents. Allowlist them by Apple-verified code-signing team ID and path, never by process name alone.
  - Signed developer tooling can read two families legitimately. The VS Code extension host running cloud toolkits or Remote-SSH can read `~/.aws/sso/cache` and `~/.ssh` together. `aws-vault`, `granted`, `saml2aws`, and `leapp` can read AWS caches plus Keychain. None of these read browser cookie databases or dump the Keychain, so when the parent is a signed developer tool, require browser stores or Keychain extraction as one of the families.
  - Python cookie libraries (`yt-dlp --cookies-from-browser`, `browser_cookie3`, `pycookiecheat`) and browser-test frameworks that use real profiles (Playwright, Puppeteer, Selenium) can read cookies and the `Chrome Safe Storage` item. Separate these by repo ownership and by whether the same tree also touched SSH or cloud caches and made an outbound upload.
  - IT and MDM self-service scripts can use `osascript` dialogs. Allowlist those by signed parent and known script path.
  
  Cloud: IP drift is normal. VPN reconnects, home/office roaming, tethering, and secure-web-gateway egress pools all rotate addresses. Normalize to ASN and corporate egress ranges, then require all three of the following:
  (a) an ASN not seen for that user in IdP or AWS logs in 30 days
  (b) no IdP sign-in from that IP
  (c) at least one sensitive API from the list above
  Exclude calls made by AWS services on the user's behalf (an invoking service is recorded, or the source is an AWS service hostname). Also exclude AWS CloudShell sessions, which originate from AWS address space; label them rather than suppress them globally. CI/CD should not use human Identity Center sessions; if it does, treat that as a finding to fix, not an allowlist entry.
notes: |
  macOS EDR process telemetry (Endpoint Security exec events) - Core filter: process name `node`, `python3`, or `python`, or any unsigned/ad-hoc-signed binary, whose ancestry includes `npm`, `npx`, `pip`, `Code Helper (Plugin)`, or a shell started inside a recently cloned or downloaded repo (`~/Downloads/`, `~/Desktop/`, or a project folder created in the last 7 days), and that spawns `osascript`, `curl`, `security`, `zip`, or `ditto`. Triage values: `process command line`, `parent process command line`, `process path`, `code signing team ID`, `signing status`, `working directory`, `user`. Pivot: walk to the root of the tree and inspect the repo for `.vscode/tasks.json` with `"runOn": "folderOpen"`, `package.json` `preinstall`/`postinstall` hooks, or a `requirements.txt`/`setup.py` that pulls an unfamiliar package. Strong red flags: `node -e` or `python3 -c` with long base64 or `eval` strings; `osascript -e` containing `display dialog` with `hidden answer`; `security find-generic-password` targeting `Chrome Safe Storage` from a non-browser process.
  macOS EDR file-open telemetry (Endpoint Security open events or a sensitive-path watchlist) - Core filter: one process tree (same root process) opening paths from 2 or more of these families within `10 minutes`:
  - Cloud/CLI tokens: `~/.aws/sso/cache/`, `~/.aws/cli/cache/`, `~/.aws/credentials`, `~/.kube/config`, `~/.config/gcloud/`, `~/.config/gh/hosts.yml`.
  - SSH private keys: `~/.ssh/id_*` (exclude `*.pub`, `known_hosts`, `config`).
  - Browser stores: `~/Library/Application Support/Google/Chrome/*/Cookies` and `Login Data`, plus Brave/Edge equivalents and Firefox `cookies.sqlite`.
  - Keychain: `~/Library/Keychains/login.keychain-db` opened by a non-Apple process, or exec of `security` with `find-generic-password`, `find-internet-password`, or `dump-keychain`.
  Triage values: `file path`, `process path`, `process command line`, `parent process command line`, `code signing team ID`, count of distinct credential families, first and last access time. Correlation: if your EDR does not record reads in home directories, fall back to exec telemetry for `cp`, `ditto`, `tar`, `zip`, or `cat` whose command line names these paths. Strong red flags: a browser `Cookies` database read by a non-browser process; the sweep followed within seconds by a new archive written to `/tmp/` or `$TMPDIR`.
  macOS EDR network and file-write telemetry (staging and egress) - Core filter: `curl` or the interpreter itself opening an outbound connection within `5 minutes` of the sweep, especially `curl -F`, `curl -X POST`, or `--data-binary @` referencing a `.zip` or `.tar.gz` under `/tmp/`. Triage values: `destination domain`, `destination IP address`, `bytes sent`, `process command line`, staged archive `file path`. Pivot: the destination's first-seen date across the fleet, its registration age, and any other host contacting it. Strong red flags: an upload to a raw IP, a newly registered domain, or a paste/file-sharing service, from a developer Mac with no prior history to that destination.
  AWS CloudTrail, IAM Identity Center issuance (logged in the Identity Center home region) - Core filter: event source `sso.amazonaws.com` with `GetRoleCredentials`, `ListAccounts`, and `ListAccountRoles`, plus `sso-oauth.amazonaws.com` `CreateToken`, for the user mapped to the flagged Mac. Match the IdP username/email to the role session name under `AWSReservedSSO_<PermissionSet>_*`. Triage values: `source IP address`, `ASN`, `user agent`, `role session name`, `account ID`, `role name`, event time. Correlation: compare each issuance IP to the IdP sign-in IP for the IAM Identity Center application and to the Mac's known egress. One token calling `GetRoleCredentials` across many account/role pairs within minutes from a new ASN is enumeration. Strong red flags: a `CreateToken` refresh or `GetRoleCredentials` call from a hosting or VPN ASN with no matching IdP sign-in; a `user agent` that departs from the developer's usual `aws-cli/2` or IDE toolkit strings.
  AWS CloudTrail, post-compromise resource access - Core filter: calls by an `ASIA` temporary `access key ID` under an `AWSReservedSSO_` session (or an IAM user's session token) to any of: `GetSecretValue`; `GetParameter`/`GetParameters` with decryption; KMS `Sign` or `Decrypt`; `AssumeRole` into deploy or signer roles; S3 `PutObject` to front-end or artifact buckets (requires S3 data events); `CreateVirtualMFADevice`/`EnableMFADevice`. Triage values: `access key ID`, `source IP address`, `ASN`, `user agent`, `resource ARN`, `request parameters`, `error code`. Correlation: group by `access key ID`. One temporary key seen from 2 or more source IPs or ASNs indicates replay. So does a key used from an IP different from the `GetRoleCredentials` call that issued it for that role session name. Keep a 30-day baseline of which secrets, keys, and buckets each role session name touches, and confirm the trail does not exclude KMS events. Strong red flags: a first-ever `Sign` against a signing key by a human SSO session; `PutObject` on JavaScript served to transaction signers (the Bybit pattern); MFA device registration from the new IP; bursts of `AccessDenied` while probing.
  IdP sign-in logs (Okta System Log or Entra ID sign-in logs) - Core filter: SSO sign-ins to the AWS IAM Identity Center application for the flagged user over the prior 30 days. Triage values: `source IP address`, `user agent`, managed-device state, `session ID`, MFA result. Correlation: legitimate Identity Center sessions start with an IdP sign-in from the same IP or from corporate egress. Replayed cached tokens produce AWS activity from an IP that never appears in the IdP for that user. Strong red flags: AWS activity from an IP absent from IdP history within hours of an endpoint hit from the sections above, especially when the user recently had recruiter contact, a take-home test, or an interview that needed a downloaded plugin.

# H444

On October 29, 2026, roughly $6.4 billion in cryptocurrency left Binance hot wallets across 10 blockchains in about 20 minutes. Chainalysis and TRM Labs attribute the activity to the DPRK cluster TraderTraitor. Binance said its initial investigation suggested a compromised laptop and that it later found additional points of breach. It reported no evidence of a wallet private key leak. TRM assesses that the attacker gained the ability to make the hot-wallet signing system sign whatever it was asked to sign.

Jamf Threat Labs has tracked DPRK activity for several years and describes a consistent pattern against developers. The lure is almost always a job: a recruiter message, a take-home coding exercise, an assessment portal, or a video interview that needs a "plugin" to fix audio. Delivery uses tools developers already trust: GitHub repositories and npm/PyPI packages. Payloads run under Node and Python. The first action on the host is a credential sweep of browser sessions, SSH keys, cloud tokens, and Keychain items. The same scripts and binaries show up at unrelated organizations.

The February 2025 Bybit theft followed the same path from a laptop into the cloud. A Safe{Wallet} developer's macOS workstation was compromised on February 4. The next day, that developer's AWS session tokens were used to access Safe{Wallet}'s AWS environment, getting around MFA. The attacker also tried to register their own virtual MFA device on the developer's IAM user. CISA AA22-108A documents earlier TraderTraitor tradecraft: recruitment-themed lures aimed at DevOps and system administration staff that deliver trojanized Node.js applications.

This hunt ignores lure artifacts, which rotate per target, and focuses on two chokepoints the actor cannot avoid. First, on the Mac, one process tree rooted in an interpreter or unsigned binary reads several unrelated credential stores in a short window and then stages or uploads them. Second, in AWS, the developer's Identity Center session is used from infrastructure with no matching IdP sign-in, against secrets, signing, role-assumption, or deployment APIs. Each half can be hunted on its own. Together they give a high-confidence, user-scoped story.

## Why

- Binance's October 29, 2026 loss (roughly $6.4 billion across 10 chains in about 20 minutes, attributed to TraderTraitor) may trace back to a compromised laptop and a signing system that was made to sign on demand. Bybit 2025 followed the same path from a developer's Mac to a replayed AWS session. At that cash-out speed, the gap between the credential sweep and cloud misuse is the realistic place to break the chain.
- Lures, repos, packages, and C2 change for each target. The payload still has to read the same fixed OS locations (`~/.aws/sso/cache`, `~/.ssh/id_*`, browser `Cookies`, `login.keychain-db`), and the stolen session still has to be used from infrastructure where the developer never signed in. The actor cannot rename either chokepoint, so the hunt survives indicator rotation.
- Both halves show up in standard telemetry. macOS EDR records exec lineage, code-signing state, and sensitive-path file opens. CloudTrail records `GetRoleCredentials` issuance and every later call with its temporary access key ID, source IP, and user agent. Replay can be shown by joining key, IP, and role session name with the IdP sign-in history.
- False positives stay manageable because legitimate tools each read one credential family. The hunt requires two or more families from one interpreter-rooted or unsigned tree within 10 minutes, with cookies or Keychain among them, followed by a sensitive API call from a new ASN. That leaves a small queue that can be triaged one user at a time.
