false_positive_notes: |
  Legitimate Remote-SSH extensions in VS Code and Cursor start ssh with -L, -D or a ProxyCommand toward hosts the user configured. They write ~/.ssh/known_hosts and ~/.ssh/config but never edit the local authorized_keys or enable the local sshd, so editor-attributed authorized_keys writes and SSH-service enablement have almost no legitimate baseline. Developers do use -R for port sharing, but the remote forward usually targets an app port such as localhost:3000 or 8080 from an interactive terminal. Keep the filter tied to a local target of port 22 and a non-terminal ancestor. Config management (Ansible, Chef, Puppet, Salt), MDM scripts (Jamf, Intune, Kandji) and cloud-init write authorized_keys or turn on Remote Login for IT support. # H443

On October 29, 2026, Cursor reported that tampered builds of the AI vendor's own coding-assistant extension (versions 2.1.312 and 2.1.313) were served from the Cursor extension marketplace from about 02:27 to 13:35 PDT. StepSecurity estimates the build reached up to 5,000 Cursor users. Microsoft Threat Intelligence analyzed the injected JavaScript loader on October 30. The loader runs when the extension module loads, before the legitimate bundle, and suppresses its own errors so the extension keeps working. It has no install or postinstall script.

The loader takes these steps:
- Collects host details: hostname, user, OS, git global user.email, public IP from ifconfig.me and api.ipify.org, and the names (not the values) of up to 40 environment variables matching KEY/TOKEN/SECRET/PASS/AWS/GCP. It sends them over plain HTTP.
- Appends an ed25519 key with the comment svc-telemetry to ~/.ssh/authorized_keys. It writes with Node file APIs, not a shell command.
- Tries to enable the local SSH service: on macOS via `sudo -n systemsetup -setremotelogin on`, on Linux by enabling sshd, and on Windows by installing OpenSSH Server.
- Decodes a second embedded private key into a hidden `$TMPDIR/.stk_*` file and loops `ssh -N -R '*:0:localhost:22'` to the operator's server with host-key checking disabled, ExitOnForwardFailure and 30-second keepalives. It reconnects about every 60 seconds and uses autossh when present.
- Installs per-OS persistence: macOS user LaunchAgent com.apple.sysmond.plist (RunAtLoad, KeepAlive) running ~/.config/.smt; Linux user crontab @reboot entry; Windows scheduled task SysMon set to run as SYSTEM at startup, with a Startup-folder sysmon.cmd fallback.

Microsoft notes that the key and persistence may be written even when the tunnel fails. Removing or updating the extension does not remove them. Phorion found a macOS logic bug that limits SSH enablement when Remote Login was not already on, so hosts that already had Remote Login or passwordless sudo are at higher risk. The case-specific strings and infrastructure can change in the next variant. The behavior that stays the same is an editor extension host making a workstation reachable from outside through its own sshd.

## Why

- The October 29, 2026 Cursor marketplace incident served trojanized builds for about 11 hours to up to 5,000 developers. The planted key, LaunchAgent, crontab entry and SysMon task persist after the extension is removed or updated, so exposed workstations can still be reachable now, and developer machines hold git, cloud and SSH credentials.
- The behavior forces a fixed path. Whatever key comment, server IP or file names the next variant uses, an implant that wants inbound access to a NAT'd laptop must authorize a key sshd will accept, get sshd running, and reverse-forward to local port 22. Each step is a separate observable event, so rotating indicators does not break the hunt.
- The telemetry exists in standard tooling, but only if file events are used. The authorized_keys append happens through Node file APIs inside the editor helper process, so command-line rules miss it, while EDR file events with acting-process attribution capture it. The ssh -R command line, launchd, cron and Task Scheduler creation events, and loopback publickey logins in sshd logs are default OS or EDR records.
- False positives are controllable by lineage. Legitimate editor SSH features forward outward with -L or -D and never modify the local authorized_keys or enable sshd, and legitimate -R use targets app ports from an interactive shell. Requiring an editor or startup-item ancestor plus a local target of port 22 leaves a near-empty baseline.
