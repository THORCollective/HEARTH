false_positive_notes: |
  `MpCmdRun.exe` is a legitimate administrative tool and runs routinely in managed estates. Signature updates, on-demand scans, diagnostic log collection via `-GetFiles`, and scripted remediation all invoke it, frequently from management agents and scheduled tasks. The abuse case is narrow by comparison, so filter on the argument rather than the binary.

  The `-DownloadFile` argument itself has legitimate uses, including Microsoft's own documented support workflows and some vendor diagnostic scripts. It is rare in most estates but not unheard of, so treat it as high-signal rather than conclusive, and resolve the destination URL before judging.

  `certutil` with `-urlcache` is long-established tradecraft and correspondingly well covered by most detection stacks, but it also has genuine certificate-management uses and appears in some enterprise scripts and installers. The parent process is the discriminator - a management agent or a logon script is plausible, a shortcut file or Explorer is not.

  LNK files are created constantly and legitimately. Installers create them, users pin and copy them, and Explorer generates them for recent items. The hunt is not LNK creation but the combination of a shortcut whose embedded command line invokes a download LOLBin, which requires parsing the shortcut target rather than watching for the file.

  `RuntimeBroker.exe` is a real and very common Windows binary, which is exactly why it was chosen. Talos states the payload is saved as `RuntimeBroker.exe` to blend into process inventories. So the filename alone is useless as an indicator - the discriminator is a `RuntimeBroker.exe` outside `C:\Windows\System32`, unsigned, or with an unexpected parent. A naive filename search will return every host in the estate.

  The build-machine identifier `win-8oa3ccqae4d` that Talos recovered from both shortcuts is a correlation artefact for intelligence purposes, not a detection input - it appears in LNK metadata on recovered samples, not in endpoint telemetry.

  Talos is explicit that in this campaign it has not observed how the actor delivers these malicious initial vector files to victims' machines. Email, removable media and web download are all plausible, but the report does not attest any of them, so do not scope the hunt to one delivery channel.
notes: |
  Leg one, the Defender tool as downloader (Sysmon 1 or 4688) - Core filter: `MpCmdRun.exe` with a download argument. This is the sharpest query in the hunt because the argument is rare and the binary is otherwise trusted.

      DeviceProcessEvents
      | where Timestamp > ago(30d)
      | where FileName =~ "MpCmdRun.exe"
      | where ProcessCommandLine has "-DownloadFile" or ProcessCommandLine has "-url"
      | project Timestamp, DeviceName, ProcessCommandLine, FolderPath,
                InitiatingProcessFileName, InitiatingProcessCommandLine,
                InitiatingProcessParentFileName, AccountName
      | order by Timestamp desc

  Thirty days is the whole Defender advanced hunting retention. Rank on the initiating process: `explorer.exe` is the shortcut-click signature and the strongest finding; `cmd.exe` or `powershell.exe` under a user context is next; a management agent or `svchost.exe` is probably administrative. Extract the destination URL and the `-path` target from the command line - the latter is where the payload landed and is the pivot into leg three. Note also that the allowlisting argument Talos makes cuts both ways for a hunter: because `MpCmdRun.exe` is a signed Microsoft binary, this download will not appear in application-control denials, so WDAC and AppLocker logs will be silent and process telemetry is the only place it shows.

  Leg two, the certutil variant. Core filter: `certutil` with `-urlcache` and a URL, or with `-f` and a remote path.

      Sysmon Event ID 1 where
        Image ends with "\certutil.exe"
        and CommandLine contains "urlcache"
        and (CommandLine contains "http" or CommandLine contains "-f")

  Field names matter - Sysmon exposes `Image`, `ParentImage` and `IntegrityLevel`; Windows Security 4688 exposes `New_Process_Name` and `Creator_Process_Name` and carries no Sysmon-style integrity field, so a 4688 query written with Sysmon field names returns nothing and returns it silently. This leg is well-trodden ground and most estates already alert on it; it is included because the two shortcuts are siblings and finding one should prompt a search for the other.

  Leg three, where the payload lands (DeviceFileEvents or Sysmon 11). Hunt a `RuntimeBroker.exe` created anywhere other than `C:\Windows\System32`, which is where the genuine binary lives. The real one is a signed Windows component; a copy written into a user profile, `AppData`, `ProgramData` or a temporary directory by `MpCmdRun.exe` is the finding. `DeviceFileEvents` records creates, modifies, renames and deletes but no reads, which is the right shape here - the question is who wrote the file. Pair the file hash with the destination URL from leg one.

  Leg four, the shortcut itself. Parsing LNK targets is what turns this from a process hunt into an early-stage one. Collect `.lnk` files from download directories, mail attachment staging paths and removable media, and parse the embedded command line, icon location and working directory. The two patterns Talos describes are a shortcut whose icon is borrowed from a legitimate system binary or from Microsoft Edge's PDF icon, and a double-extension filename so the shortcut reads as a document. In both cases the embedded target is a LOLBin with a download argument and a minimised window. Talos also recovered the actor's LNK generation script from the exposed staging directory and states it accepts a payload URL and icon type - PDF, Word, or Windows Update - and generates a COM-based LNK with spoofed and hidden execution, which means these three icon themes are the expected variants rather than the only possible ones.

  Leg five, the two other initial access vectors from the same report, worth running alongside since they are alternative first stages for the same implant. An HTA dropper executed by `mshta.exe`, whose JavaScript uses `MSXML2.ServerXMLHTTP` to fetch the payload as raw binary and `ADODB.Stream` to write it to `%TEMP%\s.exe`, then executes it with the window hidden. And a weaponised MSBuild project file named `dl.xml` carrying an inline C# `CodeTaskFactory` task, which when executed via `msbuild.exe` compiles and executes the C# in memory so no intermediate executable is written to disk for the downloader stage. That second one has a distinctive network-side tell: Talos states the download uses a spoofed `Microsoft BITS/7.8` User-Agent string, impersonating the Background Intelligent Transfer Service used by Windows Update, Defender and many third-party updaters, so the request blends in with routine background download traffic. A `Microsoft BITS/7.8` user agent on a connection that did not originate from the BITS service itself is a proxy-log hunt worth running independently of everything above.

  Infrastructure context for scoping. Talos found the actor hosted the malicious files on a server at `41[.]216[.]188[.]11`, running a Flask-based file delivery service on port 8000 with resumable byte-range download support. Because of what Talos describes as the actor's operational security failure, the server's root folder was exposed to the internet, revealing the toolset and the port layout - 8000 for the Flask file drop serving `Payload.exe`, `MyApp2.exe` and HTA files, 5173 for Overlord RAT WebSocket C2 serving `Ovl.exe` and `Client.exe`, and 5656 and 5959 for Python stealer TCP C2. Sweep proxy and firewall logs for that address and for outbound connections to those ports.

  Scope note on existing coverage. A grep of every hunt body for `MpCmdRun` returns nothing - no existing HEARTH hunt covers Defender's own command-line utility as a download mechanism. `certutil` and LNK abuse are both represented in the corpus on other ground, and MSBuild appears in seven files, which is why leg five is positioned as a pivot rather than as this hunt's subject. H519 and H520 cover the persistence and anti-removal behaviour of the implant this chain delivers.

# H521

An application allowlist asks one question: is this binary trusted? `MpCmdRun.exe` is Microsoft Defender's own command-line utility, signed by Microsoft, present on every Windows installation. It passes.

It also takes a `-DownloadFile` argument.

Talos found UAT-12643 using exactly that, wrapped in a Windows shortcut wearing the standard document icon so it reads as a PDF in Explorer. Click it, and Defender's own tool fetches the payload — which, as Talos points out, passes application allowlisting controls transparently because of who signed the downloader. The file is saved as `RuntimeBroker.exe`, a real Windows binary name chosen to blend into process inventories, and the console window is minimised so nothing visible happens.

A sibling shortcut does the same job with `certutil -urlcache -f`, hiding behind a double extension and Microsoft Edge's PDF icon — a download, in Talos's description, operating under the guise of a certificate cache update. Both were built on the same machine, `win-8oa3ccqae4d`, and Talos recovered the actor's LNK builder from an exposed staging directory: give it a payload URL and pick an icon, PDF, Word or Windows Update.

The awkward part for defenders is that the allowlisting bypass also silences the logs you would check. WDAC and AppLocker have nothing to deny, so there is no denial to review. The argument on the command line is the entire detection.

## Why

- `-DownloadFile` is rare and `MpCmdRun.exe` is common, which is the ideal shape for a hunt. Filtering a very noisy binary by a very quiet argument gives a short, reviewable result set in most estates, and almost every hit is either a support workflow or an intrusion.
- Application control cannot see this at all. The binary is signed by Microsoft and legitimately installed, so allowlisting denials never fire and the usual "what got blocked" review is blind to it. Process command-line telemetry is the only place the behaviour exists.
- The payload filename is deliberately useless as an indicator, which tells you what to hunt instead. `RuntimeBroker.exe` exists on every Windows host, so the discriminator is location and writer — a copy outside `System32` created by Defender's own tool is unambiguous.
- Parsing LNK targets catches this before anything executes. The shortcut carries the whole attack in its embedded command line, so collecting and parsing `.lnk` files from download and attachment paths finds the lure rather than the aftermath.
- The builder tells you the variant space in advance. Because the generation script takes a URL and an icon type of PDF, Word or Windows Update, the three disguises are known up front — which makes an icon-and-target mismatch a durable rule rather than a one-sample observation.
- It is the front door to a serious implant. This chain delivers a Go RAT with 35 commands, a reverse SOCKS tunnel into the internal network, recovery-environment persistence that survives a reset, and a self-set critical-process flag that bluescreens the host if killed. Catching the download stage is worth far more than catching any later one.
