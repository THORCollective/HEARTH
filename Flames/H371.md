false_positive_notes: |
  Each primitive here is individually common and the combination is not. `Get-Date` is one of the most-used cmdlets in existence - it appears in essentially every logging, reporting, backup, maintenance and deployment script ever written, so time queries alone carry no signal whatsoever and must never be the filter on their own. `Stop-Process` and `taskkill` are likewise routine in administrative tooling. Legitimate time-gated automation is real and widespread - maintenance windows, backup schedules, after-hours patching, overnight batch jobs and license-reclamation scripts all branch on the hour. What has no good explanation is the specific join - a script that queries local time *and* terminates an interactive diagnostic tool *and* does so only during hours when nobody is expected to be at the console. Scope on that conjunction and the noise collapses. A second real false-positive class is kiosk, VDI, exam-proctoring, classroom-management and endpoint-lockdown software, which deliberately blocks or closes Task Manager as a policy control; these are identifiable by vendor, are usually deployed via policy rather than a loose script in `%TEMP%`, and typically block it outright rather than waiting an hour. Group Policy's own "Remove Task Manager" setting is the sanctioned way to do this and produces no process-termination events at all, which is a useful contrast - a sanctioned control prevents, whereas this script reacts. Third, `taskmgr.exe` genuinely does exit often and for ordinary reasons, so the termination leg needs the *cause* from Event ID 5 or Defender telemetry rather than the mere absence of the process. Finally note the misspelling - `Taskgmr.ps1` transposes two letters of `Taskmgr`, so a name-based search must be fuzzy or it will miss both this sample and the next one.

  What the script actually does, and why it is the most interesting artefact in the intrusion. Huntress describes "what appears to be an AI-assisted PowerShell script that monitors the Windows Task Manager and shuts it down if it remains open for too long in the middle of the night," and specifies - "the script also kills Task Manager at a specific time (18:00) and if it was left open for more than one hour during overnight hours.   Core filter, the script leg. PowerShell script-block logging (4104) where a block contains a time query (`Get-Date`, `[DateTime]::Now`, `(Get-Date).Hour`, `Get-CimInstance Win32_OperatingSystem` for uptime) in the same block as a termination primitive (`Stop-Process`, `taskkill`, `Get-Process` piped to `Stop-Process`, `.Kill()`) and a reference to a diagnostic or monitoring tool (`taskmgr`, `perfmon`, `resmon`, `procexp`, `procmon`, `taskmgr.exe`). Triage fields - the full script block, the invoking parent process, the account, the file path the script was run from, and the hours the logic branches on.
  Sample KQL - time query joined to process termination in one script block.
  `DeviceEvents | where Timestamp > ago(30d) | where ActionType == "PowerShellCommand" | extend Script = tostring(AdditionalFields.Command) | where Script has_any ("Get-Date", "[DateTime]::Now", "Win32_OperatingSystem") | where Script has_any ("Stop-Process", "taskkill", ".Kill()") | where Script has_any ("taskmgr", "perfmon", "resmon", "procexp", "procmon") | project Timestamp, DeviceName, InitiatingProcessFileName, InitiatingProcessParentFileName, AccountName, Script`
  Sample KQL - the effect rather than the cause, repeated short-lived Task Manager sessions.
  `DeviceProcessEvents | where Timestamp > ago(30d) | where FileName =~ "taskmgr.exe" | summarize Launches = count(), Hours = make_set(bin(Timestamp % 1d, 1h)) by DeviceName, bin(Timestamp, 1d) | where Launches >= 5 | order by Launches desc`

Huntress recommends restricting AhsayCBS management interface web access to trusted IPs or behind a VPN, and advises that any host showing these IOCs be fully re-imaged from a trusted backup, "as attackers have been able to hide secondary backdoors for extended persistence." # H371

Of everything in this intrusion — the authentication bypass, the SYSTEM-level RCE, the JSP webshell, the Monero miner wearing Microsoft Edge's name — the detail worth building a hunt on is a PowerShell script that checks the time.

Huntress describes it as monitoring Task Manager and shutting it down "if it remains open for too long in the middle of the night," plus killing it outright at 18:00. The script is named `Taskgmr.ps1`, which transposes two letters of `Taskmgr`. And one implementation choice gives the whole thing away: it used the endpoint's local `Get-Date` rather than UTC.

Think about why that is strange. If you are writing scheduled automation across a server estate, UTC is the correct choice and local time is the unreliable one — time zones differ, daylight saving shifts, and a fleet-wide script keyed to local time behaves differently on every host. An operator picks local time only when local time is the thing they actually care about. And the only reason to care about an individual server's wall clock is that it approximates the working day of the person who might be sitting in front of it.

Once the miner is in the frame, the logic is obvious. XMRig pins the CPU. A server that feels slow gets Task Manager opened. And a Task Manager left open for an hour overnight does not mean someone is curious — it means someone is investigating. So the script closes it, and it closes it harder during the hours when nobody should be there.

What makes this huntable is that neither half is ordinary on its own but the join has essentially no benign case. `Get-Date` is in every script ever written. `Stop-Process` is in most administrative ones. A script that queries the clock, terminates an interactive diagnostic tool, and branches its behaviour on the hour is not maintenance automation. It is a script written to avoid being watched.

The rest of the intrusion supplies cheap corroboration. Huntress published Sigma rules for it, and two generalise well past this campaign: any process spawned by the AhsayCBS service — because the web app runs inside the service, so webshell commands appear as its direct children — and any Edge-named binary carrying `--daemonized` or the `msedge_exe` original filename, which is how a renamed NSSM and XMRig both presented. `WinRing0x64.sys` on a backup server is its own red flag, legitimate signed driver or not.

## Why

- **Choosing local time over UTC reveals the target of the evasion.** UTC is correct for scheduling; local time is correct for modelling an administrator's day. The choice is a direct statement that the script is reacting to human attention rather than to a clock.
- **The conjunction is the detection, and each half alone is worthless.** Time queries are ubiquitous and process termination is routine. Requiring a time query, a kill primitive and a diagnostic-tool name in the same script block collapses an enormous baseline to a readable list.
- **It inverts the usual relationship between miner and detection.** Cryptominers are normally found by CPU load or pool traffic, both of which operators tune to stay quiet. The anti-observation script is a second, independent artefact that exists precisely *because* the miner is noisy.
- **Hour-of-day branching is a structural property, not a signature.** The specific hours — 18:00, overnight, the one-hour threshold — will change in the next build. A script whose logic differs by hour will not.
- **The effect is detectable even if the script is never recovered.** Repeated short-lived `taskmgr.exe` sessions terminated by something other than the user is a standalone query, and Event ID 5 supplies the cause that mere absence does not.
- **Sanctioned Task Manager blocking looks nothing like this.** Group Policy's "Remove Task Manager" prevents launch and generates no termination events. Kiosk and proctoring software blocks outright rather than waiting an hour. A reactive kill from a loose script in `%TEMP%` is a different shape entirely.
- **The misspelling is a lesson about name-based hunting.** `Taskgmr.ps1` would be missed by an exact search for `Taskmgr`. Hunt the behaviour; use the name only for retrospective scoping.
- **A confirmed miner is not the end of the intrusion.** Huntress advises full re-imaging because secondary backdoors were hidden for extended persistence, and the RCE ran as SYSTEM. Treat the miner as an indicator of access, not as the scope.
