# H395

Every part of this chain is boring on its own. That is the design.

A user double-clicks a shortcut. The shortcut launches PowerShell. PowerShell fetches a script from GitHub and runs it, and the script is a reverse shell. Later samples also dropped PickleShell into the Startup folder so the access survived a reboot.

Shortcuts are ordinary. PowerShell is ordinary. GitHub is so ordinary that in most development organisations it is unblockable and frequently uninspected. Talos's Chain C works because none of its components look like anything, and the only thing that does look like something is the order they appear in.

So hunt the order.

A `.lnk` file never shows up as a process. Windows resolves the shortcut and launches its target, which means the shortcut leaves no process-creation record at all. The only evidence it existed is the lineage it produces: `powershell.exe` as a direct child of `explorer.exe`. That alone is not suspicious — people launch PowerShell from the Start menu constantly. But interactive PowerShell launches with no arguments, or with a profile switch. It does not launch with a URL in its command line.

PowerShell as a child of explorer, carrying a download cradle, is the triple. It is narrow enough to read by hand in most environments.

The instinct to block GitHub is the wrong one, and chasing the destination is the wrong filter. Scope by the *fetching process* instead. A browser, `git.exe`, a package manager or an IDE reaching raw content hosts is expected traffic and always will be. A script interpreter doing it, in a session that began with a double-click, is not — and that formulation keeps working when the next actor hosts on GitLab, Bitbucket, Pastebin or a CDN.

Two things about telemetry that decide whether you see anything.

Expect obfuscation in the command line. `-EncodedCommand`, string concatenation, backticks, case variation — a literal match on `Invoke-WebRequest` will miss a meaningful share. Event ID 4104 is the right surface for script content because the block is logged after decoding. It is also the only correct surface: the Defender `PowerShellCommand` action type records cmdlet *names*, not script text, so searching it for a URL returns nothing no matter how the attack is written.

And Talos publishes none of the specifics here — not the shortcut's command line, not the repository URL, not the script filename, not whether the cradle was encoded. The hunt is built on lineage and cradle shape rather than published strings, which is the more durable construction anyway.

Follow every hit forward an hour on the same host. Chain C ends in a Startup-folder write; its sibling Chain B ends in a scheduled task. Both are a short join away.

## Why

- **The lineage is the only artefact the shortcut leaves.** A `.lnk` is never a process image, so `powershell.exe` parented by `explorer.exe` is the sole process-telemetry trace that a shortcut was clicked.
- **Interactive PowerShell does not carry URLs.** A human-launched session starts bare or with a profile switch, so a cradle in a command line launched from explorer is a sharp anomaly.
- **GitHub hosting defeats reputation and often defeats inspection.** The retrieval is TLS to a high-reputation domain that most organisations cannot block, so the local process identity has to do the work.
- **Filtering by process rather than destination outlives the campaign.** The same query catches the next actor on GitLab, Bitbucket, Pastebin or a CDN; a GitHub blocklist catches nobody.
- **Script-block logging is the only place content survives obfuscation.** Event ID 4104 records the decoded block, while the Defender PowerShellCommand action type holds cmdlet names and never script text.
- **The chain has a confirmable second half.** A Startup-folder write within the following hour turns a suspicious cradle into an established persistence finding.
- **It is one of four delivery chains from one actor.** Macro documents, PS2EXE downloaders with scheduled tasks, this shortcut chain and a WinRAR exploit all deliver the same three reverse shells, so a single-vector detection leaves three open.
- **Public hosting left the attacker visible too.** Talos tracked infrastructure changes and malware development through the repository's own commit history, which is the same openness defenders can use for retrospective scoping.
