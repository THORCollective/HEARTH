false_positive_notes: |
  `control.exe` runs constantly on a workstation — every Control Panel applet a user opens goes through it, and `Control_RunDLL` is the documented entry point for `.cpl` files. The discriminator is not the binary or the export, it is the *argument*. Legitimate invocations name an applet in `System32` (`inetcpl.cpl`, `desk.cpl`, `ncpa.cpl`, `appwiz.cpl`) or a vendor applet under `Program Files`. They do not name a UNC path, a WebDAV URL, a path under `%TEMP%`, `%APPDATA%` or `%LOCALAPPDATA%`, or a file with a non-`.cpl` extension. Parentage matters too - legitimate invocations descend from `explorer.exe` or from a user shell, not from a scheduled task running as the user with no interactive session. Software deployment tooling occasionally launches applets programmatically; allowlist those by full command line and by the deploying parent process. The WebDAV leg has its own noise profile - some organisations use SharePoint-mapped drives, which start the WebClient service legitimately. Where that is true, pivot to the destination rather than the service - a WebClient connection to an external host that is not the organisation's SharePoint or OneDrive tenancy is the anomaly. The scheduled-task names in this report are IOCs with a short shelf life; the structural hunt is task registration with an unexpected action, not those three strings.

# H362

Microsoft's September 2026 write-up of Star Blizzard's RedFlick delivery chain documents a long sequence — phishing archive, LNK, hidden `conhost.exe`, BAT script, `ssh.exe` abused as a downloader, MSI — but the part that persists is three scheduled tasks.

They are named "Internet Quality Test Connection", "Network Configuration Manager" and "System Health Monitor". Each sounds like something an IT department would create, and none of them matches a real Windows task. One handles registration beaconing, one prepares WebDAV, and one runs the downloader for the CosmicPulse Python backdoor.

The downloader itself runs as a Control Panel applet: `control.exe Shell32.dll,Control_RunDLL` pointed at a `.cpl` DLL on a WebDAV path. That combination is doing a lot of work for the operator. The executing process is a signed Microsoft binary that runs on every workstation all day. The payload is a DLL, so it is not a process creation anyone will notice. And because it is fetched over WebDAV, it never lands as a local executable — it arrives as remote file access performed by the WebClient service inside `svchost.exe`.

The task names will change in the next campaign. What does not change is that `Control_RunDLL` has no legitimate reason to point at a remote path.

## Why

- **The argument is the anomaly, not the binary.** `control.exe` is ubiquitous and `Control_RunDLL` is its documented entry point, so signature-style detection fails. Legitimate applets live in `System32` or `Program Files`; a UNC or HTTP argument has no benign form.
- **WebDAV keeps the payload off disk as an executable.** No dropped EXE, no write to a monitored directory, and the fetch is performed by `svchost.exe` rather than by anything attacker-named — which defeats both file-based detection and process-reputation checks.
- **The scheduled task is the durable part of the chain.** Everything before it is one-shot delivery. The task is what survives reboot, and it is the artefact a responder can find weeks later.
- **Invented maintenance-sounding task names are a reusable pattern.** The specific three are IOCs, but "task name implies a system function, task action is a LOLBin" generalises, and the fleet-wide distribution of task names makes the invented ones cheap to spot.
- **Microsoft published working queries.** The KQL above can be run as-is today for the known names, which makes this hunt immediately actionable while the structural query is tuned.
- **It composes with coverage HEARTH already has.** The `ssh.exe PermitLocalCommand` delivery step is [[H257]]; the WebDAV baseline is [[B049]]; the key-storage step is [[H363]]. Running them together covers the chain end to end rather than catching one stage of it.
- **The target set is specific and high-value.** Star Blizzard's targeting of civil society, academia, journalism and government means these hosts often sit outside corporate EDR coverage, so a query that works from scheduled-task and process telemetry alone is worth having.
