false_positive_notes: |
  Two conditions that are individually common produce most of the noise. A mismatch between file name and `OriginalFileName` happens legitimately with installers and self-extractors (`setup.exe` whose original name is the product installer), with vendors who rename binaries between versions, and with software distribution tools that stage files under temporary names. Executables in another product's folder happen legitimately with plugins, shell extensions and bundled runtimes. Their conjunction is the signal: a binary whose version-info names vendor A, running from vendor B's install directory, under a name belonging to neither. For the 7-Zip case specifically, the benign file set is small and stable (`7z.exe`, `7zFM.exe`, `7zG.exe`, `7z.dll`, `7-zip.dll`, `7-zip32.dll`, `Uninstall.exe`, plus language and help files), so any other executable in that folder is worth a look regardless of what it claims to be. If Vicarius vRx is sanctioned in your environment, the question becomes whether this instance is enrolled in your tenant — check its install path and configuration against the sanctioned deployment rather than dismissing it on the vendor name.

# H350

Midway through the INC Ransom intrusion Huntress reconstructed, the affiliate who took over from the initial access broker set up two remote channels. One was AnyDesk, which most environments would catch. The other was a Vicarius vRx component, a commercial vulnerability-remediation tool, renamed to `HealthUpdater.exe` and placed in `C:\Program Files\7-Zip\`.

Each choice defeats a different control. vRx is a legitimate product whose job is running scripts and pushing changes to endpoints, so it gives the operator remote execution without looking like a remote-support tool. RMM allowlists and inventories are usually built around products like AnyDesk, ScreenConnect and MeshAgent, and a patching agent rarely appears on either the approved or the blocked list. Renaming it removes the vendor from the process list. Putting it in the 7-Zip folder places it in an admin-only, trusted path that most rules ignore, inside a product nobody expects to phone home.

What the operator did not change is the PE version resource. The binary still says who made it and what it was originally called, and neither matches a file named `HealthUpdater.exe` in 7-Zip's folder. Sysmon and Defender both record those fields on every process creation, so the mismatch is already in most organisations' logs.

## Why

- It targets the quieter of two redundant access channels. Affiliates who deploy one noisy RMM often keep a second, less recognisable one, and this hunt looks for that second channel, which survives after the obvious tool is removed.
- The version-info mismatch is cheap and hard to fake. Changing a file name is trivial, while editing a signed binary's version resource breaks its signature, so a signed binary whose `OriginalFileName` and `CompanyName` disagree with its name and location is a strong, low-cost signal.
- Some product folders have a tiny, stable set of files. 7-Zip ships a handful of executables and DLLs, so "any other executable in this folder" is close to a zero-noise rule, and the same idea extends to other simple utilities in `Program Files`.
- It widens RMM hunting beyond remote-support brands. Treating patching, remediation and software-deployment agents as remote access tools closes a blind spot in inventories that only list the familiar remote-support products.
- It fires in the affiliate phase, before encryption. The renamed agent was installed alongside network scanning and ahead of the BYOVD and `atexec` deployment, so a hit here comes before the ransomware push.
