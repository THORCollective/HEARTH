# H391

Before it did anything else, the loader asked six different services where it was.

`myip.opendns.com` and `o-o.myaddr.l.google.com` over DNS. `checkip.amazonaws.com`, `api.ipify.org`, `ifconfig.me/ip` and `icanhazip.com` over HTTP. And then, in some execution branches, if the country code came back `"CN"`, it declined to run its primary payload path.

That check is more useful to a defender than the payload it protects, and the reason is in the rest of the report. UNC7017's staging infrastructure moved constantly across this campaign — Alibaba Cloud object storage in April and May, then dedicated vendor-themed domains like `promotion.storage-data.com` in early July, then a split on 20 July where the first download came from a Google Cloud Storage bucket specifically so it would sail past proxy filters that block newly registered domains. Mandiant's own conclusion is that the "evolving staging setup makes it particularly challenging for defenders to establish effective infrastructure-based blocking or network controls."

The guardrail did not move. It is a property of the loader, not of the infrastructure.

There are two ways to hunt it, and they are worth keeping separate because they fail differently.

The cheap one is the User-Agent. CROSSROAD made its lookups as `Anyviewer-loader/1.0` and `Anyviewer-ipcheck/1.0` — naming the product it had arrived alongside. No legitimate software sends those strings. A proxy-log search costs nothing, needs no baseline, and is high confidence. It is also trivially defeated the moment the actor edits a string literal, so it is a sweep rather than a detection.

The durable one is the conjunction, and this is where most hunts of this kind go wrong. Alerting on `api.ipify.org` is a well-known way to drown. Asking the internet for your own IP is thoroughly normal: VPN clients do it, remote-support tools do it, licensing checks do it, installers and CI scripts do it constantly. But legitimate software asks *one* service, because one answer is all it needs. A loader hedging against an unreliable or blocked answer asks four, five, six in a row. A single process hitting three or more distinct reflection services inside a minute is a different shape entirely, and that shape survives the actor changing their User-Agent, their domains and their payload.

Which means the right first step is knowing who does this legitimately in your estate — which is exactly what [[B045]] produces. Read it alongside this.

Two notes for anyone triaging a hit.

The abort is narrower than it sounds. Mandiant says the country-code check aborts "its primary payload execution path" in "specific execution branches" — not that the process exits. So a host in an aborted branch may show the reflection lookups and some cleanup, and never receive the Stage-3 backdoor. Absence of a payload does not mean absence of contact.

And CROSSROAD has a second self-check that produces similar partial evidence: it looks for the substring `AOMEI` in its own file path, and if it is missing it deletes itself — but keeps running its downloader routines anyway. A binary that unlinks itself and then carries on making network requests is a corroborating observation, not a contradiction.

## Why

- **The guardrail stayed constant while the infrastructure rotated.** Staging moved from Alibaba Cloud to dedicated domains to a Google Cloud Storage bucket across three months; the geolocation check did not, which makes it the more durable thing to key on.
- **The conjunction is what separates this from ordinary software behaviour.** Legitimate tools query one reflection service; a loader hedging its answer queries several in seconds. Counting distinct services per process per minute is the discriminating measurement.
- **The two User-Agent strings are free precision.** `Anyviewer-loader/1.0` and `Anyviewer-ipcheck/1.0` appear in no real product, need no baseline, and cost one proxy query — while being fragile enough that they must not be the only detection.
- **A country-code abort is the actor publishing their targeting policy.** It tells a defender which populations were deliberately excluded, which is intelligence that outlasts this particular campaign.
- **The initial download was chosen to beat NRD filtering.** Moving the first-stage fetch to a Google Cloud Storage bucket defeats newly-registered-domain blocking, so perimeter domain reputation is not a control that would have caught this.
- **Nothing about the delivery looked abnormal on the endpoint.** The payload arrived through a signed vendor's own update flow, during a window of minutes, with a correctly matching MD5 in the configuration — so the loader's own behaviour is the first observable anomaly.
- **Partial execution is expected, and knowing that prevents a wrong triage conclusion.** The abort affects specific branches and the self-delete does not stop the downloader, so hosts can show contact without a payload and self-deletion without termination.
- **A fabricated 2024 compile timestamp means file dates cannot be trusted here.** The dropper was timestomped to complicate timeline analysis, so build date is not evidence of when a binary arrived.
- **It closes a technique with no HEARTH coverage at all.** T1614 System Location Discovery returns zero files across Flames, Embers and Alchemy, and [[B045]] covers the adjacent connectivity-discovery baseline rather than location-based execution control.
