false_positive_notes: |
  Suspended-process creation is a legitimate and common pattern: software installers and updaters, debuggers and profilers, Windows Error Reporting, application-virtualisation and DLP agents, browser and Electron sandbox brokers, and EDR agents themselves all create suspended children and write into other processes. The single APC or single memory-write event is therefore near-worthless alone. Control this three ways. First, require the conjunction within a short window (roughly five minutes) on the same source/target pair — suspended creation AND cross-process write AND APC queue — because the legitimate users of one primitive rarely use all three against a freshly suspended child. Second, allowlist by signed publisher and expected install path rather than by image name, since the interesting cases are precisely unsigned binaries or signed-but-relocated ones in %TEMP%, %APPDATA%, %PROGRAMDATA% and C:\Windows\Temp. Third, treat the target's identity as signal: a Go or .NET binary from a user-writable path injecting into svchost.exe, werfault.exe, notepad.exe, dllhost.exe or RuntimeBroker.exe is materially more suspicious than an installer writing into its own child. Expect legitimate volume from your own EDR and from any application-control or virtualisation product, and exclude those by publisher up front or the hunt will not be workable.
notes: |
  Sysmon process creation (Event ID 1) - Core filter: children created by a parent whose Image sits in a user-writable path (%TEMP%, %APPDATA%, %PROGRAMDATA%, C:\Windows\Temp, C:\Users\*\Downloads) or whose signature is absent/invalid, where the child is a signed Microsoft binary that the parent has no product reason to launch. Triage fields: ParentImage, ParentCommandLine, Image, CommandLine, IntegrityLevel, Hashes. Sysmon does not record the CREATE_SUSPENDED flag, so recover the suspension indirectly: the child shows an unusually long gap between process create and its first image load or first network/file event, and in Event ID 7 it loads only ntdll.dll (and often kernel32/kernelbase) before the injection events land.
  Sysmon ProcessAccess (Event ID 10) - Core filter: SourceImage equals the suspicious parent, TargetImage equals the just-created child, and GrantedAccess includes the write/operate bits — PROCESS_VM_WRITE (0x0020) and PROCESS_VM_OPERATION (0x0008), commonly seen as 0x1FFFFF (full access), 0x1F3FFF, 0x143A or 0x0028. Strong red flag: a CallTrace containing UNKNOWN frames (unbacked memory) or resolving into ntdll.dll!NtQueueApcThread / kernel32.dll!QueueUserAPC rather than a documented product code path.
  The deliberate telemetry gap - Sysmon Event ID 8 (CreateRemoteThread) does NOT fire for APC-based injection, because execution is delivered by queuing an APC to a thread that already exists rather than by creating one. A hunt written against Event ID 8 will return nothing here; that absence is the reason the technique was selected, and pivoting to Event ID 10 plus API-level telemetry is the workaround.
  Microsoft Defender XDR advanced hunting - DeviceEvents exposes the APC call directly. Require both legs of the injection in one window:
  DeviceEvents
  | where Timestamp > ago(30d)
  | where ActionType in ("QueueUserApcRemoteApiCall", "WriteToProcessMemoryApiCall")
  | summarize Legs = make_set(ActionType), Hits = count(), TargetProcs = make_set(FileName, 8)
      by DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, bin(Timestamp, 5m)
  | where array_length(Legs) == 2
  | where InitiatingProcessFolderPath has_any (@"\Temp\", @"\AppData\", @"\ProgramData\", @"\Downloads\")
  Join to DeviceProcessEvents on DeviceId and InitiatingProcessSHA256 to recover the parent lineage and whether the initiating binary is signed.
  ETW where available - Microsoft-Windows-Threat-Intelligence provides kernel notifications for remote allocate, remote write and APC queue (the same source EDRs consume via ELAM); Microsoft-Windows-Kernel-Process gives thread start with the start address, useful for confirming execution began in unbacked memory. Neither is collected by default, so treat them as confirmation for a shortlist, not as the primary hunt.
  CLOSEDQUORUM specifics from the source report - The implant is a Go binary whose symbol table retains main.earlyBirdInject, with process hollowing (T1055.012) as the fallback path when APC injection fails; the same sample writes C:\Windows\Temp\wmi.ps1 for a WMI event subscription firing every 60 seconds, sets a Run key value named WindowsUpdate, and dumps LSASS via MiniDumpWriteDump. Retained Go function names such as main.ModelOrchestrator, main.lsassDump and main.earlyBirdInject are practical string pivots for a retro-hunt over collected binaries, and the surrounding persistence artefacts give corroborating events to join against once a candidate host is identified.

# H335

Cisco Talos documented CLOSEDQUORUM on 22 September 2026, and while the headline was its use of multiple large language model APIs for command and control, the implant's local tradecraft is the part that is broadly reusable by other families. Its default execution primitive is Early Bird APC injection: create a process suspended, write dynamically generated shellcode into it, queue that shellcode onto the suspended primary thread with NtQueueApcThread, and resume. The technique dates to 2018 and remains attractive for one concrete reason — it delivers execution without creating a remote thread, so the Sysmon Event ID 8 signal that underpins a large share of deployed injection detections simply never appears, and the payload runs before the target process's entry point and therefore ahead of user-mode hooking by security products. What the technique cannot avoid is the surrounding shape: something has to create the suspended process, something has to write into its address space, and something has to queue the APC. Those three facts are recorded in ordinary Sysmon and Defender telemetry, and their conjunction against a single freshly created child is rare enough in a tuned environment to hunt on.

## Why

- APC injection is chosen precisely to defeat the most widely deployed injection detection, so an environment can be well instrumented for Event ID 8 CreateRemoteThread and still be blind here; the gap is structural rather than a collection oversight, which makes it a hunt rather than an alert already firing.
- Executing before the target's entry point means the payload is resident before security-product hooks and in-process instrumentation initialise, so in-process detection is unreliable by construction and the durable evidence is the cross-process API sequence observed from outside the victim process.
- Every leg of that sequence is available in first-party telemetry that mature shops already collect: Sysmon Event ID 1 for the suspended child and its parent's path and signature, Event ID 10 with GrantedAccess and CallTrace for the memory write, and Defender's QueueUserApcRemoteApiCall action type for the APC itself — no bespoke sensor is required.
- The technique is family-agnostic and long-lived, so a hunt written against the primitive keeps paying out after CLOSEDQUORUM's hashes, LLM endpoints and Discord webhooks have all rotated, while the retained Go symbol names give an immediate retro-hunt pivot for this specific campaign.
