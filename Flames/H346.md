false_positive_notes: |
  `.pif` is the rare case where the base rate genuinely is near zero. The extension dates to MS-DOS program-information files consumed by Windows 3.x and NTVDM; 64-bit Windows has no NTVDM at all, and a legitimate `.pif` on a modern endpoint is almost always either a decades-old shortcut file carried forward by profile migration — which is inert and never executes — or an artifact inside a very old line-of-business application's install directory. So process execution of a `.pif` image is the signal, and file presence alone is not. Two real sources of noise to resolve before treating a hit as an incident: legacy industrial, laboratory or manufacturing software occasionally ships `.pif` files that a launcher genuinely invokes, so inventory those applications and allowlist by full path and hash rather than by extension; and roaming or redirected profiles will surface historical `.pif` files in `FileCreate` telemetry during migration without any execution. Because the expected volume is so low, the correct posture is to enumerate every `.pif` execution in the environment over 30 days and explain each one individually — if that list is longer than a handful of known-legacy paths, the extension is worth blocking outright at the gateway and via software restriction policy, which is a better outcome than tuning. Do not narrow the hunt to `image.pif` or to the specific hashes in the source report; the extension and the delivery mismatch are the durable properties, the filename is not.
notes: |
  Platform: Windows. Driven by Huntress, "DarkMe RAT: A VB6 APT Trojan Turned Conventional Infostealer" (September 22, 2026). Observed delivery: a phishing email containing a hyperlink presented as an image, `https://readonline365[.]com/view/image.png`; the server returned `image.pif`, a 1 MB PE32+ executable that Windows' Properties sheet labels a "Shortcut to MS-DOS program" (the standard description for any `.pif`) and whose forged version information implies a component of a security product called "Aegis Sentinel". Huntress also saw `.png` and `.pdf` URLs answer with a 301 straight to the `.pif`, and two hosts serve the PE as `text/plain`. The dropper then staged an `msiexec` fetch of `propi.msi` from `onlineview365[.]com` and a three-stage VB6 loader chain.
  Why .pif still works - Windows resolves `.pif` through the `piffile` class and will execute a PE image carrying that extension, a behaviour retained for backward compatibility long after the DOS subsystem it existed for was removed. This produces three simultaneous advantages: although mail clients such as Outlook block `.pif` attachments, the extension is often missing from custom web-gateway and EDR extension lists built around `.exe`, `.scr`, `.com`, `.bat`, `.js`, `.vbs`, `.hta` and `.lnk`, and a link-delivered download sidesteps attachment blocking entirely; Explorer describes it as a "Shortcut to MS-DOS program" rather than an application; and the extension is obscure enough that a user who does see it has no intuition about it. That "shortcut" description, plus forged version metadata naming a security product, reinforces the impression that the file is a pointer rather than a program.
  The delivery mismatch is the second, independent anchor - The requested URL ended `.png` and the delivered file was a PE with a `.pif` extension. That mismatch is observable at the gateway without touching the endpoint, and it generalises far past this family: a response whose `Content-Type` is `application/octet-stream`, `application/x-msdownload` or even `text/plain` (two DarkMe hosts served the PE as `text/plain`), a 301 from an image or document path to an executable extension, or a body beginning with the `MZ` magic, served against a request for an image, document or media path, is a high-fidelity signal regardless of which extension is finally written to disk. Hunt it as a standing query — it catches the next campaign that substitutes `.com`, `.scr` or `.cpl` for `.pif`.
  Sysmon Event ID 1 / 4688 / DeviceProcessEvents — execution (primary) - Core filter: process creation where the image path ends in `.pif`. Triage fields: `FolderPath`, `ProcessCommandLine`, `AccountName`, `InitiatingProcessFileName`, `InitiatingProcessCommandLine`, `SHA256`. Strong red flags: the image sits in `%USERPROFILE%\Downloads`, `%TEMP%`, `%LOCALAPPDATA%\Temp` or an archive-extraction directory; the parent is a browser (`chrome.exe`, `msedge.exe`, `firefox.exe`), an archive utility (`7zFM.exe`, `WinRAR.exe`, `explorer.exe` extracting a ZIP), or a mail client; and the child processes that follow — DarkMe's dropper proceeded to `msiexec /i https://... /quiet /norestart`, `EXPAND.EXE -R files.cab`, `wscript.exe` running a `.wsf`, and `reg.exe import`, any of which immediately downstream of a `.pif` is conclusive.
  Splunk sketch (derived from the report's hunting guidance; Huntress did not publish detection rules) - `index=main sourcetype=WinEventLog:Sysmon EventCode=1 Image="*.pif" | stats count by ComputerName, User, CommandLine`
  Sample KQL — .pif execution with lineage:
  `DeviceProcessEvents | where Timestamp > ago(30d) | where FolderPath endswith ".pif" | project Timestamp, DeviceName, AccountName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessParentFileName, SHA256 | order by Timestamp desc`
  Sysmon Event ID 11 / 15 / DeviceFileEvents — arrival - Core filter: `FileCreate` for `*.pif` where the creating process is a browser, mail client or archive tool. Pair with Event ID 15 (`FileCreateStreamHash`) to confirm a `Zone.Identifier` alternate data stream, which establishes the file came from the internet and records the referring host — valuable because the source URL often does not survive elsewhere. Strong red flag: a `.pif` created with a `Zone.Identifier` and executed within minutes, which is the complete user-click-to-execution sequence on one host.
  Sample KQL — .pif arrival with its download origin (compare the origin URL's extension to the file's):
  `DeviceFileEvents | where Timestamp > ago(30d) | where FileName endswith ".pif" | project Timestamp, DeviceName, FileName, FolderPath, InitiatingProcessFileName, FileOriginUrl, FileOriginReferrerUrl, SHA256 | order by Timestamp desc`
  Proxy and gateway leg - Core filter: responses carrying a PE magic (`MZ`) or an executable `Content-Type` where the request path ends in an image, document or media extension; and `Content-Disposition` filenames whose extension differs from the requested path's. Strong red flags: the host is newly registered; the same host serves both an innocuous-looking path and a PE; and a subsequent `msiexec` request for an `.msi` in the domain root from the same client, since a legitimate installer is essentially never hosted at a domain root. Retro-hunt `readonline365[.]com` and `onlineview365[.]com` from the source report, but treat the pattern as the finding rather than those two names.
  Hardening that makes the hunt permanent - Once the 30-day enumeration confirms the legitimate `.pif` population is empty or a short known list, block the extension at the mail and web gateway, remove or restrict the `piffile` shell association, and add `.pif` to Software Restriction Policies' designated file types (App Control for Business/WDAC does not filter by extension; use it instead to restrict unsigned executables in user-writable paths). This is one of the few cases where the hunt's likely conclusion is a cheap, low-risk configuration change rather than an ongoing detection, and the hunt should be re-run afterwards to confirm the control holds.
  Cross-technique: [[H344]] covers the `rundll32 /sta {CLSID}` execution and [[H345]] the custom URL-protocol persistence that follow this dropper in the same chain. Compare [[H244]] for double-extension and RTLO filename spoofing, which is the adjacent but distinct case of disguising the name rather than exploiting a still-executable legacy extension.

# H346

In the DarkMe campaign Huntress analysed in September 2026, the initial access is a single, almost trivially simple trick. A phishing email contains a hyperlink presented as an image and pointing at `https://readonline365[.]com/view/image.png`. The server ignores the implied file type and returns `image.pif` — a 1 MB PE32+ executable — which Windows describes as a "Shortcut to MS-DOS program" and whose forged version information implies a component of a security product called "Aegis Sentinel".

`.pif` files were program-information files for DOS applications, consumed by a subsystem that 64-bit Windows no longer contains. The extension nonetheless remains registered as an executable type through the `piffile` class, and Windows will happily run a PE image that carries it. That combination of "still executes" and "nobody thinks about it any more" is the entire technique. Outlook blocks `.pif` attachments, but a link-delivered download sidesteps that, and many custom gateway and EDR lists are built around `.exe`, `.scr`, `.com`, `.bat`, `.js`, `.vbs`, `.hta` and `.lnk`; Explorer labels a `.pif` a "Shortcut to MS-DOS program" rather than an application; and a user who notices the extension has no intuition about what it means, especially when the file claims to be a shortcut.

There are two independent places to catch this, which is what makes it a good hunt rather than a good indicator. At the endpoint, a `.pif` appearing as a process image is very nearly a zero-base-rate event on modern Windows — rare enough that the right response to a nonempty result is usually to block the extension outright rather than to tune a rule. At the gateway, the mismatch between a request for `.png` and a response body starting with `MZ` is visible without any endpoint telemetry at all, and that check survives the adversary swapping `.pif` for the next overlooked legacy extension.

## Why

- The base rate is close to zero, which is rare and valuable. On 64-bit Windows there is no DOS subsystem for a `.pif` to serve, so process execution of one is anomalous almost by definition — the hunt can be run exhaustively over 30 days and every hit explained individually, rather than thresholded.
- The likely outcome is a permanent control rather than a permanent alert. If the legitimate `.pif` population is empty or a short list of legacy application paths, the extension can be blocked at the gateway and restricted via SRP designated file types, which retires the risk instead of monitoring it — an unusually cheap win for a detection engineering effort.
- The technique exploits a gap in allow/block-list design rather than a vulnerability, so it will recur. Any extension that Windows still treats as executable but that block lists omit is a candidate, which is exactly why the gateway-side content/extension mismatch check matters more than the `.pif` string: it generalises to the successor.
- The mismatch is detectable before anything reaches the endpoint. A response bearing PE magic or an executable content type against a request for an image or document path is a high-fidelity signal available in ordinary proxy logs, giving a detection point that does not depend on EDR coverage of the target host.
- A hit yields an unusually complete chain. DarkMe's dropper proceeded directly to a remote `msiexec` fetch, CAB expansion, a `.wsf` script and `reg.exe import`, so a single `.pif` execution event anchors a lineage that identifies the staging infrastructure, the persistence design and the affected user in one triage pass.
