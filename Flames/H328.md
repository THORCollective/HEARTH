false_positive_notes: |
  Every single component of this hunt is legitimate, which is the whole problem and the reason the hunt is built on co-occurrence rather than on any one artefact. `docs.google.com` is universally allowlisted, is almost never blocked, and is reached by essentially every user in an organisation that uses Google Workspace or that merely receives shared documents from partners — so the domain itself carries zero signal and must never be the filter. The Google Visualization API is a real, documented, supported product surface with genuine business uses: internal dashboards, Looker Studio and Data Studio connectors, BI tools and home-grown reporting pages all pull spreadsheet data through `/gviz/tq?`, and in an organisation that has built such a dashboard the path will appear at steady volume from a small, stable, enumerable set of referring pages and users. Enumerate those once and they become a permanent allowlist entry; what remains is `/gviz/tq?` requests that arrive with no accompanying Google Docs or Drive session activity from the same browser in the same window of time, and that population is genuinely small. Tampermonkey, Violentmonkey and their relatives are likewise real, popular, and installed for entirely honest reasons — developers, QA engineers, web-scraping analysts and power users install them deliberately, and in some organisations they are even sanctioned. The discriminator is therefore not the presence of a userscript manager but the reconciliation: which hosts have one, whether the installing user has any plausible reason to, and above all WHAT USERSCRIPTS IT CONTAINS, because the userscript body is stored locally and can be read. An empty result is ambiguous in two distinct and important ways. First, if your proxy logs only SNI or hostname for TLS traffic you cannot see `/gviz/tq?` at all, so an empty result means nothing whatsoever until you have confirmed full-URI logging on a test request. Second, extension inventory only covers ENROLLED devices in a MANAGED browser — unmanaged Chrome profiles, personal profiles signed into a corporate machine, and BYOD hosts are invisible to it, and this campaign targets individuals holding cryptocurrency rather than enterprises, so the most likely victim population in a corporate estate is precisely the one least likely to be under browser management. Resolve the coverage question before drawing any conclusion from a clean result.

  READ THIS FIRST - there is no process telemetry. Any hunt framed on process lineage, command-line arguments or `RunMRU` will return nothing and that nothing will be meaningless. The hunt surface is (1) browser extension inventory, (2) proxy/DNS telemetry with full URI, and (3) Chrome managed-policy reporting. Nothing else.

This hunt shares only the social-engineering veneer. Running the [[H313]] queries against this campaign produces a clean result that a hunter will wrongly read as a true negative. Treat the two as separate detection problems that happen to share a marketing name.
  Core filter, the Google Sheets C2 - proxy or TLS-inspection records where `host` is `docs.google.com` and the URI path contains `/gviz/tq?`. The payload text was hidden in the sheet by FORMATTING IT WHITE-ON-WHITE, so a human opening the spreadsheet sees an empty cell. This is a legitimate Google API - the signal is not the API but its rarity in ordinary corporate browsing and its isolation from other Google Docs activity.

A `/gviz/tq?` call standing alone, with no surrounding Docs session, is the anomaly. If full-URI proxy logging is unavailable, this axis of the hunt is not runnable and you should say so rather than substituting DNS.
  Core filter, extension inventory - enumerate userscript managers across the managed estate. Defender XDR advanced hunting - `DeviceTvmBrowserExtensions` (per-device installation facts) joined to `DeviceTvmBrowserExtensionsKB` (extension metadata and requested permissions), filtered on extension name for Tampermonkey, Violentmonkey and Greasemonkey-family managers. Tampermonkey is the one named in this campaign and is installed from the official Chrome Web Store, so it is signed, reputable and will not be flagged by anything - the Chrome Web Store item ID commonly associated with it is `dhdgffkkebhmkfjojejmpbldmpobfkfo`, which you should confirm against your own inventory rather than trust from a report. Note that these TVM tables are not ingested into Sentinel - run the query in Defender XDR.
  The durable artefact - the userscript itself. Unlike the `javascript:` paste, which leaves nothing, a userscript installed under a manager is WRITTEN TO DISK and survives reboot, which is exactly why the second lure switched to it - the script re-runs every time the victim visits the target site. # H328

Cisco Talos documented a ClickFix campaign that deliberately never leaves the browser. The lure — posted on Telegram, in DarkForums private messages and in Pastebin comments — points at a Google Docs file called "API Logic Flaw" describing a supposed arbitrage bug in a cryptocurrency swap service. The victim is told either to copy a script from `paste[.]sh` and paste it into Chrome's navigation bar prefixed with `javascript:`, executing it against the current page, or — in the later and more durable variant — to install the entirely legitimate Tampermonkey extension from the Chrome Web Store "to activate the bonus". Either way the code runs as page JavaScript inside `chrome.exe`. It then reaches back to a Google Sheet through the Visualization API, reading two cells whose contents are obfuscated JavaScript hidden by being formatted white-on-white, overrides the page's `fetch` API, installs a `MutationObserver` over the exchange's DOM, and replaces the Bitcoin deposit address at the moment the victim copies it. Talos tracked roughly 0.159 BTC stolen across 24 funded addresses before the proceeds were fanned out through thousands more.

The important consequence for a hunter is structural rather than tactical. This campaign produces no process execution, no dropped binary, no service, no scheduled task and no registry persistence. HEARTH's existing ClickFix hunts, [[H313]] and [[B049]], are built entirely on the Run-dialog-to-`rundll32` process chain and on `RunMRU`; pointed at this campaign they return a clean, confident, wrong answer.

## Why

- **The absence of process telemetry is the finding, not an obstacle.** Every control an organisation has positioned around process creation, command-line auditing, script-block logging and binary reputation is structurally blind here, because nothing is ever created, written or executed outside the browser's own JavaScript engine. Recognising that up front changes what a hunter collects before they write the first query, and prevents an empty `DeviceProcessEvents` result from being read as a negative.
- **`/gviz/tq?` is a legitimate API that is genuinely rare, and rarity is the whole detection.** The Google Visualization API is documented, supported and used by real dashboards, so it cannot be blocked and should not be alerted on blindly. But in ordinary corporate browsing it is close to absent, and the small population of legitimate users is stable and enumerable in one pass. Once enumerated, a `/gviz/tq?` call arriving with no surrounding Google Docs session is a short, hand-triageable list.
- **The extension angle is the part that survives infrastructure rotation.** Spreadsheet IDs, paste links, target exchanges and lure text all change between versions — Talos already documented two. A userscript manager sitting on a managed endpoint against policy does not change, is directly enumerable from inventory you may already have, and carries the payload on disk in readable form. That makes it both the durable detection and the fastest route to proof.
- **Abusing a trusted extension is cheaper for the attacker than writing a malicious one.** Tampermonkey is real, popular, signed and installed from the official store, so it passes every reputation and store-review check by construction. The malicious part is the userscript, which is user-supplied content that no store ever reviews. Any organisation whose extension posture consists of "block extensions with a bad reputation" has no coverage here at all.
- **The victim population in a corporate estate is the one least likely to be managed.** This campaign targets individuals holding cryptocurrency, reached through Telegram and forums, on whatever browser profile they happen to use. That is disproportionately a personal profile on a corporate machine, or a BYOD host — precisely the population that browser-management reporting does not cover. Establish coverage honestly before interpreting a clean inventory.
